1 概要# TOC

ffmpeg [global_options] {[input_file_options] -i input_url} ... {[output_file_options] output_url} ...

2 描述# TOC

ffmpeg 是一款通用的媒体转换器。它可以读取种类繁多的 输入——包括实时采集/录制设备——对它们进行滤镜处理和转码， 转换成各式各样的输出格式。

ffmpeg 从任意数量的输入读取数据（这些输入可以是普通 文件、管道、网络流、采集设备等），输入由 -i 选项指定；它写入任意数量的输出，输出由 一个普通的输出 url 指定。命令行上任何无法 被解释为选项的内容都被视为一个输出 url。

原则上，每个输入或输出都可以包含任意数量的不同类型的 基本流（视频/音频/字幕/附件/数据），不过允许的 流数量和/或类型可能受容器格式限制。选择 哪些输入中的哪些流会进入哪个输出，可以自动 完成，也可以用 -map 选项来完成（参见 流选择 章节）。

在选项中引用输入/输出时，必须使用它们的索引（从 0 开始）。 例如，第一个输入是 0，第二个是 1，依此类推。同样， 某个输入/输出内部的流也用它们的索引来引用。例如 2:3 指的是第三个输入或输出中的第四条流。另请参见 流说明符章节。

作为一般规则，选项会作用于其后指定的 文件。因此顺序很重要，而且同一个选项可以在命令行上 多次出现。每次出现都会 作用于其后的输入或输出文件。 这条规则的例外是全局选项（例如详细程度级别）， 它们应当最先指定。

不要混用输入文件和输出文件 – 先指定所有输入文件，再指定所有 输出文件。也不要混用属于不同文件的选项。所有 选项都只作用于其后的输入或输出文件，并在文件之间被重置。

下面是一些简单的例子。

  • 通过重新编码媒体流，把输入媒体文件转换为另一种格式： 
    ffmpeg -i input.avi output.mp4
  • 把输出文件的视频码率设为 64 kbit/s： 
    ffmpeg -i input.avi -b:v 64k -bufsize 64k output.mp4
  • 强制输出文件的帧率为 24 fps： 
    ffmpeg -i input.avi -r 24 output.mp4
  • 强制输入文件的帧率（仅对原始格式有效）为 1 fps， 并把输出文件的帧率设为 24 fps： 
    ffmpeg -r 1 -i input.m2v -r 24 output.mp4

对于原始输入文件，可能需要指定格式选项。

  • 解复用器（"demultiplexers" 的简称）读取输入源，以 提取

3.1 流拷贝# TOC

ffmpeg 中最简单的流水线是单流 流拷贝，即在不进行解码、滤镜处理或编码的情况下复制一个输入基本流的包。作为一个例子，考虑一个名为 INPUT.mkv 的输入 文件，其中有 3 条基本流，我们取出其中的 第二条并写入文件 OUTPUT.mp4。这样一条流水线的 示意图如下所示： 

┌──────────┬─────────────────────┐
│ demuxer  │                     │ unused
╞══════════╡ elementary stream 0 ├────────╳
│          │                     │
│INPUT.mkv ├─────────────────────┤          ┌──────────────────────┬───────────┐
│          │                     │ packets  │                      │   muxer   │
│          │ elementary stream 1 ├─────────►│  elementary stream 0 ╞═══════════╡
│          │                     │          │                      │OUTPUT.mp4 │
│          ├─────────────────────┤          └──────────────────────┴───────────┘
│          │                     │ unused
│          │ elementary stream 2 ├────────╳
│          │                     │
└──────────┴─────────────────────┘

上图的流水线可以用下面的命令行构建： 

ffmpeg -i INPUT.mkv -map 0:1 -c copy OUTPUT.mp4

在这个命令行中

  • 只有一个输入 INPUT.mkv；
  • 这个输入没有任何输入选项；
  • 只有一个输出 OUTPUT.mp4；
  • 这个输出有两个输出选项：
    • -map 0:1 选择要使用的输入流 —— 从索引为 0 的输入 （即第一个输入）中选择索引为 1 的流（即第二条流）；
    • -c copy 选择 copy 编码器，即不进行解码 或编码的流拷贝。

流拷贝可用于更改基本流的数量、容器格式， 或修改容器层面的元数据。由于没有解码或编码， 它非常快，而且没有质量损失。然而，由于各种 因素（例如目标容器所需的某些信息在源中不可用）， 它在某些情况下可能无法工作。应用滤镜显然 也是不可能的，因为滤镜作用于解码后的帧。

可以构建更复杂的流拷贝场景 —— 例如把两个输入文件中的 流合并到单个输出中： 

┌──────────┬────────────────────┐         ┌────────────────────┬───────────┐
│ demuxer 0│                    │ packets │                    │   muxer   │
╞══════════╡elementary stream 0 ├────────►│elementary stream 0 ╞═══════════╡
│INPUT0.mkv│                    │         │                    │OUTPUT.mp4 │
└──────────┴────────────────────┘         ├────────────────────┤           │
┌──────────┬────────────────────┐         │                    │           │
│ demuxer 1│                    │ packets │elementary stream 1 │           │
╞══════════╡elementary stream 0 ├────────►│                    │           │
│INPUT1.aac│                    │         └────────────────────┴───────────┘
└──────────┴────────────────────┘

这可以用以下命令行构建 

ffmpeg -i INPUT0.mkv -i INPUT1.aac -map 0:0 -map 1:0 -c copy OUTPUT.mp4

这里 -map 输出选项被使用了两次，在输出文件中创建了 两条流 —— 一条由第一个输入供给，一条由第二个输入供给。-c 选项的 单个实例为这两条流都选择了流拷贝。 你还可以将此选项的多个实例与 流说明符 一起使用，以便为每条流应用不同的值，这将在 后续章节中演示。

一个相反的场景是把单个输入中的多条流拆分成 多个输出： 

┌──────────┬─────────────────────┐          ┌───────────────────┬───────────┐
│ demuxer  │                     │ packets  │                   │ muxer 0   │
╞══════════╡ elementary stream 0 ├─────────►│elementary stream 0╞═══════════╡
│          │                     │          │                   │OUTPUT0.mp4│
│INPUT.mkv ├─────────────────────┤          └───────────────────┴───────────┘
│          │                     │ packets  ┌───────────────────┬───────────┐
│          │ elementary stream 1 ├─────────►│                   │ muxer 1   │
│          │                     │          │elementary stream 0╞═══════════╡
└──────────┴─────────────────────┘          │                   │OUTPUT1.mp4│
                                            └───────────────────┴───────────┘

用以下命令构建 

ffmpeg -i INPUT.mkv -map 0:0 -c copy OUTPUT0.mp4 -map 0:1 -c copy OUTPUT1.mp4

注意，即使各个输出文件的值相同，每个输出文件也都需要 一个单独的 -c 选项实例。这是因为非全局 选项（大多数选项都是非全局的）只在放置它们的文件 的上下文中生效。

当然，这些示例还可以进一步推广为把任意数量的输入 任意重新映射到任意数量的输出。

3.2 转码# TOC

转码是指先解码一条流、然后再重新编码它的 过程。由于编码往往在计算上开销很大，并且在大多数情况下 会降低流的质量（即它是有损的），因此你应当只在 需要时才转码，其他情况下应进行流拷贝。需要转码的典型 原因有：

  • 应用滤镜 —— 例如缩放、去隔行或叠加视频；重采样 或混合音频；
  • 你想把这条流送给无法解码原始编解码器的某个东西。

请注意，除非你为音频、视频和字幕流指定 -c copy， 否则 ffmpeg 将转码它们中的全部。

考虑一个示例流水线：它读取一个包含一条音频流和一条 视频流的输入文件，对视频进行转码并复制音频，写入单个输出 文件。这可以示意如下

3.3.2 复杂滤镜图# TOC

复杂滤镜图是那些不能简单地描述为作用于一条流的线性 处理链的滤镜图。例如，当滤镜图有不止一个输入和/或输出时， 或者当输出流的类型与输入不同时，就属于这种情况。复杂滤镜图通过 -filter_complex 选项进行配置。请注意该选项是全局的，因为 复杂滤镜图从本质上讲无法明确地关联到 单条流或单个文件。每个 -filter_complex 实例都会创建一个新的 复杂滤镜图，并且可以有任意多个这样的实例。

复杂滤镜图的一个简单例子是 overlay 滤镜，它有 两个视频输入和一个视频输出，其内容是一路视频叠加在另一路 之上。与之对应的音频版本是 amix 滤镜。

3.4 回环解码器# TOC

虽然解码器通常与解复用器流相关联，但也可以 创建 "环路" 解码器，用来解码某个编码器的输出，并 允许把它送回复杂滤镜图。这是通过 -dec 指令完成的，该指令以一个应当被解码的输出流的索引作为 参数。每一条这样的指令都会创建一个新的回环解码器，索引从 零开始以连续整数编号。这些索引随后应被用于在复杂滤镜图 链接标签中引用回环解码器，具体描述见 -filter_complex 的文档。

可以通过把解码 AVOptions 放在 -dec 之前来传给 回环解码器，这与输入/输出选项类似。

例如，下面的例子： 

ffmpeg -i INPUT                                        \
  -map 0:v:0 -c:v libx264 -crf 45 -f null -            \
  -threads 3 -dec 0:0                                  \
  -filter_complex '[0:v][dec:0]hstack[stack]'          \
  -map '[stack]' -c:v ffv1 OUTPUT

读取一个输入视频，并

  • （第 2 行）以低质量用 libx264 对它编码；
  • （第 3 行）使用 3 个线程解码这个已编码的流；
  • （第 4 行）把解码后的视频与原始输入视频并排放在一起；
  • （第 5 行）合并后的视频随后被无损编码并写入 OUTPUT。

4 流选择# TOC

ffmpeg 提供了 -map 选项，用于手动控制每个 输出文件中的流选择。用户可以跳过 -map，让 ffmpeg 按下文所述 执行自动流选择。-vn / -an / -sn / -dn 选项可用于分别跳过对 视频、音频、字幕和数据流的包含，无论这些流是手动映射的还是自动 选择的，复杂滤镜图的输出流除外。

4.1 描述# TOC

后续各小节介绍流选择所涉及的各种规则。 再往后的示例则展示这些规则在实际中如何应用。

尽管我们尽力准确反映该程序的行为，但 FFmpeg 一直在持续开发中， 代码可能自本文撰写以来已经发生变化。

4.1.1 自动流选择# TOC

当某个输出文件没有任何 map 选项时，ffmpeg 会检查输出格式，以确认其中可以包含哪些类型的流， 即视频流、音频流和/或字幕流。对于每一种可接受的流类型，只要有可用的流， ffmpeg 就会从所有输入中挑选出一条这样的流。

它将依据以下准则来选择该流：

  • 对于视频，选择分辨率最高的流，
  • 对于音频，选择声道数最多的流，
  • 对于字幕，选择找到的第一条字幕流，但这里有个需要注意的地方。 输出格式的默认字幕编码器可能是基于文本的，也可能是基于图像的， 因此只会选择同类型的字幕流。

如果有若干条同类型的流条件相当，则选择索引最小的那条流。

数据流或附件流不会被自动选中，只能通过 -map 来包含。

4.1.2 手动流选择# TOC

使用 -map 时，该输出文件中只包含用户映射的流， 下文所述的滤镜图输出是一个可能的例外。

4.1.3 复杂滤镜图# TOC

如果存在任何带有未标记 pad 的复杂滤镜图输出流，它们会被添加到第一个输出文件。 如果输出格式不支持该流类型，这会导致致命错误。在没有 map 选项时， 包含这些流会使它们所属类型的自动流选择被跳过。如果存在 map 选项， 则这些滤镜图流会在映射的流之外额外被包含进来。

带有已标记 pad 的复杂滤镜图输出流必须被映射，且只能映射一次。

4.1.4 流的处理# TOC

流的处理与流选择彼此独立，下文所述的字幕是一个例外。流的处理通过 针对特定输出文件中的流的 -codec 选项来设置。特别是，编解码器选项由 ffmpeg 在流选择过程之后应用，因此不会影响后者。如果没有为某种流类型指定 -codec 选项，ffmpeg 将选择由输出文件复用器注册的默认编码器。

字幕存在一个例外。如果为某个输出文件指定了字幕编码器，那么找到的 第一条任意类型（文本或图像）的字幕流都会被包含进来。ffmpeg 不会验证 指定的编码器能否转换所选的流，也不会验证转换后的流在输出格式中是否可接受。 这一点同样普遍适用：当用户手动设置编码器时，流选择过程无法检查编码后的流 能否被复用进输出文件。如果不能，ffmpeg 将中止，并且所有输出文件都将处理失败。

4.2 示例# TOC

以下示例演示了 ffmpeg 流选择方法的行为、怪癖和局限。

它们假定存在下面三个输入文件。 

input file 'A.avi'
      stream 0: video 640x360
      stream 1: audio 2 channels

input file 'B.mp4'
      stream 0: video 1920x1080
      stream 1: audio 2 channels
      stream 2: subtitles (text)
      stream 3: audio 5.1 channels
      stream 4: subtitles (text)

input file 'C.mkv'
      stream 0: video 1280x720
      stream 1: audio 2 channels
      stream 2: subtitles (image)

ffmpeg -i A.avi -i B.mp4 out1.mkv out2.wav -map 1:a -c:a copy out3.mov

这里指定了三个输出文件，而前两个没有设置 -map 选项， 因此 ffmpeg 会自动为这两个文件选择流。

out1.mkv 是 Matroska 容器文件，接受视频流、音频流和字幕流， 所以 ffmpeg 会尝试为每种类型各选择一条流。
对于视频，它会选择 B.mp4 中的 stream 0，其分辨率 在所有输入视频流中最高。
对于音频，它会选择 B.mp4 中的 stream 3，因为它的 声道数最多。
对于字幕，它会选择 B.mp4 中的 stream 2，这是 A.avi 和 B.mp4 中的第一条字幕流。

out2.wav 只接受音频流，因此只选择了 B.mp4 中的 stream 3。

对于 out3.mov，由于设置了 -map 选项，不会发生自动流选择。 -map 1:a 选项将选择第二个输入 B.mp4 中的所有音频流。 该输出文件中不会包含其他任何流。

对于前两个输出，所有被包含的流都将被转码。所选的编码器将是各输出格式注册的 默认编码器，它们可能与被选中的输入流的编解码器并不一致。

对于第三个输出，音频流的编解码器选项已被设置为 copy， 因此不会发生、也不能发生解码-滤镜-编码操作。 被选中流的包将从输入文件传递出来，并在输出文件内被复用。 

ffmpeg -i C.mkv out1.mkv -c:s dvdsub -an out2.mkv

尽管 out1.mkv 是接受字幕流的 Matroska 容器文件， 但只会选择一条视频流和一条音频流。C.mkv 中的字幕流是基于图像的， 而 Matroska 复用器的默认字幕编码器是基于文本的，因此对字幕的转码操作 预计会失败，所以不会选择该流。然而在 out2.mkv 中， 命令里指定了字幕编码器，因此除视频流之外，字幕流也会被选中。 -an 的存在则禁用了 out2.mkv 的音频流选择。 

ffmpeg -i A.avi -i C.mkv -i B.mp4 -filter_complex "overlay" out1.mp4 out2.srt

这里使用 -filter_complex 选项建立了一个滤镜图，它由单个 视频滤镜构成。overlay 滤镜恰好需要两路视频输入，但并未指定， 因此会使用最先可用的两条视频流，即 A.avi 和 C.mkv 的流。该滤镜的输出 pad 没有标签，因此被送往第一个输出文件 out1.mp4。正因如此，视频流的自动选择被跳过， 否则本应选中 B.mp4 中的流。声道数最多的音频流，即 B.mp4 中的 stream 3，被自动选中。不过没有选择任何字幕流， 因为 MP4 格式没有注册默认字幕编码器，而用户也没有指定字幕编码器。

第二个输出文件 out2.srt 只接受基于文本的字幕流。因此，即便 最先可用的字幕流属于 C.mkv，由于它是基于图像的，也会被跳过。 被选中的流是 B.mp4 中的 stream 2，即第一条基于文本的字幕流。 

ffmpeg -i A.avi -i B.mp4 -i C.mkv -filter_complex "[1:v]hue=s=0[outv];overlay;aresample" \
       -map '[outv]' -an        out1.mp4 \
                                out2.mkv \
       -map '[outv]' -map 1:a:0 out3.mkv

上述命令会失败，因为标记为 [outv] 的输出 pad 被映射了两次。 所有输出文件都不会被处理。 

ffmpeg -i A.avi -i B.mp4 -i C.mkv -filter_complex "[1:v]hue=s=0[outv];overlay;aresample" \
       -an        out1.mp4 \
                  out2.mkv \
       -map 1:a:0 out3.mkv

上面这条命令同样会失败，因为 hue 滤镜的输出带有一个标签 [outv]， 却没有任何地方对它进行映射。

该命令应修改如下， 

ffmpeg -i A.avi -i B.mp4 -i C.mkv -filter_complex "[1:v]hue=s=0,split=2[outv1][outv2];overlay;aresample" \
        -map '[outv1]' -an        out1.mp4 \
                                  out2.mkv \
        -map '[outv2]' -map 1:a:0 out3.mkv

B.mp4 的视频流被送入 hue 滤镜，其输出再由 split 滤镜复制一份， 两个输出都带有标签。随后各取一份副本映射到第一个和第三个输出文件。

overlay 滤镜需要两路视频输入，它会使用最先两条尚未被使用的视频流， 也就是来自 A.avi 和 C.mkv 的流。overlay 的输出没有标签， 因此无论是否设置了 -map 选项，它都会被送往第一个输出文件 out1.mp4。

aresample 滤镜收到的是最先一条尚未使用的音频流，即 A.avi 的那条流。由于该滤镜 的输出同样没有标签，它也被映射到第一个输出文件。-an 的存在 只抑制音频流的自动或手动流选择，而不影响滤镜图送出的输出。 这两条被映射的流将排在 out1.mp4 中那条被映射的流之前。

映射到 out2.mkv 的视频流、音频流和字幕流完全由自动流选择决定。

out3.mkv 由 hue 滤镜复制出的视频输出和 B.mp4 的第一条音频流 组成。

5 选项# TOC

所有数值选项，除非另有说明，都接受一个表示数字的字符串作为输入， 该字符串后面可跟一个 SI 单位前缀，例如：’K’、’M’ 或 ’G’。

如果在 SI 单位前缀后面附加 ’i’，整个前缀将被 解释为二进制倍数的单位前缀，它们以 1024 的 幂而不是 1000 的幂为基准。在 SI 单位前缀后面附加 ’B’ 会把数值乘以 8。这样就允许使用例如： ’KB’、’MiB’、’G’ 和 ’B’ 作为数字后缀。

不接受参数的选项是布尔选项，会把 相应的值设为 true。在选项名前加上 "no" 即可把它们设为 false。 例如使用 "-nofoo" 会把名为 "foo" 的布尔选项设为 false。

接受参数的选项支持一种特殊语法：命令行上给出的参数 会被解释为一个文件路径，实际的参数值将从该 文件中加载。要使用此功能，请在选项名前 （前导短横线之后）紧跟一个正斜杠 ’/’。例如 

ffmpeg -i INPUT -/filter:v filter.script OUTPUT

将从名为 filter.script 的文件中加载滤镜图描述。

5.1 流说明符# TOC

有些选项是按每条流应用的，例如码率或编解码器。流说明符 用于精确指定给定选项属于哪一条（些）流。

流说明符是一个字符串，通常附加在选项名之后， 并用冒号与选项名分隔。例如 -codec:a:1 ac3 中包含 流说明符 a:1，它匹配第二条音频流。因此，它 会为第二条音频流选择 ac3 编解码器。

一个流说明符可以匹配多条流，从而让该选项应用到 所有这些流。例如 -b:a 128k 中的流说明符匹配所有音频 流。

空的流说明符匹配所有流。例如 -codec copy 或 -codec: copy 会在不重新编码的情况下拷贝所有流。

流说明符可能的形式有：

stream_index

匹配具有此索引的流。例如 -threads:1 4 会把 第二条流的线程数设为 4。如果 stream_index 被用作 额外的流说明符（见下文），那么它会从匹配的流中 选择编号为 stream_index 的流。流编号基于 libavformat 检测到的流顺序，除非同时指定了流组 说明符或节目 ID。在这种情况下，编号基于 该组或节目中流的排列顺序。

stream_type[:additional_stream_specifier]

stream_type 为以下之一：’v’ 或 ’V’ 表示视频，’a’ 表示音频，’s’ 表示字幕，’d’ 表示数据，’t’ 表示附件。’v’ 匹配所有视频 流，’V’ 只匹配不是附加图片、视频缩略图 或封面图的视频流。如果使用了 additional_stream_specifier，那么 它匹配既具有此类型、又匹配 additional_stream_specifier 的流。否则，它匹配指定类型的 所有流。

g:group_specifier[:additional_stream_specifier]

匹配位于说明符为 group_specifier 的组中的流。 如果使用了 additional_stream_specifier，那么它匹配既 属于该组、又匹配 additional_stream_specifier 的流。 group_specifier 可以是以下之一：

group_index

匹配具有此组索引的流。

#group_id or i:group_id

匹配具有此组 id 的流。

p:program_id[:additional_stream_specifier]

匹配 id 为 program_id 的节目中的流。如果 使用了 additional_stream_specifier，那么它匹配既 属于该节目、又匹配 additional_stream_specifier 的流。

#stream_id or i:stream_id

按流 id 匹配流（例如 MPEG-TS 容器中的 PID）。

m:key[:value]

匹配元数据标签 key 具有指定值的流。如果 未给出 value，则匹配包含给定标签且取任意 值的流。key 或 value 中的冒号字符 ’:’ 需要 用反斜杠转义。

disp:dispositions[:additional_stream_specifier]

匹配具有给定处置（disposition）的流。dispositions 是一个 或多个处置的列表（如 -dispositions 选项所输出的）， 以 ’+’ 连接。

u

匹配具有可用配置的流，编解码器必须已定义，并且 视频尺寸或音频采样率等必要信息必须存在。

请注意，在 ffmpeg 中，按元数据匹配只对 输入文件正常工作。

loglevel 是一个字符串或数字，包含以下值之一：

‘quiet, -8’

什么都不显示；保持静默。

‘panic, 0’

只显示可能导致进程崩溃的致命错误，例如 断言失败。目前它未用于任何用途。

‘fatal, 8’

只显示致命错误。这些错误发生后进程绝对 无法继续。

‘error, 16’

显示所有错误，包括可以恢复的错误。

‘warning, 24’

显示所有警告和错误。任何与可能不正确或 意外的事件相关的消息都会显示。

‘info, 32’

在处理过程中显示提示性消息。这是在 警告和错误之外额外显示的消息。这是默认值。

‘verbose, 40’

与 info 相同，只是更详细。

‘debug, 48’

显示所有内容，包括调试信息。

‘trace, 56’

例如，要启用重复日志输出、添加 level 前缀，并将 loglevel 设为 verbose： 

ffmpeg -loglevel repeat+level+verbose -i input output

另一个例子，在启用重复日志输出的同时不影响 level 前缀标志或 loglevel 的当前状态： 

ffmpeg [...] -loglevel +repeat

默认情况下，程序将日志记录到 stderr。如果终端支持 着色，则会用颜色标记错误和警告。日志着色 可以通过设置环境变量 AV_LOG_FORCE_NOCOLOR 来禁用，也可以通过设置 环境变量 AV_LOG_FORCE_COLOR 来强制启用。

-report

将完整的命令行和日志输出转储到当前目录下名为 program-YYYYMMDD-HHMMSS.log 的文件中。 该文件对提交错误报告很有用。 它还会隐含启用 -loglevel debug。

将环境变量 FFREPORT 设为任意值具有 相同的效果。如果该值是以 ’:’ 分隔的 key=value 序列，这些 选项将影响报告；如果选项值 包含特殊字符或选项分隔符 ’:’，则必须对其转义（参见 ffmpeg-utils 手册中的 “Quoting and escaping” 一节）。

可识别以下选项：

file

设置用于报告的文件的名称；%p 会展开为 程序名，%t 会展开为时间戳，%% 会展开为 普通的 %

使用数值设置日志详细程度级别（参见 -loglevel）。

例如，要将报告输出到名为 ffreport.log 的文件， 并使用 32 的日志级别（日志级别 info 的别名）：

解析环境变量时出现的错误不是致命的，也不会 出现在报告中。

5.3 AVOptions# TOC

这些选项由 libavformat、libavdevice 和 libavcodec 库直接提供。要查看可用的 AVOptions 列表，请使用 -help 选项。它们分为两类：

generic

这些选项可以为任何容器、编解码器或设备设置。通用选项 对于容器/设备列在 AVFormatContext 选项下，对于编解码器则列在 AVCodecContext 选项下。

private

这些选项特定于给定的容器、设备或编解码器。私有 选项列在它们对应的容器/设备/编解码器之下。

例如，要把 ID3v2.3 头部而非默认的 ID3v2.4 写入 MP3 文件，请使用 MP3 复用器的 id3v2_version 私有选项： 

ffmpeg -i input.flac -id3v2_version 3 out.mp3

所有编解码器 AVOption 都是按流设置的，因此需要为其附加 流说明符： 

ffmpeg -i multichannel.mxf -map 0:v:0 -map 0:a:0 -map 0:a:0 -c:a:0 ac3 -b:a:0 640k -ac:a:1 2 -c:a:1 aac -b:2 128k out.mp4

在上面的示例中，一个多声道音频流被映射了两次用于输出。 第一个实例使用编解码器 ac3 编码，码率为 640k。 第二个实例被下混为 2 声道并使用编解码器 aac 编码。为其指定 128k 码率时使用的是 输出流的绝对索引。

注意：-nooption 语法不能用于布尔型 AVOption，请使用 -option 0/-option 1。

注意：过去那种未写入文档的按流指定 AVOption 的方式——在选项名前面加上 v/a/s——现已过时，并将在不久后 被移除。

5.4 主要选项# TOC

-f fmt (输入/输出)

强制指定输入或输出文件格式。格式通常对输入 文件自动检测，对输出文件则根据文件扩展名推断，因此在大多数情况下 不需要此选项。

-i url (输入)

输入文件的 url

-y (全局)

覆盖输出文件而不询问。

-n (全局)

不覆盖输出文件，并且如果指定的输出文件已存在则立即退出。

-stream_loop number (输入)

设置输入流应循环的次数。循环 0 表示不循环， 循环 -1 表示无限循环。

-recast_media (全局)

允许强制使用与解复用器检测到或指定的媒体类型不同的解码器。对于解码 被复用为数据流的媒体数据很有用。

-c[:stream_specifier] codec (输入/输出,每条流)
-codec[:stream_specifier] codec (输入/输出,每条流)

为一条或多条 stream 选择编码器（在输出文件之前使用时）或解码器（在 输入文件之前使用时）。codec 是解码器/编码器的名称， 或者是特殊值 copy（仅用于输出），表示该 stream 不重新编码。

例如 

ffmpeg -i INPUT -map 0 -c:v libx264 -c:a copy OUTPUT

会使用 libx264 编码所有视频流，并拷贝所有音频流。

对于每条流，最后一条匹配的 c 选项生效，因此 

ffmpeg -i INPUT -map 0 -c copy -c:v:1 libx264 -c:a:137 libvorbis OUTPUT

会拷贝所有流，但第二个视频流除外，它将以 libx264 编码；第 138 个音频流也一样，它将以 libvorbis 编码。

-t duration (输入/输出)

当用作输入选项时（在 -i 之前），限制从输入文件读取数据的 duration。

当用作输出选项时（在输出 url 之前），在输出时长达到 duration 后停止写入输出。

duration 必须是时间时长格式的说明， 参见 ffmpeg-utils(1) 手册中的时间时长一节。

-to 与 -t 互斥，且 -t 优先。

-to position (输入/输出)

在 position 处停止写入输出或读取输入。 position 必须是时间时长格式的说明， 参见 ffmpeg-utils(1) 手册中的时间时长一节。

-to 与 -t 互斥，且 -t 优先。

-fs limit_size (输出)

设置文件大小限制，以字节为单位。超过该限制后不再写入更多字节块。 输出文件的大小会略大于所请求的文件大小。

-ss position (输入/输出)

当用作输入选项时（在 -i 之前），在该输入文件中定位到 position。请注意，在大多数格式中无法精确寻址， 因此 ffmpeg 会定位到 position 之前最近的可寻址点。 在转码且启用了 -accurate_seek（默认值）时， 寻址点与 position 之间的这段额外片段将被解码并 丢弃。在进行流拷贝或使用 -noaccurate_seek 时， 它会被保留。

当用作输出选项时（在输出 url 之前），会解码但丢弃 输入，直到时间戳到达 position。

position 必须是时间时长格式的说明， 参见 ffmpeg-utils(1) 手册中的时间时长一节。

-sseof position (输入)

类似 -ss 选项，但相对于 "文件末尾"。也就是说，负值 表示文件中更靠前的位置，0 表示 EOF。

-isync input_index (输入)

将某个输入指定为同步源。

这会取目标输入与参考输入起始时间之间的差值，并用该差值 偏移目标文件的时间戳。为获得预期结果，两个输入的源时间戳 应来自同一时钟源。如果设置了 copyts， 则还必须设置 start_at_zero。如果两个输入中任意一个没有起始时间戳， 则不做同步调整。

可接受的值是那些指向有效 ffmpeg 输入索引的值。如果同步参考 就是目标索引本身或 -1，则不对目标时间戳做调整。一个同步 参考本身不可以再同步到任何其他输入。

默认值为 -1。

-itsoffset offset (输入)

设置输入时间偏移。

offset 必须是时间时长格式的说明， 参见 ffmpeg-utils(1) 手册中的时间时长一节。

该偏移会加到输入文件的时间戳上。指定 正偏移意味着相应的流会延迟 offset 所指定的时长。

-itsscale scale (输入,每条流)

重新缩放输入时间戳。scale 应为浮点数。

-timestamp date (输出)

设置容器中的录制时间戳。

date 必须是日期格式的说明， 参见 ffmpeg-utils(1) 手册中的日期一节。

-metadata[:metadata_specifier] key=value (输出,每项元数据)

设置一个元数据键/值对。

可以给出可选的 metadata_specifier，以在 stream、章节或节目上设置元数据。详情参见 -map_metadata 文档。

此选项会覆盖通过 -map_metadata 设置的元数据。也可以 通过使用空值来删除元数据。

例如，要在输出文件中设置标题： 

ffmpeg -i in.avi -metadata title="my title" out.flv

要设置第一条音频流的语言： 

ffmpeg -i INPUT -metadata:s:a:0 language=eng OUTPUT
-keep_metadata[:metadata_specifier] key (输出,每项元数据)

在重新编码 stream 时，某些可能会过时的元数据键 （例如 iTunSMPB 或 encoded_by）会被自动丢弃。 此选项可防止某个特定的键被丢弃，从而保留其来自输入的 原始值。

若不带说明符，该键会在所有元数据上下文中保留（格式和 stream）。使用 g 可限制为格式（全局）元数据，或者使用 s 并 带上可选的 stream 说明符，以仅限制为匹配的 stream。

例如，要在重新编码时仅在格式元数据中保留 iTunSMPB： 

ffmpeg -i in.mp3 -keep_metadata:g iTunSMPB out.mp3

要仅为视频 stream 保留 NUMBER_OF_BYTES： 

ffmpeg -i in.mkv -keep_metadata:s:v NUMBER_OF_BYTES out.mkv

有些键在元数据中是带后缀存储的（例如 NUMBER_OF_BYTES-eng）。指定不带后缀的族名（例如 NUMBER_OF_BYTES）会保留所有变体。若要只保留特定的某个变体， 请显式指定完整键名： 

ffmpeg -i in.mkv -keep_metadata:s:v NUMBER_OF_BYTES-eng out.mkv

有些键（例如 major_brand、minor_version 和 compatible_brands）无论是否重新编码都会被始终移除，因为它们 描述的是源容器，在输出中没有意义。 即使在流拷贝时，-keep_metadata 也对这些键生效。

仅与重新编码相关的键（例如编码器标签和 Matroska stream 统计信息） 只在该 stream 被重新编码时才从该 stream 的元数据中移除， 并且只有在至少有一条音频或视频 stream 被重新编码时才从格式元数据中移除。

只有格式和 stream 元数据会被过滤。章节和节目元数据 绝不会被此机制修改。

-disposition[:stream_specifier] value (输出,每条流)

设置某条 stream 的 disposition 标志。

默认值：默认情况下，所有 disposition 标志都从输入 stream 拷贝， 除非此选项所适用的输出 stream 由复杂滤镜图馈入 —— 在这种情况下默认不设置任何 disposition 标志。

value 是由 ’+’ 或 ’-’ 分隔的一系列 disposition 标志。以 ’+’ 为前缀会添加给定的 disposition，’-’ 则移除它。如果第一个标志也 带有 ’+’ 或 ’-’ 前缀，则得到的 disposition 是默认值 经 value 更新后的结果。如果第一个标志不带前缀，则得到的 disposition 就是 value。也可以通过将其设置为 0 来清除 disposition。

如果没有为某个输出文件指定任何 -disposition 选项，ffmpeg 会 自动在每种类型的第一条 stream 上设置 ’default’ disposition 标志， 前提是输出文件中该类型有多条 stream，且没有任何该类型的 stream 已被标记为 default。

-dispositions 选项会列出已知的 disposition 标志。

例如，要把第二条音频流设为默认流： 

ffmpeg -i in.mkv -c copy -disposition:a:1 default out.mkv

要把第二条字幕流设为默认流，并移除第一条字幕流的 default disposition： 

ffmpeg -i in.mkv -c copy -disposition:s:0 0 -disposition:s:1 default out.mkv

要添加内嵌的封面/缩略图： 

ffmpeg -i in.mp4 -i IMAGE -map 0 -map 1 -c copy -c:v:1 png -disposition:v:1 attached_pic out.mp4

要为第一条音频流添加 ’original’ 标志并移除 ’comment’ disposition 标志， 同时不移除其他 disposition 标志： 

ffmpeg -i in.mkv -c copy -disposition:a:0 +original-comment out.mkv

要为第一条音频流移除 ’original’ 标志并添加 ’comment’ disposition 标志， 同时不移除其他 disposition 标志： 

ffmpeg -i in.mkv -c copy -disposition:a:0 -original+comment out.mkv

要仅在第一条音频流上设置 ’original’ 和 ’comment’ disposition 标志 （并移除该流的其他 disposition 标志）： 

ffmpeg -i in.mkv -c copy -disposition:a:0 original+comment out.mkv

要移除第一条音频流的所有 disposition 标志： 

ffmpeg -i in.mkv -c copy -disposition:a:0 0 out.mkv

并非所有复用器都支持内嵌缩略图，而支持的那些也只支持少数格式， 例如 JPEG 或 PNG。

描述该混音的 key=value 字符串，其中 "key" 是符合 BCP-47 的字符串，用于指定 "value" 字符串的语言。"key" 必须与 所有子混音元素的 annotations 中的一致

例如，要从若干个 WAV 输入文件创建一个可伸缩的 5.1 IAMF 文件 

ffmpeg -i front.wav -i back.wav -i center.wav -i lfe.wav
-map 0:0 -map 1:0 -map 2:0 -map 3:0 -c:a opus
-stream_group type=iamf_audio_element:id=1:st=0:st=1:st=2:st=3,
demixing=parameter_id=998,
recon_gain=parameter_id=101,
layer=ch_layout=stereo,
layer=ch_layout=5.1(side),
-stream_group type=iamf_mix_presentation:id=2:stg=0:annotations=en-us=Mix_Presentation,
submix=parameter_id=100:parameter_rate=48000|element=stg=0:parameter_id=100:annotations=en-us=Scalable_Submix|layout=sound_system=stereo|layout=sound_system=5.1(side)
-streamid 0:0 -streamid 1:1 -streamid 2:2 -streamid 3:3 output.iamf

要把带有四个流的输入 IAMF 文件中的两个流组（Audio Element 和 Mix Presentation） 拷贝到 mp4 输出中 

ffmpeg -i input.iamf -c:a copy -stream_group map=0=0:st=0:st=1:st=2:st=3 -stream_group map=0=1:stg=0
-streamid 0:0 -streamid 1:1 -streamid 2:2 -streamid 3:3 output.mp4
-reinit_opts[:stream_specifier] pts=pts|key=value[:force_reinit=1][:key=value,pts=pts...] (输出,每条流)

创建一个以 "," 分隔的选项组，用于在指定的输出 pts 处以 AV_TIME_BASE 为单位重新配置编码器。 伪选项 force_reinit 确保编码器被完全重新初始化， 而不是仅仅重新配置。

-dn (输入/输出)

作为输入选项时，阻止文件中的所有数据流被滤镜处理， 或被自动选择或映射到任何输出。参见 -discard 选项可单独禁用各条流。

作为输出选项时，禁用数据记录，即不自动选择或 映射任何数据流。要完全手动控制，请参见 -map 选项。

-dframes number (输出)

设置要输出的数据帧数量。这是 -frames:d 的过时别名，你应该改用后者。

-frames[:stream_specifier] framecount (输出,每条流)

在写入 framecount 帧后停止写入该流。

-q[:stream_specifier] q (输出,每条流)
-qscale[:stream_specifier] q (输出,每条流)

使用固定的质量标度（VBR）。q/qscale 的含义 取决于编解码器。 如果在不带 stream_specifier 的情况下使用 qscale，则它只 作用于视频流，这样做是为了保持与以往行为的兼容性， 因为在不使用 stream_specifier 时，把同一个编解码器特定值用于两个不同的编解码器 （即音频和视频）通常并不是本意。

-filter[:stream_specifier] filtergraph (输出,每条流)

创建由 filtergraph 指定的滤镜图，并用它来 过滤该流。

filtergraph 是要施加于该流上的滤镜图的描述， 它必须具有单个输入和单个输出，且都与该流的类型相同。 在滤镜图中，输入关联到标签 in，输出关联到标签 out。关于滤镜图 语法的更多信息，参见 ffmpeg-filters 手册。

如果你想创建具有多个输入和/或多个输出的滤镜图， 请参见 -filter_complex 选项。

-reinit_filter[:stream_specifier] integer (输入,每条流)

这个布尔选项决定当输入帧参数在流中途发生变化时，接收该流的滤镜图 是否会被重新初始化。此选项默认启用，因为大多数视频滤镜和所有音频滤镜 都无法处理输入帧属性的变化。 重新初始化时，已有的滤镜状态会丢失，例如某些滤镜中可用的 帧计数 n 引用。重新初始化时缓冲的任何帧也会丢失。 会触发重新初始化的属性变化包括： 对于视频，是帧分辨率或像素格式； 对于音频，是采样格式、采样率、声道数或声道布局。

-drop_changed[:stream_specifier] integer (输入,每条流)

这个布尔选项决定当帧参数在流中途发生变化时，该帧是被丢弃， 还是导致滤镜图重新初始化（后者会造成 滤镜状态丢失）。通常用于避免直播输入中出现损坏但仍可解码的包。 默认值为 false。

-filter_threads nb_threads (全局)

定义用于处理一条滤镜流水线的线程数。每条流水线 都会创建一个线程池，其中有这么多线程可用于并行处理。 默认值为可用 CPU 的数量。

-filter_buffered_frames nb_frames (全局)

定义滤镜图中允许缓冲的最大帧数。在 正常情况下，滤镜图不应缓冲超过几帧， 尤其是在向它送入帧、又从它读取帧的过程保持平衡时 （这是 ffmpeg 中的预期行为）。尽管如此，此选项允许你 限制滤镜图中所有链路上缓冲的帧总数。 如果生成的帧更多，滤镜处理将中止并返回错误。 默认值为 0，表示不限制。

-pre[:stream_specifier] preset_name (输出,每条流)

为匹配的流指定预设。

-stats (全局)

以 "info" 级别的日志记录编码进度/统计信息（参见 -loglevel）。 它默认开启，要显式禁用它需要指定 -nostats。

-stats_period time (全局)

设置编码进度/统计信息的更新周期。默认值为 0.5 秒。

-print_graphs (全局)

按 -print_graphs_format 设置的格式把执行图详情打印到 stderr。

-print_graphs_file filename (全局)

按 -print_graphs_format 设置的格式把执行图详情写入指定文件。

-print_graphs_format format (全局)

设置输出格式（可用格式有：default、compact、csv、flat、ini、json、xml、mermaid、mermaidhtml） 默认格式为 json。

-progress url (全局)

把便于程序解析的进度信息发送到 url。

进度信息会定期写入，并在编码过程结束时写入一次。 它由 "key=value" 行组成。key 只包含字母数字字符。一段进度信息中的最后一个键 总是 "progress"，其值为 "continue" 或 "end"。

更新周期通过 -stats_period 设置。

例如，把进度信息记录到 stdout： 

ffmpeg -progress pipe:1 -i in.mkv out.mkv
-stdin

启用在标准输入上的交互。除非标准输入被用作 输入，否则默认开启。要显式禁用交互，需要指定 -nostdin。

禁用标准输入上的交互很有用，例如当 ffmpeg 位于后台进程组中时。用 ffmpeg ... < /dev/null 大致也能得到同样的效果，但那需要 一个 shell。

-debug_ts (全局)

打印时间戳/延迟信息。它默认关闭。此选项主要 用于测试和调试，其输出 格式可能随版本变化，因此不应 被可移植脚本使用。

另请参见 -fdebug ts 选项。

-attach filename (输出)

向输出文件添加附件。有少数格式支持此功能， 例如 Matroska 支持用于渲染字幕的字体。附件 是以一种特殊类型的流来实现的，因此此选项会向文件中 添加一条新流。之后就可以照常在这条流上使用 按流选项。用此选项创建的附件流会被创建在所有其他流之后 （即那些用 -map 或自动映射创建的流）。

请注意，对于 Matroska，你还必须设置 mimetype 元数据标签： 

ffmpeg -i INPUT -attach DejaVuSans.ttf -metadata:s:2 mimetype=application/x-truetype-font out.mkv

（假设该附件流在输出文件中排第三）。

-dump_attachment[:stream_specifier] filename (输入,每条流)

把匹配的附件流提取到名为 filename 的文件中。如果 filename 为空，则使用 filename 元数据标签的 值。

例如，要把第一个附件提取到名为 ’out.ttf’ 的文件中： 

ffmpeg -dump_attachment:t:0 out.ttf -i INPUT

要把所有附件提取到由 filename 标签确定的文件中： 

ffmpeg -dump_attachment:t "" -i INPUT

技术说明 – 附件是以编解码器 extradata 实现的，因此此 选项实际上可用于从任何流中提取 extradata，而不仅限于 附件。

向输出文件添加附件。有少数格式支持此功能， 例如 Matroska 支持用于渲染字幕的字体。附件 是以一种特殊类型的流来实现的，因此此选项会向文件中 添加一条新流。之后就可以照常在这条流上使用 按流选项。用此选项创建的附件流会被创建在所有其他流之后 （即那些用 -map 或自动映射创建的流）。

请注意，对于 Matroska，你还必须设置 mimetype 元数据标签： 

ffmpeg -i INPUT -attach DejaVuSans.ttf -metadata:s:2 mimetype=application/x-truetype-font out.mkv

（假设该附件流在输出文件中排第三）。

-dump_attachment[:stream_specifier] filename (输入,每条流)

把匹配的附件流提取到名为 filename 的文件中。如果 filename 为空，则使用 filename 元数据标签的 值。

例如，要把第一个附件提取到名为 ’out.ttf’ 的文件中： 

ffmpeg -dump_attachment:t:0 out.ttf -i INPUT

要把所有附件提取到由 filename 标签确定的文件中： 

ffmpeg -dump_attachment:t "" -i INPUT

技术说明 – 附件是以编解码器 extradata 实现的，因此此 选项实际上可用于从任何流中提取 extradata，而不仅限于 附件。

5.5 视频选项# TOC

-vframes number (输出)

设置要输出的视频帧数量。这是 -frames:v 的过时别名，你应该改用后者。

-r[:stream_specifier] fps (输入/输出,每条流)

设置帧率（Hz 值、分数或缩写）。

作为输入选项时，忽略文件中存储的任何时间戳，改为 假定帧率恒为 fps 来生成时间戳。 这与某些输入格式（如 image2 或 v4l2）所使用的 -framerate 选项 并不相同（在较老版本的 FFmpeg 中它们曾经相同）。 如有疑问，请使用 -framerate，而不要用输入选项 -r。

作为输出选项时：

video encoding

在编码之前复制或丢弃帧，以达到恒定的输出 帧率 fps。

video streamcopy

向复用器表明 fps 是该流的帧率。此时不会 丢弃或复制任何数据。如果 fps 与由包时间戳确定的实际流帧率不一致，可能会产生无效文件。 另请参见 setts 比特流滤镜。

5.6 高级视频选项# TOC

-fpsmax[:stream_specifier] fps (输出,每条流)

设置最大帧率（Hz 值、分数或缩写）。

当输出帧率被自动设置且高于此值时，把输出帧率限制在该值以内。 在处理批处理任务，或输入的帧率被错误检测为极高时很有用。 它不能与 -r 一起设置。在流拷贝期间它会被忽略。

-s[:stream_specifier] size (输入/输出,每条流)

设置帧尺寸。

作为输入选项时，这是 video_size 私有选项的快捷方式， 某些解复用器会识别它，因为这些格式的帧尺寸要么未 存储在文件中，要么是可配置的 – 例如裸视频或视频采集设备。

作为输出选项时，它会把 scale 视频滤镜插入到 相应滤镜图的末尾。若想插到开头或其他位置， 请直接使用 scale 滤镜。

格式为 ‘wxh’（默认值与源相同）。

-aspect[:stream_specifier] aspect (输出,每条流)

设置由 aspect 指定的视频显示宽高比。

aspect 可以是浮点数形式的字符串，也可以是 num:den 形式的字符串，其中 num 和 den 分别是 宽高比的分子和分母。例如 "4:3"、 "16:9"、"1.3333" 和 "1.7777" 都是合法的参数值。

如果与 -vcodec copy 一起使用，它会影响存储在容器层面的宽高比， 但不会影响已编码帧中存储的宽高比（如果存在的话）。

-display_rotation[:stream_specifier] rotation (输入,每条流)

设置视频旋转元数据。

rotation 是一个十进制数，指定视频在显示之前 应逆时针旋转的角度。

此选项会覆盖文件中存储的旋转/显示变换元数据（如果有）。 当视频被转码（而不是拷贝）且启用了 -autorotate 时， 视频会在滤镜处理阶段被旋转。否则，如果复用器支持， 该元数据会被写入输出文件。

如果给出了 -display_hflip 和/或 -display_vflip 选项， 它们会在此选项指定的旋转之后应用。

-display_hflip[:stream_specifier] (输入,每条流)

设置显示时图像是否应水平翻转。

更多细节参见 -display_rotation 选项。

-display_vflip[:stream_specifier] (输入,每条流)

设置显示时图像是否应垂直翻转。

更多细节参见 -display_rotation 选项。

-mastering_display[:stream_specifier] G(%u,%u)B(%u,%u)R(%u,%u)WP(%u,%u)L(%u,%u) (输入,每条流)

设置视频 mastering display 元数据。

G(%u,%u)B(%u,%u)R(%u,%u)WP(%u,%u)L(%u,%u) 是一个字符串，指定 GBR 各通道和白点（WP）的 X,Y 显示原色，单位为 0.00002；以及最大-最小亮度（L）值，单位为每平方米 0.0001 坎德拉。这些值是无符号整数，表示 一个有理数的分子，其中 GBR 和 (WP) 隐含分母为 50000， (L) 隐含分母为 10000。

此选项会覆盖文件中存储的 mastering display 元数据（如果有）。

-content_light[:stream_specifier] %u,%u (输入,每条流)

设置视频内容光级元数据。

%u,%u 是一个字符串，指定最大内容光级和最大图像 平均光级。

此选项会覆盖文件中存储的内容光级元数据（如果有）。

-vn (输入/输出)

作为输入选项时，阻止文件中的所有视频流被滤镜处理， 或被自动选择或映射到任何输出。参见 -discard 选项可单独禁用各条流。

作为输出选项时，禁用视频记录，即不自动选择或 映射任何视频流。要完全手动控制，请参见 -map 选项。

-vcodec codec (输出)

设置视频编解码器。这是 -codec:v 的别名。

-pass[:stream_specifier] n (输出,每条流)

选择遍数（1 或 2）。它用于进行两遍 视频编码。第一遍会把视频的统计信息记录到一个 日志文件中（另见 -passlogfile 选项）， 第二遍则使用该日志文件，以精确请求的码率 生成视频。 在第一遍时，你可以直接停用音频并把输出设为 null， Windows 和 Unix 的示例如下： 

ffmpeg -i foo.mov -c:v libxvid -pass 1 -an -f rawvideo -y NUL
ffmpeg -i foo.mov -c:v libxvid -pass 1 -an -f rawvideo -y /dev/null
-passlogfile[:stream_specifier] prefix (输出,每条流)

把两遍编码的日志文件名前缀设为 prefix，默认的文件名 前缀是 “ffmpeg2pass”。完整的文件名将是 PREFIX-N.log，其中 N 是该输出流特有的 编号

-vf filtergraph (输出)

创建由 filtergraph 指定的滤镜图，并用它来 过滤该流。

这是 -filter:v 的别名，参见 -filter 选项。

-autorotate

根据文件元数据自动旋转视频。默认启用， 使用 -noautorotate 可禁用。

-autoscale

根据第一帧的分辨率自动缩放视频。 默认启用，使用 -noautoscale 可禁用。当 autoscale 被禁用时，滤镜图的所有输出帧可能不在同一分辨率上， 并且可能不适合某些编码器/复用器。因此，除非你确实清楚自己在做什么， 否则不建议禁用它。 禁用 autoscale 的风险由你自己承担。

-filter_hw_device name

把名为 name 的硬件设备传递给任何滤镜图中的所有滤镜。 这可用于设置 hwupload 滤镜要上传到的设备， 或 hwmap 滤镜要映射到的设备。其他滤镜在需要硬件设备时 也可以使用此参数。请注意，通常只有在输入还不是硬件帧时才需要这样做 – 如果输入已经是硬件帧，滤镜会从它们所接收输入帧的上下文中 推导出所需的设备。

这是一项全局设置，因此所有滤镜都会收到同一个设备。

-hwaccel[:stream_specifier] hwaccel (输入,每条流)

使用硬件加速来解码匹配的流。hwaccel 的允许取值 有：

none

不使用任何硬件加速（默认值）。

auto

自动选择硬件加速方式。

vdpau

使用 VDPAU（Video Decode and Presentation API for Unix）硬件加速。

dxva2

使用 DXVA2（DirectX Video Acceleration）硬件加速。

d3d11va

使用 D3D11VA（DirectX Video Acceleration）硬件加速。

vaapi

使用 VAAPI（Video Acceleration API）硬件加速。

qsv

使用 Intel QuickSync Video 加速进行视频转码。

与大多数其他取值不同，此选项并不启用加速解码（只要选中 qsv 解码器， 就会自动使用加速解码），而是启用加速转码，且不把帧拷贝到 系统内存中。

要使其生效，解码器和编码器都必须支持 QSV 加速， 并且不能使用任何滤镜。

videotoolbox

使用 Video Toolbox 硬件加速。

如果所选的 hwaccel 不可用，或所选解码器不支持它， 则此选项无效。

请注意，大多数加速方式是为播放而设计的，在现代 CPU 上 不会比软件解码更快。此外，ffmpeg 通常需要把解码后的帧从 GPU 内存拷贝到系统 内存，这会导致进一步的性能损失。因此此选项主要 用于测试。

-hwaccel_device[:stream_specifier] hwaccel_device (输入,每条流)

选择用于硬件加速的设备。

此选项只有在同时指定了 -hwaccel 选项时才有意义。 它既可以按名称引用由 -init_hw_device 创建的现有设备， 也可以新建一个设备，其效果等同于 紧接在此之前调用 ‘-init_hw_device’ type:hwaccel_device。

-hwaccels

列出此 ffmpeg 构建中启用的所有硬件加速组件。 实际运行时的可用性取决于硬件以及是否安装了 合适的驱动。

-fix_sub_duration_heartbeat[:stream_specifier]

把某个输出视频流指定为心跳流，据此在收到 随机访问包时切分并输出当前仍在进行中的字幕。

这会降低那些尚未收到结束包或后续字幕的字幕的延迟。 其代价是，为了覆盖完整的时长，很可能会导致 字幕事件重复，因此在字幕事件传递到输出的时机 与延迟无关的使用场景中，不应使用此选项。

要使此选项生效，需要为相关的输入字幕流设置 -fix_sub_duration，并且该输入字幕流必须 直接映射到心跳流所在的那个输出。

在第一种形式中，会为来自输入文件的每个 stream 创建一个输出 stream，其索引为 input_file_id。如果给出了 stream_specifier， 则只使用与该说明符匹配的那些 stream（关于 stream_specifier 的语法， 请参见 Stream specifiers 一节）。

在 stream 标识符之前加一个 - 字符会创建 "负向" 映射。 它会禁用与已创建的映射相匹配的 stream。

在 stream 说明符之后可以给出一个可选的 view_specifier， 对于多视角视频，它指定要使用的视图。视图说明符可以具有 以下格式之一：

view:view_id

另一种 [linklabel] 形式会把复杂滤镜 图（参见 -filter_complex 选项）的输出映射到输出文件。 linklabel 必须与图中已定义的输出链接标签相对应。

使用此选项会禁用此输出文件的默认映射。

映射所有内容

把第一个输入文件中的所有 stream 都映射到输出

选择特定的 stream

ffmpeg -i INPUT -map 0:1 out.wav

ffmpeg -i a.mov -i b.mov -c copy -map 0:2 -map 1:6 out.mov
创建多个 stream 2

要从输入文件中选择所有视频以及第三个音频 stream： 

ffmpeg -i INPUT -map 0:v -map 0:a:2 OUTPUT
负向映射

要映射除第二个音频之外的所有 stream，请使用负向映射 

ffmpeg -i INPUT -map 0 -map -0:a:1 OUTPUT
可选映射

要映射第一个输入中的视频和音频 stream，并借助结尾的 ?，在第一个输入中不存在音频 stream 时忽略音频 映射： 

ffmpeg -i INPUT -map 0:v -map 0:a? OUTPUT
按语言映射

要挑选英语音频 stream： 

ffmpeg -i INPUT -map 0:m:language:eng OUTPUT
-ignore_unknown

忽略类型未知的输入 stream，而不是在尝试复制 此类 stream 时失败。

-copy_unknown

允许复制类型未知的输入 stream，而不是在尝试复制 此类 stream 时失败。

-map_metadata[:metadata_spec_out] infile[:metadata_spec_in] (输出,每条元数据)

从 infile 设置下一个输出文件的元数据信息。注意， 这些是文件索引（从零开始），而不是文件名。 可选的 metadata_spec_in/out 参数用于指定要复制哪些元数据。 元数据说明符可以具有以下形式：

g

全局元数据，即适用于整个文件的元数据

s[:stream_spec]

每条流的元数据。stream_spec 是 stream 说明符，如 Stream specifiers 一章所述。在输入元数据说明符中，会从第一个 匹配的 stream 复制。在输出元数据说明符中，会复制到所有匹配的 stream。

c:chapter_index

每个章节的元数据。chapter_index 是从零开始的章节索引。

p:program_index

每个节目的元数据。program_index 是从零开始的节目索引。

如果省略了元数据说明符，则默认为全局。

默认情况下，全局元数据从第一个输入文件复制， 每条流和每个章节的元数据随 stream/章节一起复制。这些 默认映射会因创建任何相关类型的映射而被禁用。可以使用负的 文件索引来创建一个仅用于禁用自动复制的虚拟映射。

例如，要把输入文件第一个 stream 的元数据复制到输出文件的全局 元数据： 

ffmpeg -i in.ogg -map_metadata 0:s:0 out.mp3

要执行相反的操作，即把全局元数据复制到所有音频 stream： 

ffmpeg -i in.mkv -map_metadata:s:a 0:g out.mkv

注意，在这个例子中简单地写 0 也可以，因为默认 假定为全局元数据。

-map_chapters input_file_index (输出)

把索引为 input_file_index 的输入文件中的章节复制到下一个 输出文件。如果没有指定章节映射，则从第一个 至少包含一个章节的输入文件复制章节。使用负的文件索引可以 禁用任何章节复制。

-benchmark (全局)

在一次编码结束时显示基准测试信息。 显示所用的实际时间、系统时间和用户时间以及最大内存消耗。 最大内存消耗并非在所有系统上都受支持， 如果不支持，它通常会显示为 0。

-benchmark_all (全局)

在编码过程中显示基准测试信息。 显示各个步骤（音频/视频编码/解码）中所用的实际时间、系统时间和用户时间。

-timelimit duration (全局)

在 ffmpeg 以 CPU 用户时间持续运行 duration 秒之后退出。

-dump (全局)

把每个输入包转储到 stderr。

-hex (全局)

转储包时，同时转储负载数据。

-readrate speed (输入)

限制输入读取速度。

其值是一个浮点正数，表示在一秒真实时间内 应摄入的媒体最大时长（以秒为单位）。 默认值为零，表示不限制摄入速度。 值 1 表示实时速度，等同于 -re。

主要用于模拟采集设备或实时输入 stream（例如从文件读取时）。 当输入是实际的采集设备或实时 stream 时，不应使用较小的值，因为 这可能造成丢包。

当输出包的流动速度很重要时（例如直播），它很有用。

-re (输入)

以原始帧率读取输入。这等同于设置 -readrate 1。

-readrate_initial_burst seconds

设置初始的读取突发时长（单位为秒），超过该时长后 -re/-readrate 将会生效。

-readrate_catchup speed (输入)

如果输入或输出被阻塞，导致实际读取速度落后于 所指定的 readrate，那么将启用此速率，直到输入赶上所指定的 readrate。 该值不得低于主 readrate。

-fps_mode[:stream_specifier] parameter (输出,每条流)

设置视频同步方法 / 帧率模式。

passthrough

每个帧都连同其时间戳从解复用器传递到复用器。

cfr

将通过复制和丢弃帧来精确达到所请求的 恒定帧率。

vfr

帧会连同其时间戳透传，或被丢弃，以避免 出现两个帧具有相同时间戳的情况。

auto

根据复用器的能力在 cfr 和 vfr 之间进行选择。这是 默认方法。

请注意，在此之后时间戳可能还会被复用器进一步修改。 例如，在格式选项 avoid_negative_ts 被启用的情况下。 使用 -map 可以指定时间戳应取自哪条流。你可以让视频或音频 保持不变，并将剩下的流同步到这条 未改动的流上。

-frame_drop_threshold parameter

丢帧阈值，用于指定视频帧在落后多少之后会被丢弃。 以帧率单位表示，因此 1.0 即为一帧。默认值为 -1.1。 一种可能的用途是在时间戳存在噪声时避免丢帧， 或者是在时间戳精确的情况下提高丢帧的 精度。

-apad parameters (输出,每条流)

为输出音频流填充。这等同于应用 -af apad。 参数是一个滤镜参数字符串，其构成方式与 apad 滤镜相同。 必须为该输出设置 -shortest，此选项才会生效。

-copyts

不处理输入时间戳，而是原样保留其数值，不尝试对其进行规范化。 尤其是，不会移除初始的起始时间 偏移量。

请注意，取决于 fps_mode 选项或复用器的特定处理方式 （例如在格式选项 avoid_negative_ts 被启用的情况下），即使选择了此选项，输出时间戳也可能 与输入时间戳不一致。

-start_at_zero

与 copyts 一起使用时，平移输入时间戳使其从零开始。

这意味着使用例如 -ss 50 会让输出时间戳从 50 秒开始， 而无论输入文件是从什么时间戳开始的。

-copytb mode

指定进行流拷贝时如何设置编码器时基。mode 是一个 整数值，可以取以下值之一：

1

使用解复用器的时基。

时基从对应的输入解复用器复制到输出编码器。 在拷贝可变帧率的视频流时，有时需要这样做以避免 时间戳非单调递增。

0

使用解码器的时基。

时基从对应的输入解码器复制到 输出编码器。

-1

尝试自动做出选择，以便生成合理的输出。

默认值为 -1。

-enc_time_base[:stream_specifier] timebase (输出,每条流)

设置编码器时基。timebase 可以取以下值之一：

0

根据媒体类型分配默认值。

对于视频，使用 1/framerate；对于音频，使用 1/samplerate。

demux

使用解复用器的时基。

filter

使用滤镜图的时基。

a positive number

使用所提供的数值作为时基。

该字段可以提供为两个整数的比值（例如 1:24、1:48000）， 或者提供为十进制数（例如 0.04166、2.0833e-5）

默认值为 0。

-bitexact (输入/输出)

为（解）复用器和（解/编）码器启用 bitexact 模式

-shortest (输出)

当最短的输出流结束时结束编码。

请注意，此选项可能需要缓冲帧，这会引入额外的 延迟。该延迟的最大值可以通过 -shortest_buf_duration 选项来控制。

-shortest_buf_duration duration (输出)

当至少有一条流是 "sparse"（即帧之间存在大间隔——这通常 是字幕的情况）时，-shortest 选项可能需要 缓冲大量数据。

此选项控制所缓冲帧的最大时长（以秒为单位）。 较大的值可以让 -shortest 选项产生更准确的结果， 但会增加内存占用和延迟。

默认值为 10 秒。

-dts_delta_threshold threshold

时间戳不连续增量阈值， 以秒的十进制数表示。

此选项启用的时间戳不连续校正仅适用于接受时间戳不连续的 输入格式（即启用了 AVFMT_TS_DISCONT 标志的格式）， 例如 MPEG-TS 和 HLS，并且在使用 -copyts 选项时会自动禁用 （除非检测到回绕）。

如果检测到绝对值大于 threshold 的时间戳 不连续，ffmpeg 会通过将当前的 DTS 和 PTS 减小/增大相应的增量值 来消除该不连续。

默认值为 10。

-dts_error_threshold threshold

时间戳错误增量阈值， 以秒的十进制数表示。

此选项启用的时间戳校正仅适用于不接受时间戳不连续的 输入格式（即未启用 AVFMT_TS_DISCONT 标志的格式）。

如果检测到绝对值大于 threshold 的时间戳 不连续，ffmpeg 将丢弃 PTS/DTS 时间戳值。

默认值为 3600*30（30 小时），这是任意 选取的，并且相当保守。

-muxdelay seconds (输出)

设置最大解复用-解码延迟。

-muxpreload seconds (输出)

设置初始解复用-解码延迟。

-streamid output-stream-index:new-value (输出)

为输出流分配新的 stream-id 值。此选项应在其所适用的 输出文件名之前指定。 在存在多个输出文件的情况下，可以为 streamid 重新分配不同的值。

例如，要将输出 mpegts 文件的流 0 的 PID 设为 33、 流 1 的 PID 设为 36： 

ffmpeg -i inurl -streamid 0:33 -streamid 1:36 out.ts
-bsf[:stream_specifier] bitstream_filters (输入/输出,每条流)

对匹配的流应用比特流滤镜。这些滤镜会作用于从解复用器收到的 每个包（当作为输入选项使用时），或者在包被发送到 复用器之前作用（当作为输出选项使用时）。

bitstream_filters 是以逗号分隔的比特流滤镜 规格列表，每一项的形式为 

filter[=optname0=optval0:optname1=optval1:...]
凡是需要作为选项值一部分的 ’,=:’ 字符，都需要 用反斜杠进行转义。

使用 -bsfs 选项可获取比特流滤镜列表。

例如 

ffmpeg -bsf:v h264_mp4toannexb -i h264.mp4 -c:v copy -an out.h264
将 h264_mp4toannexb 比特流滤镜（它会把 MP4 封装的 H.264 流转为 Annex B） 应用于输入视频流。

另一方面， 

ffmpeg -i file.mov -an -vn -bsf:s mov2textsub -c:s copy -f rawvideo sub.txt
将 mov2textsub 比特流滤镜（它从 MOV 字幕中提取文本） 应用于输出字幕流。不过请注意，由于这两个示例都使用 -c copy，滤镜是在输入还是输出上应用几乎没有区别—— 如果发生转码，情况就会不同。

-tag[:stream_specifier] codec_tag (输入/输出,每条流)

为匹配的流强制指定 tag/fourcc。

-timecode hh:mm:ssSEPff

指定要写入的时间码。SEP 对于非丢帧时间码为 ’:’， 对于丢帧时间码为 ’;’（或 ’.’）。 

ffmpeg -i input.mpg -timecode 01:02:03.04 -r 30000/1001 -s ntsc output.mpg
-filter_complex filtergraph (全局)

定义一个复杂滤镜图，即具有任意数量输入和/或 输出的滤镜图。对于简单图 – 即那些具有一个输入和一个同类型 输出的图 – 请参见 -filter 选项。filtergraph 是 对滤镜图的描述，说明见 ffmpeg-filters 手册的 “Filtergraph syntax” 一节。此选项可以多次指定 —— 每次使用 都会创建一个新的复杂滤镜图。

复杂滤镜图的输入可以来自不同的源类型， 通过相应链路标签的格式加以区分：

  • 要连接一个输入流，请使用 [file_index:stream_specifier]（即与 -map 相同的语法）。如果 stream_specifier 匹配多个 流，则使用第一个。对于多视图视频，流说明符 后面可以跟视图说明符，其语法请参见 -map 选项的文档。
  • 要连接回环解码器，请使用 [dec:dec_idx]，其中 dec_idx 是 要连接到给定输入的回环解码器的索引。对于多视图 视频，解码器索引后面可以跟视图说明符，其语法请参见 -map 选项的文档。
  • 要连接来自另一个复杂滤镜图的输出，请使用它的链路标签。例如 以下示例： 
    ffmpeg -i input.mkv \
  -filter_complex '[0:v]scale=size=hd1080,split=outputs=2[for_enc][orig_scaled]' \
  -c:v libx264 -map '[for_enc]' output.mkv \
  -dec 0:0 \
  -filter_complex '[dec:0][orig_scaled]hstack[stacked]' \
  -map '[stacked]' -c:v ffv1 comparison.mkv

    读取一个输入视频，并

    • （第 2 行）使用一个具有一个输入和两个输出的复杂滤镜图， 将视频缩放到 1920x1080，并把结果复制到两个 输出；
    • （第 3 行）使用 libx264 编码其中一路缩放后的输出，并将结果写入 output.mkv；
    • （第 4 行）使用回环解码器解码这个已编码的流；
    • （第 5 行）将回环解码器的输出（即 经 libx264 编码的视频）与缩放后的原始输入并排放在一起；
    • （第 6 行）合并后的视频随后被无损编码并写入 comparison.mkv。

    请注意，这两个滤镜图无法合并为一个，因为那样 转码流水线中就会出现环（滤镜图的输出送到 编码，从那里再到解码，然后又回到同一个图），而这样的环 是不允许的。

未加标签的输入会被连接到匹配类型中第一个未使用的 输入流。

输出链路标签通过 -map 来引用。未加标签的输出会被 添加到第一个输出文件。

请注意，使用此选项时可以只使用 lavfi 源，而不需要 普通的输入文件。

例如，要把图像叠加到视频上 

ffmpeg -i video.mkv -i image.png -filter_complex '[0:v][1:v]overlay[out]' -map
'[out]' out.mkv

这里 [0:v] 指的是第一个输入文件中的第一个视频流， 它被链接到 overlay 滤镜的第一个（主）输入。同样地， 第二个输入中的第一个视频流被链接到 overlay 的第二个 （叠加）输入。

假设每个输入文件中只有一个视频流，我们可以省略输入 标签，因此上面的写法等价于 

ffmpeg -i video.mkv -i image.png -filter_complex 'overlay[out]' -map
'[out]' out.mkv

此外，我们还可以省略输出标签，此时来自滤镜 图的单个输出会被自动添加到输出文件，因此我们可以简单地写成 

ffmpeg -i video.mkv -i image.png -filter_complex 'overlay' out.mkv

作为一个特例，你可以将位图字幕流用作输入：它 会被转换为与文件中最大视频尺寸相同的视频， 如果文件中没有视频则为 720x576。请注意，这是一个 实验性的临时方案。一旦 libavfilter 对字幕有了 适当的支持，它就会被移除。

例如，要把字幕硬编码到以 MPEG-TS 格式存储的 DVB-T 录像之上，并将字幕延迟 1 秒： 

ffmpeg -i input.ts -filter_complex \
  '[#0x2ef] setpts=PTS+1/TB [sub] ; [#0x2d0] [sub] overlay' \
  -sn -map '#0x2dc' output.mkv

（0x2d0、0x2dc 和 0x2ef 分别是视频、 音频和字幕流的 MPEG-TS PID；用 0:0、0:3 和 0:7 也可以）

要使用 lavfi 的 color 源生成 5 秒纯红色视频： 

ffmpeg -filter_complex 'color=c=red' -t 5 out.mkv
-filter_complex_threads nb_threads (全局)

定义用于处理 filter_complex 图的线程数量。 与 filter_threads 类似，但仅用于 -filter_complex 图。 默认值为可用 CPU 的数量。

-lavfi filtergraph (全局)

定义一个复杂滤镜图，即具有任意数量输入和/或 输出的滤镜图。等价于 -filter_complex。

-accurate_seek (输入)

此选项启用或禁用在使用 -ss 选项时对输入文件进行精确定位。它默认启用，因此转码 时定位是精确的。使用 -noaccurate_seek 可以禁用它，这在 例如拷贝部分流并对其他流转码时可能有用。

-seek_timestamp (输入)

此选项启用或禁用在使用 -ss 选项时按 时间戳对输入文件进行定位。它默认禁用。如果启用， 传给 -ss 选项的参数会被视为实际的时间戳，而不会 按文件的起始时间做偏移。这只对不 从时间戳 0 开始的文件有影响，例如传输流。

-thread_queue_size size (输入/输出)

对于输入，此选项设置从文件或设备读取时排队包的 最大数量。对于低延迟／高速率的直播流，包 如果未被及时读取就可能被丢弃；设置此值可以 强制 ffmpeg 使用单独的输入线程，并在包到达时 立即读取。默认情况下，ffmpeg 仅在指定了多个输入时才这样做。

对于输出，此选项指定可以排队到每个复用线程的 最大包数量。

-sdp_file file (全局)

将输出流的 sdp 信息打印到 file。 这允许在至少有一个输出不是 rtp 流时转储 sdp 信息。（要求至少有一种输出格式为 rtp）。

-discard (输入)

允许丢弃特定的流或流中的帧。 任何输入流都可以使用取值 all 被完全丢弃，而 对流中帧的选择性丢弃发生在解复用器 处，并且并非所有解复用器都支持。

none

不丢弃任何帧。

default

默认值，不丢弃任何帧。

noref

丢弃所有非参考帧。

bidir

丢弃所有双向帧。

nokey

丢弃除关键帧之外的所有帧。

all

丢弃所有帧。

-abort_on flags (全局)

在各种条件下停止并中止。可用的标志如下：

empty_output

没有包被传递给复用器，输出为空。

empty_output_stream

某些输出流中没有包被传递给复用器。

-max_error_rate (全局)

设置所有输入中解码帧失败的比例阈值，一旦超过该阈值， ffmpeg 将返回退出码 69。超过此阈值不会终止 处理。取值范围是 0 到 1 之间的浮点数。默认值为 2/3。

-xerror (全局)

出错时停止并退出

-max_muxing_queue_size packets (输出,每条流)

在转码音频和/或视频流时，ffmpeg 不会开始向输出写入， 直到每条此类流都有一个包为止。在等待这一情况发生期间，其他流的包会被缓冲。 此选项设置……的大小 此缓冲区以包为单位的大小，针对匹配的输出流。

此选项的默认值对大多数用途而言应该足够大，因此只有 在你确定确实需要时才应调整此选项。

-muxing_queue_data_threshold bytes (输出,每条流)

这是一个最小阈值，在未达到该阈值之前，复用队列的大小不计入 考虑范围。默认值为每条流 50 兆字节，并且基于 传递给复用器的包的总大小。

-auto_conversion_filters (全局)

启用后会在所有滤镜图中自动插入格式转换滤镜， 包括由 -vf、-af、 -filter_complex 和 -lavfi 定义的滤镜图。如果滤镜格式协商 需要转换，则滤镜的初始化将失败。 仍然可以通过在滤镜图中插入相应的转换 滤镜（scale、aresample）来完成转换。 默认开启，若要显式禁用它，需要指定 -noauto_conversion_filters。

-bits_per_raw_sample[:stream_specifier] value (输出,每条流)

声明给定输出流中每个原始采样的位数为 value。注意此选项设置的是提供给 编码器/复用器的信息，它不会改变流以符合该值。设置 与流属性不匹配的值可能导致编码失败 或产生无效的输出文件。

-stats_enc_pre[:stream_specifier] path (输出,每条流)
-stats_enc_post[:stream_specifier] path (输出,每条流)
-stats_mux_pre[:stream_specifier] path (输出,每条流)

将匹配流的逐帧编码信息写入由 path 指定的文件中。

-stats_enc_pre 在原始视频或音频帧被送去编码之前写入其信息， 而 -stats_enc_post 则写入 从编码器接收到的已编码包的信息。 -stats_mux_pre 写入即将 发送给复用器的包的信息。每个帧或包都会在指定的 文件中产生一行。该行的格式由 -stats_enc_pre_fmt / -stats_enc_post_fmt / -stats_mux_pre_fmt 控制。

当多条流的统计数据写入同一个文件时，对应于不同流的 各行会交错排列。这种交错的确切顺序 未作规定，也不保证在程序的 不同次调用之间保持稳定，即使使用相同的选项也是如此。

-stats_enc_pre_fmt[:stream_specifier] format_spec (输出,每条流)
-stats_enc_post_fmt[:stream_specifier] format_spec (输出,每条流)
-stats_mux_pre_fmt[:stream_specifier] format_spec (输出,每条流)

指定用 -stats_enc_pre / -stats_enc_post / -stats_mux_pre 写入的行的格式。

format_spec 是一个字符串，可以包含形如 {fmt} 的指令。format_spec 使用反斜杠转义 — 分别用 \{、\} 和 \\ 将字面量 {、} 或 \ 写入输出。

用 fmt 给出的指令可以是以下之一：

fidx

输出文件的索引。

sidx

文件中输出流的索引。

n

帧编号。编码前：到目前为止发送给编码器的帧数。 编码后：到目前为止从编码器接收到的包数。 复用：到目前为止为此流提交给复用器的包数。

ni

输入帧编号。与此输出帧或包相对应的输入帧 （即由解码器输出的帧）的索引。不可用时为 -1。

tb

此帧/包的时间戳所采用的时间基，表示为有理数 num/den。注意编码器和复用器可能使用不同的时间基。

tbi

ptsi 的时间基，表示为有理数 num/den。当 ptsi 可用时可用，否则为 0/1。

pts

帧或包的显示时间戳，为整数。应 将其乘以时间基以计算显示时间。

ptsi

输入帧（参见 ni）的显示时间戳，为整数。应 将其乘以 tbi 以计算显示时间。不可用时 输出为 (2^63 - 1 = 9223372036854775807)。

t

帧或包的显示时间，为十进制数。等于 pts 乘以 tb。

ti

输入帧（参见 ni）的显示时间，为十进制数。等于 ptsi 乘以 tbi。不可用时输出为 inf。

dts (包)

包的解码时间戳，为整数。应将其乘以 时间基以计算显示时间。

dt (包)

帧或包的解码时间，为十进制数。等于 dts 乘以 tb。

sn (帧,音频)

到目前为止发送给编码器的音频采样数。

samp (帧,音频)

帧中的音频采样数。

size (包)

已编码包的大小，以字节为单位。

br (包)

当前码率，以比特每秒为单位。

abr (包)

到目前为止整条流的平均码率，以比特每秒为单位；如果此时 无法确定，则为 -1。

key (包)

如果包包含关键帧则为字符 ’K’，否则为字符 ’N’。

标记为 包 的指令只能与 -stats_enc_post_fmt 和 -stats_mux_pre_fmt 一起使用。

标记为 帧 的指令只能与 -stats_enc_pre_fmt 一起使用。

标记为 音频 的指令只能用于音频流。

默认格式字符串为：

pre-encoding

{fidx} {sidx} {n} {t}

post-encoding

{fidx} {sidx} {n} {t}

5.12 预设文件# TOC

预设文件包含一系列 option=value 键值对， 每行一个，用于指定在命令行上书写起来会很 不便的一系列选项。以井号（’#’）开头的行会被忽略，用于 提供注释。示例可查看 FFmpeg 源码树中的 presets 目录。

预设文件有两种类型：ffpreset 文件和 avpreset 文件。

5.12.1 ffpreset 文件# TOC

ffpreset 文件通过 vpre、apre、 spre 和 fpre 选项来指定。fpre 选项接受 预设文件的文件名而非预设名称作为输入，可用于 任何类型的编解码器。对于 vpre、apre 和 spre 选项，预设文件中指定的选项会被 应用到当前选中的、与预设选项同类型的编解码器上。

传给 vpre、apre 和 spre 预设选项的参数，按以下规则确定要使用的 预设文件：

首先，ffmpeg 会在 $FFMPEG_DATADIR（如果设置了）、 $HOME/.ffmpeg、配置时定义的 datadir（通常是 PREFIX/share/ffmpeg），以及 win32 下可执行文件旁的 ffpresets 文件夹中查找名为 arg.ffpreset 的文件， 按上述顺序进行。例如，如果参数是 libvpx-1080p，它会 查找文件 libvpx-1080p.ffpreset。

如果找不到这样的文件，ffmpeg 会在上述 目录中查找名为 codec_name-arg.ffpreset 的文件， 其中 codec_name 是要应用该预设文件选项的编解码器的 名称。例如，如果你用 -vcodec libvpx 选择视频编解码器 并使用 -vpre 1080p，那么它会查找文件 libvpx-1080p.ffpreset。

5.12.2 avpreset 文件# TOC

avpreset 文件通过 pre 选项来指定。它们的工作方式与 ffpreset 文件类似，但只允许使用编码器特定的选项。因此，用于指定 编码器的 option=value 键值对不能使用。

当指定了 pre 选项时，ffmpeg 会在 $AVCONV_DATADIR（如果设置了）、 $HOME/.avconv，以及配置时定义的 datadir（通常是 PREFIX/share/ffmpeg）中查找后缀为 .avpreset 的文件， 按上述顺序进行。

首先，ffmpeg 会在上述目录中查找名为 codec_name-arg.avpreset 的文件， 其中 codec_name 是要应用该预设文件选项的编解码器的 名称。例如，如果你用 -vcodec libvpx 选择视频编解码器 并使用 -pre 1080p，那么它会查找文件 libvpx-1080p.avpreset。

如果找不到这样的文件，ffmpeg 会在同样的目录中 查找名为 arg.avpreset 的文件。

6 示例# TOC

6.1 视频与音频采集# TOC

如果指定了输入格式和设备，ffmpeg 就能直接采集视频 和音频。 

ffmpeg -f oss -i /dev/dsp -f video4linux2 -i /dev/video0 /tmp/out.mpg

或者改用 ALSA 音频源（单声道输入，声卡 id 为 1）而不是 OSS： 

ffmpeg -f alsa -ac 1 -i hw:1 -f video4linux2 -i /dev/video0 /tmp/out.mpg

请注意，在启动 ffmpeg 之前，你必须先用任意 TV 观看程序（例如 Gerd Knorr 的 xawtv）激活正确的视频源和频道。你还 必须用标准混音器正确设置音频录制电平。

6.2 X11 采集# TOC

用 ffmpeg 采集 X11 显示画面的方式如下 

ffmpeg -f x11grab -video_size cif -framerate 25 -i :0.0 /tmp/out.mpg

0.0 是你的 X11 服务器的 display.screen 编号，与 DISPLAY 环境变量相同。 

ffmpeg -f x11grab -video_size cif -framerate 25 -i :0.0+10,20 /tmp/out.mpg

0.0 是你的 X11 服务器的 display.screen 编号，与 DISPLAY 环境 变量相同。10 是采集的 x 偏移，20 是 y 偏移。

6.3 视频与音频文件格式转换# TOC

任何受支持的文件格式和协议都可以作为 ffmpeg 的输入：

示例：

  • 你可以把 YUV 文件用作输入： 
    ffmpeg -i /tmp/test%d.Y /tmp/out.mpg

    它会使用以下文件： 

    /tmp/test0.Y, /tmp/test0.U, /tmp/test0.V,
/tmp/test1.Y, /tmp/test1.U, /tmp/test1.V, etc...

    Y 文件的分辨率是 U 和 V 文件的两倍。它们是 不带文件头的裸文件。它们可以由所有像样的视频 解码器生成。如果 ffmpeg 无法猜出图像尺寸，你必须用 -s 选项 指定它。

  • 你可以从裸 YUV420P 文件输入： 
    ffmpeg -i /tmp/test.yuv /tmp/out.avi

    test.yuv 是一个包含裸 YUV 平面数据的文件。每一帧由 Y 平面，以及垂直和水平分辨率都减半的 U、V 平面组成。

  • 你可以输出到裸 YUV420P 文件： 
    ffmpeg -i mydivx.avi hugefile.yuv
  • 你可以设置多个输入文件和输出文件： 
    ffmpeg -i /tmp/a.wav -s 640x480 -i /tmp/a.yuv /tmp/a.mpg

    把音频文件 a.wav 和裸 YUV 视频文件 a.yuv 转换为 MPEG 文件 a.mpg。

  • 你也可以同时进行音频和视频转换： 
    ffmpeg -i /tmp/a.wav -ar 22050 /tmp/a.mp2

    把 a.wav 转换为采样率 22050 Hz 的 MPEG 音频。

  • 你可以同时编码为多种格式，并定义从输入流到输出流的 映射关系： 
    ffmpeg -i /tmp/a.wav -map 0:a -b:a 64k /tmp/a.mp2 -map 0:a -b:a 128k /tmp/b.mp2

    把 a.wav 转换为 64 kbits 的 a.mp2 和 128 kbits 的 b.mp2。’-map file:index’ 按照输出流的定义顺序，指定每条输出流 使用哪个输入流。

  • 你可以转码已解密的 VOB： 
    ffmpeg -i snatch_1.vob -f avi -c:v mpeg4 -b:v 800k -g 300 -bf 2 -c:a libmp3lame -b:a 128k snatch.avi

    这是一个典型的 DVD 抓取示例；输入是 VOB 文件， 输出是带有 MPEG-4 视频和 MP3 音频的 AVI 文件。注意，在这个 命令中我们使用了 B 帧，因此该 MPEG-4 流与 DivX5 兼容，且 GOP 大小为 300，这意味着对于 29.97fps 的输入视频，每 10 秒有一个 帧内帧。此外，音频流采用 MP3 编码，因此你需要 通过向 configure 传递 --enable-libmp3lame 来启用 LAME 支持。 这种映射对 DVD 转码特别有用， 可以获取所需的音频语言。

    注意：要查看受支持的输入格式，请使用 ffmpeg -demuxers。

  • 你可以从视频中提取图像，或者用许多图像创建一个视频：

    从视频中提取图像： 

    ffmpeg -i foo.avi -r 1 -s WxH -f image2 foo-%03d.jpeg

    这会从视频中每秒提取一帧视频帧，并把它们 输出到名为 foo-001.jpeg、foo-002.jpeg 等 文件中。图像会被缩放以适合新的 WxH 值。

    如果你只想提取有限数量的帧，可以把 上面的命令与 -frames:v 或 -t 选项结合使用， 或者与 -ss 结合使用以从某个时间点开始提取。

    用许多图像创建一个视频： 

    ffmpeg -f image2 -framerate 12 -i foo-%03d.jpeg -s WxH foo.avi

    语法 foo-%03d.jpeg 表示使用一个由三位数字 组成的、以零填充的十进制数来表示序列 编号。这与 C 语言 printf 函数支持的语法相同，但 只有接受普通整数的格式才适用。

    导入图像序列时，-i 也支持在内部展开 类似 shell 的通配符模式（globbing），方法是选择 image2 特有的 -pattern_type glob 选项。

    例如，要用匹配通配符模式 foo-*.jpeg 的文件名 创建视频： 

    ffmpeg -f image2 -pattern_type glob -framerate 12 -i 'foo-*.jpeg' -s WxH foo.avi
  • 你可以在输出中放入多条同类型的流： 
    ffmpeg -i test1.avi -i test2.avi -map 1:1 -map 1:0 -map 0:1 -map 0:0 -c copy -y test12.nut

    得到的输出文件 test12.nut 会按相反顺序包含来自 输入文件的前四条流。

  • 要强制输出 CBR 视频： 
    ffmpeg -i myfile.avi -b 4000k -minrate 4000k -maxrate 4000k -bufsize 1835k out.m2v
  • lmin、lmax、mblmin 和 mblmax 这四个选项使用 ’lambda’ 单位， 但你可以使用 QP2LAMBDA 常量轻松地从 ’q’ 单位转换过来： 
    ffmpeg -i src.ext -lmax 21*QP2LAMBDA dst.ext
