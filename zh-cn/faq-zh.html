1 通用问题# TOC

1.1 为什么 FFmpeg 不支持 [xyz] 功能？# TOC

因为还没有人承担这项任务。FFmpeg 的开发是由 对各个开发者而言重要的任务所驱动的。 如果有某项功能对你很重要，让它得以实现的最好办法 就是自己承担这项任务，或者资助一位开发者。

1.2 FFmpeg 不支持编解码器 XXX。你们能加入一个 Windows DLL 加载器来支持它吗？# TOC

不。Windows DLL 不可移植、体积臃肿而且常常很慢。 此外，FFmpeg 力求原生支持所有编解码器。 DLL 加载器无助于这一目标。

1.3 尽管 ffmpeg 似乎支持这种格式，我却无法读取该文件。# TOC

即使 ffmpeg 能读取该容器格式，它也可能不支持其中的全部编解码器。 请查阅 ffmpeg 文档中列出的 受支持编解码器列表。

1.4 Windows 支持哪些编解码器？# TOC

Windows 对 MPEG 这类标准格式的支持并不好，除非你 安装一些额外的编解码器。

以下视频编解码器列表在大多数 Windows 系统上应当可以工作：

msmpeg4v2

.avi/.asf

msmpeg4

仅 .asf

wmv1

仅 .asf

wmv2

仅 .asf

mpeg4

仅当你安装了 ffdshow 或 Xvid 之类的 MPEG-4 编解码器时。

mpeg1video

仅 .mpg

注意，在 Windows 中 ASF 文件常常带有 .wmv 或 .wma 扩展名。还应当 提到，Microsoft 声称对 ASF 格式拥有专利，并可能起诉 或威胁那些使用非 Microsoft 软件创建 ASF 文件的用户。强烈 建议尽可能避免使用 ASF。

以下音频编解码器列表在大多数 Windows 系统上应当可以工作：

adpcm_ima_wav
adpcm_ms
pcm_s16le

总是可用

libmp3lame

如果安装了 LAME 之类的 MP3 编解码器。

2 编译# TOC

2.1 error: can't find a register in class 'GENERAL_REGS' while reloading 'asm'# TOC

这是 gcc 的一个缺陷。不要向我们报告。请改为向 gcc 开发者报告。请注意，我们不会为 gcc 的缺陷添加变通方案。

另请注意，（部分）gcc 开发者认为这不是缺陷，或者 不是他们应当修复的缺陷： https://gcc.gnu.org/bugzilla/show_bug.cgi?id=11203. 不过，他们中的一些人并不了解不可判定问题 与 NP 难问题之间的区别……

2.2 我已用发行版的包管理器安装了这个库。为什么 configure 看不到它？# TOC

发行版通常把库拆分成多个软件包。主包 包含使用该库运行程序所需的文件。开发包 包含使用该库构建程序所需的文件。有时 文档和/或数据也在单独的软件包中。

要构建 FFmpeg，你需要安装开发包。它通常 叫作 libfoo-dev 或 libfoo-devel。你可以在 构建完成后把它移除，但务必保留主包。

2.3 如何让 pkg-config 找到我的库？# TOC

在你的库附近某处，有一个 .pc 文件（也可能有多个）， 位于 pkgconfig 目录中。你需要设置环境变量，把 pkg-config 指向这些文件。

如果你需要向 pkg-config 的搜索列表添加目录 （典型场景：库是单独安装的），就把它添加到 $PKG_CONFIG_PATH： 

export PKG_CONFIG_PATH=/opt/x264/lib/pkgconfig:/opt/opus/lib/pkgconfig

如果你需要替换 pkg-config 的搜索列表 （典型场景：交叉编译），就在 $PKG_CONFIG_LIBDIR 中设置它： 

export PKG_CONFIG_LIBDIR=/home/me/cross/usr/lib/pkgconfig:/home/me/cross/usr/local/lib/pkgconfig

如果你需要了解该库的内部依赖（典型用法：静态 链接），就给 pkg-config 加上 --static 选项： 

./configure --pkg-config-flags=--static

2.4 交叉编译时如何使用 pkg-config？# TOC

最好的办法是在你的交叉编译环境中 安装 pkg-config。它会自动使用交叉编译的库。

你也可以使用宿主机环境中的 pkg-config，方法是 向 configure 显式指定 --pkg-config=pkg-config。 在这种情况下，你必须用 PKG_CONFIG_LIBDIR 把 pkg-config 指向正确的目录，如上一项所述。

作为折中方案，你可以在交叉编译 环境中放一个脚本，该脚本在设置了 PKG_CONFIG_LIBDIR 的情况下 调用宿主机的 pkg-config。该脚本可以像这样： 

#!/bin/sh
PKG_CONFIG_LIBDIR=/path/to/cross/lib/pkgconfig
export PKG_CONFIG_LIBDIR
exec /usr/bin/pkg-config "$@"

3 用法# TOC

3.1 ffmpeg 不工作；出了什么问题？# TOC

构建之前，先在 ffmpeg 源码目录中执行一次 make distclean。 如果这没有帮助，请参阅 (https://ffmpeg.org/bugreports.html).

3.2 如何把单张图片编码成影片？# TOC

首先，把你的图片重命名为遵循数字序列的名称。 例如 img1.jpg、img2.jpg、img3.jpg…… 然后你可以运行： 

ffmpeg -f image2 -i img%d.jpg /tmp/a.mpg

注意，‘%d’ 会被图片编号替换。

img%03d.jpg 表示序列 img001.jpg、img002.jpg 等。

使用 -start_number 选项来为序列声明一个起始编号。 如果你的序列不是从 img001.jpg 开始， 但仍按数字顺序排列，这很有用。下面的示例 将从 img100.jpg 开始： 

ffmpeg -f image2 -start_number 100 -i img%d.jpg /tmp/a.mpg

如果你有大量图片需要重命名，可以使用 下面的命令来减轻负担。该命令使用 bourne shell 语法，把当前目录中所有匹配 *jpg 的文件 以 img001.jpg、img002.jpg 这样的序列 符号链接到 /tmp 目录，依此类推。 

x=1; for i in *jpg; do counter=$(printf %03d $x); ln -s "$i" /tmp/img"$counter".jpg; x=$(($x+1)); done

如果你想按修改时间最早的排在前面来排序，请用 $(ls -r -t *jpg) 替换 *jpg。

然后运行： 

ffmpeg -f image2 -i /tmp/img%03d.jpg /tmp/a.mpg

同样的逻辑适用于 ffmpeg 能读取的任何图像格式。

你也可以用 cat 把图片通过管道传给 ffmpeg： 

cat *.jpg | ffmpeg -f image2pipe -c:v mjpeg -i - output.mpg

3.3 如何把影片编码成单张图片？# TOC

使用： 

ffmpeg -i movie.mpg movie%d.jpg

作为输入使用的 movie.mpg 会被转换为 movie1.jpg、movie2.jpg 等等……

除了依赖文件格式的自动识别之外，你也可以使用

-c:v ppm
-c:v png
-c:v mjpeg

来强制指定编码。

把它应用到上一个示例： 

ffmpeg -i movie.mpg -f image2 -c:v mjpeg menu%d.jpg

注意，并不存在 "jpeg" 编解码器。请改用 "mjpeg"。

3.4 为什么多线程 MPEG* 编码会出现轻微的画质下降？# TOC

对于多线程 MPEG* 编码，编码后的条带必须相互独立， 否则线程 n 实际上必须等待 n-1 完成，所以 出现轻微的画质下降是很合乎逻辑的。这不是缺陷。

3.5 如何从标准输入读取或向标准输出写入？# TOC

使用 - 作为文件名。

3.6 -f jpeg 无法工作。# TOC

试试 ’-f image2 test%d.jpg’。

3.7 为什么我无法更改帧率？# TOC

某些编解码器（如 MPEG-1/2）只允许少量固定帧率。 请通过 -c:v 命令行选项选择其他编解码器。

3.8 如何用 ffmpeg 编码 Xvid 或 DivX 视频？# TOC

Xvid 和 DivX（4 版及更高版本）都是 ISO MPEG-4 标准的实现（注意，还有许多其他编码格式也使用这同一 标准）。因此，请使用 ’-c:v mpeg4’ 按这些格式进行编码。 存储在 MPEG-4 编码文件中的默认 fourcc 将是 ’FMP4’。如果你想 使用不同的 fourcc，请使用 ’-vtag’ 选项。例如，’-vtag xvid’ 将 强制把 fourcc ’xvid’ 存储为视频 fourcc，而不是 默认值。

3.9 编码高质量 MPEG-4 有哪些好参数？# TOC

’-mbd rd -flags +mv4+aic -trellis 2 -cmp 2 -subcmp 2 -g 300 -pass 1/2’， 可以尝试：’-bf 2’、’-mpv_flags qp_rd’、’-mpv_flags mv0’、’-mpv_flags skip_rd’。

3.10 编码高质量 MPEG-1/MPEG-2 有哪些好参数？# TOC

’-mbd rd -trellis 2 -cmp 2 -subcmp 2 -g 100 -pass 1/2’ 但要注意，’-g 100’ 在某些解码器上可能会引发问题。 可以尝试：’-bf 2’、’-mpv_flags qp_rd’、’-mpv_flags mv0’、’-mpv_flags skip_rd’。

3.11 隔行视频用 ffmpeg 编码后看起来非常糟，出了什么问题？# TOC

对于隔行素材，你应当使用 ’-flags +ilme+ildct’，也许还要加上 ’-flags +alt’， 如果结果看起来一团糟，可以试试 ’-top 0/1’。

3.12 如何读取 DirectShow 文件？# TOC

如果你为 Windows 构建 FFmpeg 时使用了 ./configure --enable-avisynth， 并且你的 AviSynth+ 安装提供了 DirectShowSource，那么你 就可以把 DirectShow 能够读取的任何文件用作输入。

只需创建一个内容为下面这一行的 "input.avs" 文本文件…… 

DirectShowSource("C:\path to your file\yourfile.asf")

……然后把该文本文件传给 ffmpeg： 

ffmpeg -i input.avs

关于 AviSynth 的任何其他帮助，请访问 AviSynth 主页。

3.13 如何连接视频文件？# TOC

“拼接”视频文件的含义相当模糊。下面的列表解释了 各种不同的“拼接”，并指出它们在 FFmpeg 中是如何处理的。拼接视频文件可能意味着：

  • 把它们一个接一个地排列：这称为对它们进行串联 （简称 concat），相关说明见 本 FAQ 的这一节。
  • 把它们放进同一个文件，让用户在不同的 版本之间选择（例如：不同的音频语言）：这称为把它们 复用在一起（简称 mux），只需 用多个 -i 选项调用 ffmpeg 即可完成。
  • 对于音频，把所有声道放进单个流（例如：把两个 单声道流合并为一个立体声流）：这有时称为把它们 合并，可以使用 amerge 滤镜来完成。
  • 对于音频，把一个叠加在另一个之上播放：这称为把它们混音， 可以先把它们合并成单个流，然后 使用 pan 滤镜按需混合 各声道。
  • 对于视频，把两者一起显示、并排显示或把一个叠在另一个的一部分之上； 这可以使用 overlay 视频滤镜来完成。

3.14 如何拼接视频文件？# TOC

根据具体情况，有几种解决方案。

3.14.1 使用 concat 滤镜拼接# TOC

FFmpeg 有一个专为此设计的 concat 滤镜， 文档中附有示例。如果你需要重新编码，推荐使用这一做法。

3.14.2 使用 concat 解复用器拼接# TOC

FFmpeg 有一个 concat 解复用器，当你想避免重新编码 而你的格式不支持文件级串联时，可以使用它。

3.14.3 使用 concat 协议拼接（文件级）# TOC

FFmpeg 有一个专为此设计的 concat 协议， 文档中附有示例。

少数多媒体容器（MPEG-1、MPEG-2 PS、DV）允许仅通过串联 包含它们的文件来串联视频。

因此，你可以先把多媒体文件转码为这些特殊格式，然后 使用朴素无华的 cat 命令（或 Windows 下同样朴素的 copy），最后再转码回你 所选用的格式，从而完成串联。 

ffmpeg -i input1.avi -qscale:v 1 intermediate1.mpg
ffmpeg -i input2.avi -qscale:v 1 intermediate2.mpg
cat intermediate1.mpg intermediate2.mpg > intermediate_all.mpg
ffmpeg -i intermediate_all.mpg -qscale:v 2 output.avi

此外，你还可以使用 concat 协议代替 cat 或 copy，这样可以避免创建可能非常巨大的中间文件。 

ffmpeg -i input1.avi -qscale:v 1 intermediate1.mpg
ffmpeg -i input2.avi -qscale:v 1 intermediate2.mpg
ffmpeg -i concat:"intermediate1.mpg|intermediate2.mpg" -c copy intermediate_all.mpg
ffmpeg -i intermediate_all.mpg -qscale:v 2 output.avi

请注意，你可能需要对字符 "|" 进行转义，它对许多 shell 来说都是特殊字符。

另一种选择是使用命名管道，前提是你的平台支持它： 

mkfifo intermediate1.mpg
mkfifo intermediate2.mpg
ffmpeg -i input1.avi -qscale:v 1 -y intermediate1.mpg < /dev/null &
ffmpeg -i input2.avi -qscale:v 1 -y intermediate2.mpg < /dev/null &
cat intermediate1.mpg intermediate2.mpg |\
ffmpeg -f mpeg -i - -c:v mpeg4 -c:a libmp3lame output.avi

3.14.4 使用原始音频和视频拼接# TOC

类似地，yuv4mpegpipe 格式以及原始视频、原始音频编解码器也 允许串联，而且转码这一步几乎是无损的。 使用多个 yuv4mpegpipe 时，需要从除第一个流之外的 所有流中丢弃第一行。这可以通过管道传送给 tail 来实现，如下所示。请注意，通过管道传送给 tail 时，你 必须使用命令分组 { ;}，才能正确地放到后台。

例如，假设我们想把两个 FLV 文件串联成一个 output.flv 文件： 

mkfifo temp1.a
mkfifo temp1.v
mkfifo temp2.a
mkfifo temp2.v
mkfifo all.a
mkfifo all.v
ffmpeg -i input1.flv -vn -f u16le -c:a pcm_s16le -ac 2 -ar 44100 - > temp1.a < /dev/null &
ffmpeg -i input2.flv -vn -f u16le -c:a pcm_s16le -ac 2 -ar 44100 - > temp2.a < /dev/null &
ffmpeg -i input1.flv -an -f yuv4mpegpipe - > temp1.v < /dev/null &
{ ffmpeg -i input2.flv -an -f yuv4mpegpipe - < /dev/null | tail -n +2 > temp2.v ; } &
cat temp1.a temp2.a > all.a &
cat temp1.v temp2.v > all.v &
ffmpeg -f u16le -c:a pcm_s16le -ac 2 -ar 44100 -i all.a \
       -f yuv4mpegpipe -i all.v \
       -y output.flv
rm temp[12].[av] all.[av]

3.15 使用 -f lavfi 时，音频无缘无故变成单声道。# TOC

使用 -dumpgraph - 来准确查明声道布局是在 哪里丢失的。

很可能是在 auto-inserted aresample 处。试着理解 为什么在那个位置需要这个转换滤镜。

输出之前就是一个很可能的位置，因为 -f lavfi 目前 仅支持 packed S16。

然后在滤镜图中显式插入正确的 aformat， 并指定确切的格式。 

aformat=sample_fmts=s16:channel_layouts=stereo

3.16 为什么 FFmpeg 看不到我 VOB 文件中的字幕？# TOC

VOB 和少数其他格式没有能够描述 文件中全部内容的全局头。相反，应用程序应当扫描 文件来查看其中包含什么。由于 VOB 文件往往很大，所以只 扫描开头部分。如果字幕恰好只出现在文件较后的位置， 它们一开始就不会被检测到。

包括 ffmpeg 命令行工具在内的一些应用程序，只能 处理初始扫描期间检测到的流；那些 稍后才检测到的流会被忽略。

初始扫描的大小由两个选项控制：probesize （默认 ~5 Mo）和 analyzeduration（默认 5,000,000 µs = 5 s）。要 让字幕流被检测到，这两个值都必须足够大。

3.17 为什么移除了 ffmpeg 的 -sameq 选项？改用什么呢？# TOC

-sameq 选项的意思是 "same quantizer"，只在 非常有限的情况下才有意义。遗憾的是，很多人把它误认为 "same quality"，并在它并不合理的场合使用它：它大体上 能达到预期的可见效果，但实现它的方式非常低效 。

每个编码器都有自己的一套选项来设定质量与大小的平衡， 请使用你所用编码器的选项，把质量级别设定到 对你来说可以接受的程度。最常用于此的选项是 -qscale 和 -qmax，但你应当仔细阅读 你所选编码器的文档。

3.18 我有一个被拉伸的视频，为什么缩放无法修复它？# TOC

许多视频编解码器和格式都能存储视频的宽高比： 它要么是整幅图像宽与高之比（DAR，显示宽高比）， 要么是单个像素宽与高之比（SAR，样本宽高 比）。例如，分辨率为 640×350 的 EGA 屏幕具有 4:3 的 DAR 和 35:48 的 SAR。

大多数静止图像处理都使用方形像素，即 1:1 SAR，但许多 视频标准，尤其是模拟到数字过渡时期的标准，使用 非方形像素。

FFmpeg 中的大多数处理滤镜都会处理宽高比，以避免 拉伸图像：裁剪会调整 DAR 以保持 SAR 不变， 缩放会调整 SAR 以保持 DAR 不变。

如果你想拉伸或“反拉伸”图像，就需要用 以下滤镜来覆盖该信息： setdar or setsar filters.

不要忘记仔细检查原始视频，以确认 这种拉伸是来自图像本身，还是来自宽高比信息。

例如，要修复编码糟糕的 EGA 采集，可以使用以下命令， 要么用第一条放大到方形像素，要么用第二条设置 正确的宽高比，要么用第三条避免转码（可能因格式 / 编解码器 / 播放器 / 月相的不同而无效）： 

ffmpeg -i ega_screen.nut -vf scale=640:480,setsar=1 ega_screen_scaled.nut
ffmpeg -i ega_screen.nut -vf setdar=4/3 ega_screen_anamorphic.nut
ffmpeg -i ega_screen.nut -aspect 4/3 -c copy ega_screen_overridden.nut

3.19 如何把 ffmpeg 作为后台任务运行？# TOC

ffmpeg 在执行操作时通常会检查控制台输入，以接收诸如 "q" 用于停止 和 "?" 用于提供帮助之类的输入。ffmpeg 没有办法 检测自己何时作为后台任务运行。 当它检查控制台输入时，可能导致在后台运行 ffmpeg 的 进程被挂起。

要阻止这些输入检查，让 ffmpeg 能作为后台任务运行， 请在 ffmpeg 调用中使用 -nostdin 选项， 这在以下两种情况下都有效：无论你是在 shell 中运行 ffmpeg，还是通过操作系统 API 在 其独立进程中调用 ffmpeg。

另一种做法是，当你在 shell 中运行 ffmpeg 时，可以把 标准输入重定向到 /dev/null（在 Linux 和 macOS 上） 或 NUL（在 Windows 上）。这个重定向既可以在 ffmpeg 调用处执行，也可以在调用 ffmpeg 的 shell 脚本中执行。

例如： 

ffmpeg -nostdin -i INPUT OUTPUT

或者（在 Linux、macOS 以及其他类 UNIX shell 上）： 

ffmpeg -i INPUT OUTPUT </dev/null

或者（在 Windows 上）： 

ffmpeg -i INPUT OUTPUT <NUL

3.20 如何防止 ffmpeg 因类似 suspended (tty output) 的消息而挂起？# TOC

如果你在后台运行 ffmpeg，可能会发现它的进程挂起了。 可能会出现类似 suspended (tty output) 的消息。问题在于如何 防止该进程被挂起。

例如： 

% ffmpeg -i INPUT OUTPUT &> ~/tmp/log.txt &
[1] 93352
%
[1]  + suspended (tty output)  ffmpeg -i INPUT OUTPUT &>

尽管消息中说的是 "tty output"，但这里的问题在于 ffmpeg 在运行时通常会检查控制台输入。操作系统 检测到这一点，就会挂起该进程，直到你能把它切换到 前台并处理它。

解决办法是使用正确的技巧，告诉 ffmpeg 不要读取 控制台输入。你可以使用 -nostdin 选项， 或者用 < /dev/null 重定向标准输入。 请参见 FAQ 如何把 ffmpeg 作为后台任务运行？ 了解详情。

4.2 你们能支持我的 C 编译器 XXX 吗？# TOC

视情况而定。如果你的编译器符合 C11，那么支持它的补丁很可能会受到欢迎， 前提是这些补丁不会用与编译器相关的 #ifdef 污染源代码。

4.3 是否支持 Microsoft Visual C++？# TOC

支持。请参见 FFmpeg 文档中的 Microsoft Visual C++ 一节。

4.4 你们能添加对 automake、libtool 或 autoconf 的支持吗？# TOC

不能。这些工具过于臃肿，而且会使构建变得复杂。

4.5 为什么不用面向对象的 C++ 重写 FFmpeg？# TOC

FFmpeg 已经以高度模块化的方式组织，不需要 用正式的对象语言重写。此外，许多开发者 更青睐纯 C；它对他们来说很好用。关于此问题的更多论述， 请阅读 "Programming Religion"。

4.6 为什么 ffmpeg 程序没有调试符号？# TOC

构建过程会创建 ffmpeg_g、ffplay_g 等，它们 包含完整的调试信息。这些二进制文件会被剥离以创建 ffmpeg、ffplay 等。如果你需要调试信息，请使用 *_g 版本。

4.7 我不喜欢 LGPL，我可以改为按 GPL 贡献代码吗？# TOC

可以，只要该代码是可选的，并且能够轻松、干净地置于 #if CONFIG_GPL 之下而不会破坏任何东西。因此，举例来说，新增一个编解码器 或滤镜以 GPL 发布是可以的，而对 LGPL 代码的缺陷修复则不行。

4.8 我在自己的 C 应用程序中使用 FFmpeg，但链接器报错说缺少来自库本身的符号。# TOC

FFmpeg 默认构建静态库。在静态库中，依赖关系 不会被处理。这带来两个后果。第一，你必须按依赖顺序指定 库：-lavdevice 必须位于 -lavformat 之前，而 -lavutil 必须位于其它所有库之后，等等。 第二，FFmpeg 中使用的外部库也必须一并指定。

获取按依赖顺序排列的完整所需库列表的一个简便方法是 使用 pkg-config。 

c99 -o program program.c $(pkg-config --cflags --libs libavformat libavcodec)

请参见 doc/example/Makefile 和 doc/example/pc-uninstalled 以了解更多细节。

4.9 我在自己的 C++ 应用程序中使用 FFmpeg，但链接器报错说缺少一些似乎可用的符号。# TOC

FFmpeg 是一个纯 C 项目，因此要在你的 C++ 应用程序中使用这些库， 你需要明确声明你使用的是 C 库。要做到这一点，可以 用 extern "C" 包住 FFmpeg 的头文件包含。

参见 http://www.parashift.com/c++-faq-lite/mixing-c-and-cpp.html#faq-32.3

4.10 我的文件在内存中／一个不同于 *open/*read/ libc 的 API，如何配合 libavformat 使用它？# TOC

你必须使用 avio_alloc_context 创建一个自定义的 AVIOContext， 参见 FFmpeg 中的 libavformat/aviobuf.c 以及 MPlayer 或 MPlayer2 源码中的 libmpdemux/demux_lavf.c。

4.11 关于 ffv1、msmpeg4、asv1、4xm 的文档在哪里？# TOC

参见 https://www.ffmpeg.org/~michael/

4.12 如何把 H.263-RTP（以及 RTP 中的其他编解码器）喂给 libavcodec？# TOC

尽管 RTP 因为面向网络而显得特殊，但它像其它任何容器一样， 必须先 解复用 RTP，然后再把载荷送入 libavcodec。 在这种特定情况下，请参阅 RFC 4629 了解应当如何操作。

4.13 AVStream.r_frame_rate 是错误的，它比帧率大得多。# TOC

r_frame_rate 不是平均帧率，它是能够准确表示所有 时间戳的最小帧率。所以，不，如果它大于平均值， 它也没有错！ 例如，如果你有 25 和 30 fps 混合的内容，那么 r_frame_rate 将是 150（它是最小公倍数）。 如果你需要的是平均帧率，请参见 AVStream.avg_frame_rate。

4.14 为什么 make fate 没有运行所有测试？# TOC

请确保你拥有 fate-suite 样本，并且 SAMPLES Make 变量 或 FATE_SAMPLES 环境变量或 --samples configure 选项已设置为正确的路径。

4.15 为什么 make fate 找不到样本？# TOC

你的样本路径中是否恰好含有一个 ~ 字符，用来表示 主目录？该值在某些使用方式下 shell 无法将其展开， 从而导致 FATE 找不到文件。只需把 ~ 替换为完整路径。
