1 描述# TOC

本文档介绍由 libavcodec 库提供的比特流滤波器。

比特流滤波器作用于已编码的流数据，并在不进行 解码的情况下完成比特流层面的修改。

2 比特流滤波器# TOC

配置 FFmpeg 构建时，所有受支持的比特流 滤波器默认均已启用。你可以使用 配置选项 --list-bsfs 列出全部可用的比特流滤波器。

你可以使用配置选项 --disable-bsfs 禁用所有比特流滤波器，并使用 选项 --enable-bsf=BSF 选择性地启用任意比特流 滤波器，也可以使用选项 --disable-bsf=BSF 禁用某个特定的比特流滤波器。

ff* 工具的选项 -bsfs 会显示你的构建版本中 所包含的全部受支持的比特流滤波器列表。

ff* 工具的 -bsf 选项按流生效，它接受一个 以逗号分隔的滤镜列表，其参数跟在滤镜 名之后，以 ’=’ 分隔。 

ffmpeg -i INPUT -c:v copy -bsf:v filter1[=opt1=str1:opt2=str2][,filter2] OUTPUT

下面介绍当前可用的比特流滤波器 及其参数（如果有）。

2.1 aac_adtstoasc# TOC

将 MPEG-2/4 AAC ADTS 转换为 MPEG-4 Audio Specific Configuration 比特流。

此滤波器从 MPEG-2/4 ADTS 头创建 MPEG-4 AudioSpecificConfig，并移除 ADTS 头。

例如，当把 AAC 流从原始 ADTS AAC 或 MPEG-TS 容器复制到 MP4A-LATM、 FLV 文件， 或 MOV/MP4 文件以及 3GP 或 M4A 等相关格式时，需要使用此滤波器。请注意， 对于 MP4A-LATM 和 MOV/MP4 及相关格式，它会被自动插入。

2.2 av1_metadata# TOC

修改嵌入 AV1 流中的元数据。

td

在流的所有时间单元中插入或移除时间定界符 OBU。

‘insert’

在每个尚无 TD 的 TU 开头插入一个 TD。

‘remove’

从每个含 TD 的 TU 开头移除该 TD。

color_primaries
transfer_characteristics
matrix_coefficients

设置流中的颜色描述字段（参见 AV1 第 6.4.2 节）。

color_range

设置流中的颜色范围（参见 AV1 第 6.4.2 节；注意 此值无法为使用 BT.709 原色、sRGB 传输 特性和恒等（RGB）矩阵系数的流设置）。

‘tv’

有限范围。

‘pc’

全范围。

chroma_sample_position

设置流中的色度采样位置（参见 AV1 第 6.4.2 节）。 此项仅可对 4:2:0 流设置。

‘vertical’

左侧位置（与 MPEG-2 和 H.264 中的默认值一致）。

‘colocated’

左上位置。

tick_rate

设置 tick 速率（time_scale / num_units_in_display_tick），即 序列头中时间信息的 tick 速率。

num_ticks_per_picture

设置每幅图像中的 tick 数量，以表明该流 具有固定帧率。若未同时设置 tick_rate，则此项被忽略。

delete_padding

删除 Padding OBU。

2.3 chomp# TOC

移除数据包末尾的零填充。

2.4 dca_core# TOC

从 DCA/DTS 流中提取核心，丢弃 DTS-HD 等扩展。

2.5 dovi_rpu# TOC

操作 HEVC/AV1 比特流中的 Dolby Vision 元数据，并可选地启用 元数据压缩。

strip

若启用，则从流中剥离全部 Dolby Vision 元数据（配置记录 + RPU 数据 块）。

compression

启用哪个压缩级别。

‘none’

不进行元数据压缩。

‘limited’

受限的元数据压缩方案。应当与大多数设备兼容。 这是默认值。

‘extended’

扩展的元数据压缩。设备不要求支持此项。请注意， 此级别在 libavcodec 中目前的行为与 ‘limited’ 相同。

2.6 dovi_split# TOC

拆分 Dolby Vision Profile 7 多层 HEVC 比特流。Profile 7 将 增强层 HEVC 比特流以交织方式承载在基础层访问单元内部， 封装于类型 63（UNSPEC63）的用户未指定 NAL 单元中，并将 RPU 元数据 作为同级的类型 62（UNSPEC62）用户未指定 NAL。

mode

在输出比特流中保留哪些 Dolby Vision 组件。

‘bl’

仅基础层：丢弃所有 UNSPEC63（EL）和所有 UNSPEC62（RPU）。 输出为不含 Dolby Vision 标记的普通 HEVC 流。这是 默认值。

‘bl_rpu’

保留 RPU NAL 的基础层。

‘el’

仅增强层：对每个 UNSPEC63 NAL，剥离两字节的外层 NAL 头并输出内部载荷。结果是一条独立的 HEVC 比特流。 UNSPEC62（RPU）被丢弃。

‘el_rpu’

原样保留 RPU NAL 的增强层。与 ‘el’ 相同，但 UNSPEC62 RPU NAL 也会与解包后的 EL NAL 一同输出。

2.7 dump_extra# TOC

将 extradata 添加到经过滤波的数据包开头，但当 这些数据包已经正好以准备添加的 extradata 开头时 除外。

freq

附加参数指定哪些数据包应被滤波。 它接受以下取值：

‘k’
‘keyframe’

为所有关键帧数据包添加 extradata

‘e’
‘all’

为所有数据包添加 extradata

若未指定，则假定为 ‘k’。

例如，下面的 ffmpeg 命令在由 libx264 编码器 生成的 H.264 数据包中强制使用全局 头（从而禁用逐个数据包头），但通过将 存储在 extradata 中的头添加到关键帧数据包来修正它们： 

ffmpeg -i INPUT -map 0 -flags:v +global_header -c:v libx264 -bsf:v dump_extra out.ts

2.8 dv_error_marker# TOC

DV 中被标记为损坏的块会被替换为指定颜色的块。

color

用于替换损坏块的颜色

sta

一个 16 位掩码，用于指定 16 种可能的错误状态值中哪些 应被彩色块替换。0xFFFE 是默认值，它会替换所有非 0 的错误状态值。

‘ok’

无错误，不隐藏

‘err’

有错误，不隐藏

‘res’

保留

‘notok’

错误或隐藏

‘notres’

非保留

‘Aa, Ba, Ca, Ab, Bb, Cb, A, B, C, a, b, erri, erru’

特定的错误状态码

参见第 44-46 页或第 5.5 节： http://web.archive.org/web/20060927044735/http://www.smpte.org/smpte_store/standards/pdf/s314m.pdf

2.9 eac3_core# TOC

从 E-AC-3 流中提取核心部分，丢弃额外的声道。

2.10 eia608_to_smpte436m# TOC

将 EIA_608 流转换为 SMPTE_436M_ANC 数据流，并把隐藏式字幕封装到 CTA-708 CDP VANC 数据包中。

line_number

选择生成的 VANC 数据包应使用哪个行号。通常需要第 9 行（默认值）或第 11 行。

wrapping_type

选择 SMPTE 436M 封装类型，默认为 ‘vanc_frame’。 它接受以下取值：

‘vanc_frame’

VANC 帧（隔行帧或分段逐行帧）

‘vanc_field_1’
‘vanc_field_2’
‘vanc_progressive_frame’
sample_coding

选择 SMPTE 436M 采样编码，默认为 ‘8bit_luma’。 它接受以下取值：

‘8bit_luma’

8 位分量亮度采样

‘8bit_color_diff’

8 位分量色差采样

‘8bit_luma_and_color_diff’

8 位分量亮度和色差采样

‘10bit_luma’

10 位分量亮度采样

‘10bit_color_diff’

10 位分量色差采样

‘10bit_luma_and_color_diff’

10 位分量亮度和色差采样

‘8bit_luma_parity_error’

带奇偶校验错误的 8 位分量亮度采样

‘8bit_color_diff_parity_error’

带奇偶校验错误的 8 位分量色差采样

‘8bit_luma_and_color_diff_parity_error’

带奇偶校验错误的 8 位分量亮度和色差采样

initial_cdp_sequence_cntr

CDP 的 16 位无符号整数 cdp_hdr_sequence_cntr 和 cdp_ftr_sequence_cntr 字段的初始值。默认为 0。

cdp_frame_rate

设置 CDP 的 cdp_frame_rate 字段。这实际上不会改变数据流的时序，只会改变生成的 CDP 数据包中插入该字段的值。默认为 ‘30000/1001’。

2.11 extract_extradata# TOC

提取带内附加数据。

某些编解码器允许将长期头（例如 MPEG-2 序列头， 或 H.264/HEVC 的 (VPS/)SPS/PPS）以“带内”方式（即作为 包含已编码帧的比特流的一部分）或“带外”方式（例如在 容器层面）传输。后一种形式在 FFmpeg 术语中称为“extradata”。

该比特流滤波器检测带内头，并将其作为 附加数据提供。

remove

启用该选项后，长期头会在提取之后从 比特流中移除。

2.12 filter_units# TOC

从流中移除类型属于或不属于给定集合的单元。

pass_types

要通过的单元类型或单元类型范围的列表，同时移除 所有其它单元。它指定为以 ’|’ 分隔的单元类型值列表， 或以 ’-’ 表示的值范围。

remove_types

与 pass_types 相同，区别在于给定集合中的单元会被 移除，而所有其它单元会被通过。

pass_types 和 remove_types 使用的类型对应于 H.264、HEVC 和 H.266 中的 NAL 单元类型 (nal_unit_type)（参见 H.264 和 HEVC 规范的表 7-1，或 H.266 规范的表 5），对应 JPEG 的标记值（不含 0xFF 前缀），对于 MPEG-2 则对应不含 起始码前缀的起始码（即 0x000001 之后的字节）。 对于 VP8 和 VP9，每个单元的类型都为零。

此变换不会改变附加数据，但请注意，如果流中 包含内联参数集，那么将它们移除后输出可能 无法使用。

例如，要从 H.264 流中移除所有非 VCL 的 NAL 单元： 

ffmpeg -i INPUT -c:v copy -bsf:v 'filter_units=pass_types=1-5' OUTPUT

要从 H.265 流中移除所有 AUD、SEI 和填充： 

ffmpeg -i INPUT -c:v copy -bsf:v 'filter_units=remove_types=35|38-40' OUTPUT

要从 MPEG-2 流中移除所有用户数据，包括隐藏式字幕： 

ffmpeg -i INPUT -c:v copy -bsf:v 'filter_units=remove_types=178' OUTPUT

要从 H264 流中移除所有 SEI，包括隐藏式字幕： 

ffmpeg -i INPUT -c:v copy -bsf:v 'filter_units=remove_types=6' OUTPUT

要从 HEVC 流中移除所有前缀和后缀 SEI，包括隐藏式字幕和动态 HDR： 

ffmpeg -i INPUT -c:v copy -bsf:v 'filter_units=remove_types=39|40' OUTPUT

2.13 hapqa_extract# TOC

从 HAPQA 文件中提取 Rgb 或 Alpha 部分，不重新压缩，从而创建一个 HAPQ 或 HAPAlphaOnly 文件。

texture

指定要保留的纹理。

color
alpha

将 HAPQA 转换为 HAPQ 

ffmpeg -i hapqa_inputfile.mov -c copy -bsf:v hapqa_extract=texture=color -tag:v HapY -metadata:s:v:0 encoder="HAPQ" hapq_file.mov

将 HAPQA 转换为 HAPAlphaOnly 

ffmpeg -i hapqa_inputfile.mov -c copy -bsf:v hapqa_extract=texture=alpha -tag:v HapA -metadata:s:v:0 encoder="HAPAlpha Only" hapalphaonly_file.mov

2.14 h264_metadata# TOC

修改嵌入在 H.264 流中的元数据。

aud

在流的所有访问单元中插入或移除 AUD NAL 单元。

‘pass’
‘insert’
‘remove’

默认为 pass。

sample_aspect_ratio

在 VUI 参数中设置流的样本宽高比。 参见 H.264 表 E-1。

overscan_appropriate_flag

设置该流是否适合使用过扫描 进行显示（参见 H.264 第 E.2.1 节）。

video_format
video_full_range_flag

设置流中的视频格式（参见 H.264 第 E.2.1 节和 表 E-2）。

colour_primaries
transfer_characteristics
matrix_coefficients

设置流中的色彩描述（参见 H.264 第 E.2.1 节 以及表 E-3、E-4 和 E-5）。

chroma_sample_loc_type

设置流中的色度采样位置（参见 H.264 第 E.2.1 节和图 E-1）。

tick_rate

在 VUI 参数中设置时钟频率 (time_scale / num_units_in_tick)。 它是在流中可表示的最小时间单位， 在很多情况下代表流的场率 （帧率的两倍）。

fixed_frame_rate_flag

设置该流的帧率是否固定 —— 这通常表示 帧率恰好是时钟频率的一半，但确切的 含义取决于隔行方式和图像结构（参见 H.264 第 E.2.1 节和表 E-6）。

zero_new_constraint_set_flags

将 SPS 中的 constraint_set4_flag 和 constraint_set5_flag 置零。这些 比特在上一版 H.264 规范中是保留位，因此 某些硬件解码器要求它们为零。将其置零后的 结果仍然是有效的比特流。

crop_left
crop_right
crop_top
crop_bottom

设置 SPS 中的帧裁剪偏移。如果流已被裁剪， 这些值将替换当前的值。

这些字段以像素为单位设置。请注意，如果色度经过 二次采样或流为隔行，某些尺寸可能无法表示 （参见 H.264 第 7.4.2.1.1 节）。

sei_user_data

以 SEI 未注册用户数据的形式插入一个字符串。该参数必须 为 UUID+string 形式，其中 UUID 为十六进制数字， 可以用连字符分隔，而字符串可以是任意内容。

例如，‘086f3693-b7b3-4f2c-9653-21492feee5b8+hello’ 会 插入与给定 UUID 关联的字符串 “hello”。

delete_filler

同时删除填充 NAL 单元和填充 SEI 消息。

display_orientation

插入、提取或移除显示方向 SEI 消息。 语法和语义参见 H.264 第 D.1.27 和 D.2.27 节。

‘pass’
‘insert’
‘remove’
‘extract’

默认为 pass。

插入模式与 rotate 和 flip 选项配合使用。 在插入或移除模式下，任何已存在的显示方向消息都会被移除。 提取模式会将显示矩阵作为附属数据附加到数据包上。

rotate

设置显示方向 SEI 中的旋转（逆时针角度，单位为度）。 范围为 -360 到 +360。默认为 NaN。

flip

设置显示方向 SEI 中的翻转。

‘horizontal’
‘vertical’

默认不设置。

level

设置 SPS 中的级别。请参考 H.264 第 A.3 节以及表 A-1 到 A-5。

该参数必须是级别名称（例如 ‘4.2’）、 level_idc 值（例如 ‘42’），或特殊名称 ‘auto’ 表示该比特流滤波器应尝试根据 输入流的属性猜测级别。

2.15 h264_mp4toannexb# TOC

将 H.264 比特流从长度前缀模式转换为起始码 前缀模式（如 ITU-T H.264 规范的附录 B 中所定义）。

某些流式格式要求如此，典型的 是 MPEG-2 传输流格式（复用器 mpegts）。

例如，要用 ffmpeg 将包含 H.264 流的 MP4 文件重新复用为 mpegts 格式，可以使用以下命令： 

ffmpeg -i INPUT.mp4 -codec copy -bsf:v h264_mp4toannexb OUTPUT.ts

请注意，对于 MPEG-TS（复用器 mpegts）和原始 H.264（复用器 h264）输出格式，该比特流滤波器会被自动插入。

2.16 h264_redundant_pps# TOC

这会对某些包含冗余 PPS 的蓝光 BDMV H264 流 应用特定的修正。这些 PPS 修改了流中无关的 参数，从而干扰需要正确 附加数据的其它变换。

受影响的流上使用的编码器会在整个流中添加额外的 PPS， 并改变初始 QP 以及是否启用加权预测。将流复制到 全局头容器后这会造成问题，因为起始的 PPS 不适用于流的其余部分。例如，一个副作用 是在新的 PPS 出现之前，定位会返回 乱码输出。

该比特流滤波器会移除多余的 PPS，并重写条带头， 使流在全局头中使用单个起始 PPS， 从而解决该问题。

2.17 hevc_metadata# TOC

修改嵌入在 HEVC 流中的元数据。

aud

在流的所有访问单元中插入或删除 AUD NAL 单元。

‘insert’
‘remove’
sample_aspect_ratio

在流的 VUI 参数中设置样本宽高比。

video_format
video_full_range_flag

设置流中的视频格式（参见 H.265 第 E.3.1 节和 表 E.2）。

colour_primaries
transfer_characteristics
matrix_coefficients

设置流中的色彩描述（参见 H.265 第 E.3.1 节 以及表 E.3、E.4 和 E.5）。

chroma_sample_loc_type

设置流中的色度样本位置（参见 H.265 第 E.3.1 节和图 E.1）。

tick_rate

在 VPS 和 VUI 参数中设置 tick 速率（time_scale / num_units_in_tick）。与 num_ticks_poc_diff_one 结合使用，可以 在流中设置恒定的帧率。注意，当该流位于容器中时，它很可能 会被容器参数覆盖。

num_ticks_poc_diff_one

在 VPS 和 VUI 中设置 poc_proportional_to_timing_flag，并使用该值 设置 num_ticks_poc_diff_one_minus1（参见 H.265 第 7.4.3.1 节和 E.3.1 节）。如果未同时设置 tick_rate，则忽略该项。

crop_left
crop_right
crop_top
crop_bottom

在 SPS 中设置符合性窗口裁剪偏移。如果该流已被裁剪， 这些值将替换当前值。

这些字段以像素为单位设置。注意，如果色度是子采样的， 某些尺寸可能无法表示（H.265 第 7.4.3.2.1 节）。

width
height

设置裁剪后的宽度和高度。

level

在 VPS 和 SPS 中设置级别。参见 H.265 第 A.4 节以及表 A.6 和 A.7。

该参数必须是级别名称（例如 ‘5.1’）、一个 general_level_idc 值（例如级别 5.1 对应 ‘153’）， 或者是特殊名称 ‘auto’，表示该滤波器应 尝试根据输入流的属性推测级别。

2.18 hevc_mp4toannexb# TOC

将 HEVC/H.265 比特流从长度前缀模式转换为起始码 前缀模式（如 ITU-T H.265 规范附录 B 中所定义）。

某些流式格式需要这样做，典型的是 MPEG-2 传输流格式（复用器 mpegts）。

例如，要用 ffmpeg 将包含 HEVC 流的 MP4 文件重新复用为 mpegts 格式，可以使用以下命令： 

ffmpeg -i INPUT.mp4 -codec copy -bsf:v hevc_mp4toannexb OUTPUT.ts

请注意，对于 MPEG-TS（复用器 mpegts）以及原始 HEVC/H.265（复用器 h265 或 hevc）输出格式，该滤波器会被自动插入。

2.19 imxdump# TOC

2.20 mjpeg2jpeg# TOC

将 MJPEG/AVI1 数据包转换为完整的 JPEG/JFIF 数据包。

MJPEG 是一种视频编解码器，其中每个视频帧本质上都是一幅 JPEG 图像。可以无损地提取各个帧， 例如通过 

ffmpeg -i ../some_mjpeg.avi -c:v copy frames_%d.jpg

遗憾的是，这些数据块是不完整的 JPEG 图像，因为 它们缺少解码所需的 DHT 段。以下引自 http://www.digitalpreservation.gov/formats/fdd/fdd000063.shtml：

Avery Lee 于 2001 年在 rec.video.desktop 新闻组中写道， 他说："MJPEG，或者至少是具有 MJPG fourcc 的 AVI 中的 MJPEG，是带有固定 – 且*省略*的 – 霍夫曼表的受限 JPEG。该 JPEG 必须是 YCbCr 色彩空间，必须是 4:2:2， 并且必须使用基本霍夫曼编码，而不是算术编码或 渐进编码。……你确实可以提取 MJPEG 帧并 用普通 JPEG 解码器解码它们，但必须在它们前面加上 DHT 段，否则解码器将无从 得知如何解压这些数据。所需的确切表在 OpenDML 规范中给出。"

该比特流滤波器会修补从 MJPEG 流中提取的帧的头部 （这些帧携带 AVI1 头部 ID 且缺少 DHT 段），以 生成完全合格的 JPEG 图像。 

ffmpeg -i mjpeg-movie.avi -c:v copy -bsf:v mjpeg2jpeg frame_%d.jpg
exiftran -i -9 frame*.jpg
ffmpeg -i frame_%d.jpg -c:v copy rotated.avi

2.24 mpeg4_unpack_bframes# TOC

解包 DivX 风格的打包 B 帧。

DivX 风格的打包 B 帧不是合法的 MPEG-4，它只是针对 有缺陷的 Video for Windows 子系统的一种变通方案。 它们占用更多空间，可能导致轻微的 AV 同步问题，解码时需要 更多 CPU 算力（除非播放器有某种已解码图像队列 来补偿 2,0,2,0 的每数据包帧模式），并且如果被复制到 mp4 或 mpeg-ps/ts 之类的标准容器中就会带来麻烦， 因为 MPEG-4 解码器可能无法解码它们， 它们不是合法的 MPEG-4。

例如，要用 ffmpeg 修复包含带 DivX 风格打包 B 帧的 MPEG-4 流的 AVI 文件，可以使用以下命令： 

ffmpeg -i INPUT.avi -codec copy -bsf:v mpeg4_unpack_bframes OUTPUT.avi

2.25 noise# TOC

破坏数据包的内容，或直接丢弃数据包而不破坏 容器。可用于模糊测试或测试错误恢复/掩盖能力。

参数：

amount

接受一个表达式，其逐数据包的求值结果决定该数据包中字节被修改的 频率。小于 0 的值会导致频率可变。 默认值为 0，表示不做任何修改。但是，如果既未指定 amount 也未指定 drop， amount 将被设为 -1。可接受的变量见下文。

drop

接受一个逐数据包求值的表达式，其值决定该数据包是否被丢弃。 求值为正值会导致该数据包被丢弃。求值为负值 会导致其被丢弃的概率可变，大致与该值的大小成反比， 默认值为 0，表示不丢弃。可接受的变量见下文。

dropamount

接受一个非负整数，它赋予一个可变的丢弃概率，大致与该值 成反比。默认值为 0，表示不丢弃。保留该选项是为了向后 兼容，它等价于将 drop 设为大小相同的负值， 即 dropamount=4 等同于 drop=-4。如果同时指定了 drop，则忽略该项。

amount 和 drop 都接受包含以下变量的表达式：

‘n’

数据包的索引，从零开始。

‘tb’

数据包时间戳的时基。

‘pts’

数据包的显示时间戳。

‘dts’

数据包的解码时间戳。

‘nopts’

表示 AV_NOPTS_VALUE 的常量。

‘startpts’

流中出现的第一个非 AV_NOPTS_VALUE 的 PTS。

‘startdts’

流中出现的第一个非 AV_NOPTS_VALUE 的 DTS。

‘duration’
‘d’

数据包时长，以时基为单位。

‘pos’

数据包在输入中的位置；未知或未设置时可能为 -1。

‘size’

数据包大小，以字节为单位。

‘key’

数据包是否被标记为关键帧。

‘state’

一个伪随机整数，主要派生自数据包负载的内容。

2.25.1 示例# TOC

对每个字节都施加修改，但不丢弃任何数据包。 

ffmpeg -i INPUT -c copy -bsf noise=1 output.mkv

丢弃时间戳 30s 之后所有未标记为关键帧的视频数据包，但不要 修改其余的任何数据包。 

ffmpeg -i INPUT -c copy -bsf:v noise=drop='gt(pts*tb\,30)*not(key)' output.mkv

每 10 秒丢弃一秒音频，并对其余部分添加一些随机噪声。 

ffmpeg -i INPUT -c copy -bsf:a noise=amount=-1:drop='between(mod(pts*tb\,10)\,9\,10)' output.mkv

2.27 pcm_rechunk# TOC

将 PCM 音频重新打包为每个数据包固定数量的样本，或固定的 每秒数据包速率。这类似于 asetnsamples 音频 滤镜，但它作用于音频数据包而非音频帧。

nb_out_samples, n

设置每个输出音频数据包的样本数量。该数值指的是 每个声道的样本数量。默认值为 1024。

pad, p

如果设为 1，滤波器会用静音填充最后一个音频数据包，使其 包含与之前的数据包相同数量的样本（或大致相同数量的样本， 参见 frame_rate）。默认值为 1。

frame_rate, r

该选项使滤波器每秒输出固定数量的数据包，而不是每个数据包 固定数量的样本。如果音频采样率不能被帧率 整除，那么样本数量将不是恒定的，而是 会有轻微变化，以便每个数据包尽可能接近帧 边界开始。使用该选项优先于 nb_out_samples。

使用 frame_rate 选项，可以为 NTSC 帧率生成 众所周知的 48kHz 音频 1602-1601-1602-1601-1602 模式。 

ffmpeg -f lavfi -i sine=r=48000:d=1 -c pcm_s16le -bsf pcm_rechunk=r=30000/1001 -f framecrc -
