1 描述# TOC

本文档介绍 libavformat 库提供的 输入和输出协议。

2 协议选项# TOC

libavformat 库提供了一些通用的全局选项， 可在所有协议上设置。此外，每个协议还可能支持 所谓的私有选项，这些选项是该组件特有的。

选项可以通过在 FFmpeg 工具中指定 -option value 来设置， 也可以通过显式设置 AVFormatContext 选项中的值，或使用 libavutil/opt.h API 供编程使用。

受支持的选项列表如下：

protocol_whitelist list (input)

设置一个以 "," 分隔的允许协议列表。"ALL" 匹配所有协议。以 "-" 为前缀的协议将被禁用。 默认情况下允许所有协议，但被另一个协议使用的协议 （嵌套协议）则被限制在各协议专属的子集内。

3 协议# TOC

协议是 FFmpeg 中经过配置的元素，用于访问 需要使用特定协议的资源。

配置 FFmpeg 构建时，所有受支持的协议 默认都已启用。你可以使用 配置选项 "–list-protocols" 列出所有可用的协议。

你可以使用配置选项 "–disable-protocols" 禁用所有协议，并使用 选项 "–enable-protocol=PROTOCOL" 有选择地启用某个协议，或者使用选项 "–disable-protocol=PROTOCOL" 禁用 某个特定的协议。

ff* 工具的 "-protocols" 选项会显示 受支持协议的列表。

所有协议都接受以下选项：

rw_timeout

等待（网络）读写操作完成的最长时间， 以微秒为单位。

下面介绍当前可用的协议。

3.1 amqp# TOC

Advanced Message Queueing Protocol (AMQP) 0-9-1 版本是一种基于代理的 发布-订阅通信协议。

要支持 AMQP，FFmpeg 必须使用 –enable-librabbitmq 编译。此外还必须运行一个独立的 AMQP 代理。一个开源 AMQP 代理的示例是 RabbitMQ。

启动代理后，FFmpeg 客户端可以使用以下命令 向代理流式传输数据： 

ffmpeg -re -i input -f mpegts amqp://[[user]:[password]@]hostname[:port][/vhost]

其中 hostname 和 port（默认值为 5672）是代理的地址。 客户端还可以设置用户名/密码用于认证。这两个 字段的默认值都是 "guest"。代理上的虚拟主机名可以用 vhost 设置。其 默认值是 "/"。

多个订阅者可以使用以下命令从代理进行流式传输： 

ffplay amqp://[[user]:[password]@]hostname[:port][/vhost]

在 RabbitMQ 中，发布到代理的所有数据都会流经一个特定的 exchange， 每个订阅客户端都有一个分配的队列/缓冲区。当数据包到达 某个 exchange 时，它会根据 exchange 和 routing_key 字段被复制到客户端的队列中。

支持以下选项：

exchange

设置要在代理上使用的 exchange。RabbitMQ 有几个预定义的 exchange："amq.direct" 是默认 exchange，发布者和 订阅者必须具有匹配的 routing_key；"amq.fanout" 等同于 广播操作（即数据被转发到 fanout exchange 上的所有队列， 与 routing_key 无关）；而 "amq.topic" 类似于 "amq.direct"，但允许更复杂的模式匹配（请参阅 RabbitMQ 文档）。

routing_key

设置路由键。默认值是 "amqp"。路由键用于 "amq.direct" 和 "amq.topic" exchange，以决定数据包是否写入 订阅者的队列。

pkt_size

发送到代理/从代理接收的每个数据包的最大大小。默认值为 131072。 最小值为 4096，最大值可以是任意大的值（只要能由 int 表示）。在 接收数据包时，这会设置 FFmpeg 中的内部缓冲区大小。它应当 等于或大于发布到代理的数据包大小。否则 接收到的消息可能被截断，从而导致解码错误。

connection_timeout

与代理建立初始连接时的超时时间，以秒为单位。其 默认值是 rw_timeout，如果未设置 rw_timeout 则为 5 秒。

delivery_mode mode

设置发送到代理的每条消息的投递模式。 接受以下取值：

‘persistent’

投递模式设置为 "persistent"（2）。这是默认值。 根据代理的配置，消息可能会被写入代理的磁盘。

‘non-persistent’

投递模式设置为 "non-persistent"（1）。 除非代理面临内存压力，否则消息将保留在代理的 内存中。

3.2 async# TOC

输入流的异步数据填充包装器。

在后台线程中填充数据，使 I/O 操作与解复用线程解耦。 

async:URL
async:http://host/resource
async:cache:http://host/resource

3.3 bluray# TOC

读取 BluRay 播放列表。

接受的选项为：

angle

BluRay 角度

chapter

起始章节（1...N）

playlist

要读取的播放列表（BDMV/PLAYLIST/?????.mpls）

示例：

读取挂载到 /mnt/bluray 的 BluRay 中最长的播放列表： 

bluray:/mnt/bluray

读取挂载到 /mnt/bluray 的 BluRay 中播放列表 4 的角度 2，从第 2 章开始： 

-playlist 4 -angle 2 -chapter 2 bluray:/mnt/bluray

3.4 cache# TOC

输入流的缓存包装器。

将输入流缓存到临时文件。这为直播流带来了定位能力。

接受的选项为：

read_ahead_limit

在不支持定位时可以预读的字节数。范围为 -1 到 INT_MAX。 -1 表示无限制。默认值为 65536。

URL 语法为 

cache:URL

3.5 concat# TOC

物理拼接协议。

按顺序从多个资源读取和定位，就像它们是 一个单独的资源一样。

此协议接受的 URL 语法为： 

concat:URL1|URL2|...|URLN

其中 URL1、URL2、...、URLN 是要 拼接的资源的 url，其中每一个都可能指定不同的 协议。

例如，要使用 ffplay 读取一系列文件 split1.mpeg、 split2.mpeg、split3.mpeg，请使用 以下命令： 

ffplay concat:split1.mpeg\|split2.mpeg\|split3.mpeg

请注意，你可能需要转义字符 "|"，因为它在 许多 shell 中具有特殊含义。

3.6 concatf# TOC

使用以换行符分隔的资源列表的物理拼接 协议。

按顺序从多个资源读取和定位，就像它们是 同一个资源一样。

该协议接受的 URL 语法为： 

concatf:URL

其中 URL 是包含以换行符分隔的待拼接资源 列表的 URL，每个资源都可以指定不同的协议。特殊字符必须用 反斜杠或单引号转义。参见 ffmpeg-utils(1) 手册中的 "引号与转义" 一节。

例如，要使用 ffplay 读取在文件 split.txt 中分行列出的文件序列 split1.mpeg、 split2.mpeg、split3.mpeg，请使用以下命令： 

ffplay concatf:split.txt

其中 split.txt 包含以下几行： 

split1.mpeg
split2.mpeg
split3.mpeg

3.9 fd# TOC

文件描述符访问协议。

接受的语法为： 

fd: -fd file_descriptor

如果未指定 fd，默认情况下将使用 stdout 文件描述符 进行写入，使用 stdin 进行读取。与 pipe 协议不同，fd 协议在对应 普通文件时支持定位。出于安全考虑，fd 协议不支持通过 URL 传递文件描述符。

该协议接受以下选项：

blocksize

以字节为单位设置 I/O 操作的最大块大小。默认值为 INT_MAX，这会导致不限制所请求的块大小。 将此值设置得适当小可以改善用户终止请求的响应时间， 在数据传输缓慢时这一点很有价值。

fd

设置文件描述符。

3.10 file# TOC

文件访问协议。

从文件读取或写入文件。

文件 URL 可以采用以下形式： 

file:filename

其中 filename 是要读取的文件的路径。

没有协议前缀的 URL 将被视为文件 URL。取决于构建方式，看起来 像是以盘符开头的 Windows 路径的 URL 也将被视为文件 URL （在类 unix 系统的构建中 通常并非如此）。

例如，要使用 ffmpeg 从文件 input.mpeg 读取，请使用以下命令： 

ffmpeg -i file:input.mpeg output.mpeg

该协议接受以下选项：

truncate

如果设置为 1，则在写入时截断已存在的文件。值为 0 会禁止 截断。默认值为 1。

blocksize

以字节为单位设置 I/O 操作的最大块大小。默认值为 INT_MAX，这会导致不限制所请求的块大小。 将此值设置得适当小可以改善用户终止请求的响应时间， 对于慢速介质上的文件这一点很有价值。

follow

如果设置为 1，协议将在文件末尾重试读取，从而 允许读取仍在写入的文件。为了使该过程终止，你需要 使用 rw_timeout 选项，或者使用中断回调（对于 API 用户）。设置此选项还会忽略文件系统报告的 文件大小。

seekable

控制是否对文件声明可定位性。0 表示不可定位，-1 表示自动（普通文件可定位，命名管道不可定位）。

许多解复用器对可定位和不可定位资源的处理方式不同， 覆盖此设置可能会加快某些文件的打开速度，但代价是 失去某些功能（例如精确定位）。

pkt_size

设置用于文件 I/O 的最大数据包大小。较小的值可以减少 内存占用。较大的值可以提高吞吐量，尤其是在网络 文件系统上。

对于读取，如果显式设置，它将覆盖默认的内部缓冲区 大小（32 KB）并限制每次操作读取的最大数据量。

对于写入，它设置每次写入操作的大小。普通文件的 默认值为 256 KB，其它情况为 32 KB。

3.11 ftp# TOC

FTP（文件传输协议）。

使用 FTP 协议从远程资源读取或向其写入。

需要遵循以下语法。 

ftp://[user[:password]@]server[:port]/path/to/remote/resource.mpeg

该协议接受以下选项。

timeout

以微秒为单位设置底层低层操作所使用的套接字 I/O 操作的 超时时间。默认设置为 -1，这意味着未指定 超时。

ftp-user

设置用于向 FTP 服务器进行身份验证的用户。它会被 FTP URL 中的用户覆盖。

ftp-password

设置用于向 FTP 服务器进行身份验证的密码。它会被 FTP URL 中的密码覆盖，或者在未设置用户时被 ftp-anonymous-password 覆盖。

ftp-anonymous-password

以匿名用户身份登录时使用的密码。通常应使用 电子邮件地址。

ftp-write-seekable

控制编码期间连接的可定位性。如果设置为 1，则认为 该资源可定位；如果设置为 0，则假定它不可定位。 默认值为 0。

注意：该协议可以用作输出，但建议不要这样做，除非 特别小心（测试、定制的服务器配置等）。不同的 FTP 服务器 在定位操作期间的行为方式不同。由于服务器限制，ff* 工具 可能会产生不完整的内容。

3.14 http# TOC

HTTP（超文本传输协议）。

该协议接受以下选项：

seekable

控制连接的可定位性。如果设置为 1，则认为该资源 可定位；如果设置为 0，则假定它不可定位；如果设置为 -1， 它将尝试自动检测其是否可定位。默认 值为 -1。

chunked_post

如果设置为 1，则对 post 使用分块传输编码，默认值为 1。

http_proxy

设置用于隧道传输的 HTTP 代理，例如 http://example.com:1234

headers

设置自定义 HTTP 头，可以覆盖内置的默认头。该 值必须是对这些头进行编码的字符串。

content_type

为 POST 消息或监听模式设置特定的内容类型。

user_agent

覆盖 User-Agent 头。如果未指定，协议将使用一个 描述 libavformat 构建的字符串。（"Lavf/<version>"）

referer

设置 Referer 头。在 HTTP 请求中包含 ’Referer: URL’ 头。

multiple_requests

如果设置为 1，则强制使用持久连接；如果为 0 则禁用。默认值为 -1， 表示自动（使用 -request_size 或 -initial_request_size 时隐含 keep-alive）。

request_size

限制所发出请求的大小。这对于某些会限制无边界范围请求的 病态服务器很有用，在预期会频繁定位时也很有用。 默认情况下禁用（设置为 0）。

请注意，如果启用此选项，强烈建议同时将 short_seek_size 设置为相同或更大的值。这样做 可以让 FFmpeg 尽可能复用单个 HTTP 连接。

initial_request_size

限制初始请求的大小。与 request_size 类似，但仅 在初始格式解析期间使用。对于 MXF 或 MOV 等在头解析期间 需要频繁定位的格式很有用。该限制持续到解复用器发出 大于此大小的读取请求（中间没有定位）为止，此后 实现将继续照常使用请求。默认情况下禁用 （设置为 0）。

请注意，如果启用此选项，强烈建议同时启用 multiple_requests 选项，并将 short_seek_size 设置为相同或更大的值。

post_data

设置自定义 HTTP post 数据。

mime_type

导出 MIME 类型。

http_version

导出 HTTP 响应版本号。通常为 "1.0" 或 "1.1"。

cookies

设置将来请求中要发送的 cookie。每个 cookie 的格式 与 Set-Cookie HTTP 响应字段的值相同。多个 cookie 可以 用换行符分隔。

icy

如果设置为 1，则从服务器请求 ICY（SHOUTcast）元数据。如果服务器 支持此功能，应用程序必须通过读取 icy_metadata_headers 和 icy_metadata_packet 选项来获取元数据。 默认值为 1。

icy_metadata_headers

如果服务器支持 ICY 元数据，此项包含 ICY 特有的 HTTP 回复 头，以换行符分隔。

icy_metadata_packet

如果服务器支持 ICY 元数据，并且 icy 设置为 1， 此项包含服务器发送的最后一个非空元数据数据包。对流中途 元数据更新感兴趣的应用程序应按固定间隔 轮询它。

metadata

设置一个导出的字典，其中包含来自比特流的 Icecast 元数据（如果存在）。 仅在使用 C API 时有用。

auth_type

设置 HTTP 身份验证类型。没有用于 Digest 的选项，因为该方法需要 先从服务器获取 nonce 参数，无法像 Basic 那样 直接使用。

none

自动选择 HTTP 身份验证类型。这是默认值。

basic

选择 HTTP 基本认证。

基本认证会发送一个 Base64 编码的字符串，其中包含供客户端使用的用户名和密码。 Base64 不是一种加密形式，应当被视为等同于 以明文发送用户名和密码（Base64 是一种可逆编码）。 如果需要保护某个资源，强烈建议使用基本认证之外的 其他认证方案。HTTPS/TLS 应当与基本认证配合使用。 如果没有这些额外的安全增强措施，就不应使用基本认证 来保护敏感或有价值的信息。

send_expect_100

为 POST 发送 Expect: 100-continue 头。若设为 1 则发送，若设 为 0 则不发送，若设为 -1 则在适用时会尝试发送。默认 值为 -1。

location

一个导出的字典，包含内容位置。仅在使用 C API 时有用。

offset

设置初始字节偏移量。

end_offset

尝试把请求限制在此偏移量之前的字节。

method

作为客户端选项使用时，它设置请求的 HTTP 方法。

作为服务端选项使用时，它设置将要 从客户端接收的 HTTP 方法。 如果期望的 HTTP 方法与收到的 HTTP 方法不匹配，客户端将 收到 Bad Request 响应。 未设置时不检查 HTTP 方法。将来这会 被自动检测取代。

reconnect

在到达 EOF 之前断开时自动重新连接。

reconnect_at_eof

若设置，则把 eof 视为错误并触发重新连接，这对 直播／无尽流很有用。

reconnect_on_network_error

在连接期间发生 TCP/TLS 错误时自动重新连接。

reconnect_on_http_error

一个以逗号分隔的 HTTP 状态码列表，用于确定何时重新连接。该列表可以 包含具体的状态码（例如 ’503’）或字符串 ’4xx’ / ’5xx’。

reconnect_streamed

若设置，则即使是流式的／不可定位的流也会在出错时重新连接。

reconnect_delay_max

设置放弃重新连接之前的最长延迟秒数。

reconnect_max_retries

设置重试连接的最大次数。默认未设置。

reconnect_delay_total_max

设置放弃重新连接之前的最长总延迟秒数。

respect_retry_after

若启用，并且遇到 Retry-After 头，则将遵循它请求的重新连接 延迟，而不使用指数退避。对 429 和 503 错误有用。默认启用。

listen

若设为 1 则启用实验性的 HTTP 服务端。它用于发送数据，例如 用作输出选项时；或在用作输入选项时用 HTTP POST 从客户端 读取数据。 若设为 2 则启用实验性的多客户端 HTTP 服务端。它尚未在 ffmpeg.c 中实现，因此不能用作命令行选项。 

# Server side (sending):
ffmpeg -i somefile.ogg -c copy -listen 1 -f ogg http://server:port

# Client side (receiving):
ffmpeg -i http://server:port -c copy somefile.ogg

# Client can also be done with wget:
wget http://server:port -O somefile.ogg

# Server side (receiving):
ffmpeg -listen 1 -i http://server:port -c copy somefile.ogg

# Client side (sending):
ffmpeg -i somefile.ogg -chunked_post 0 -c copy -f ogg http://server:port

# Client can also be done with wget:
wget --post-file=somefile.ogg http://server:port
resource

使用实验性 HTTP 服务端时，客户端请求的资源。

reply_code

使用实验性 HTTP 服务端时，返回给客户端的 HTTP 代码。

short_seek_size

设置阈值（以字节为单位），超过它时应优先预读而不是定位并 发起新的 HTTP 请求。这很有用，例如可以确保同一连接 用于读取大视频数据包，而其间夹杂小音频数据包。

3.14.1 HTTP Cookies# TOC

3.20 pipe# TOC

从 UNIX 管道读写。

可接受的语法为：

# ...this is the same as...
cat test.wav | ffmpeg -i pipe:

用 ffmpeg 写入 stdout： 

ffmpeg -i test.wav -f avi pipe:1 | cat > test.avi

ffmpeg -i test.wav -f avi pipe: | cat > test.avi

这是相对于 app 中所指定应用程序的、 要播放的资源路径或名称，可带有 "mp4:" 前缀。您 也可以通过 rtmp_playpath 选项 覆盖从 URI 中解析出的值。

作为服务器运行，监听传入的连接。

要在 RTMP 服务器上连接的应用程序名称。此选项 会覆盖 URI 中指定的参数。

rtmp_buffer

设置客户端缓冲区时间，单位为毫秒。默认为 3000。

嵌入该媒体的网页的 URL。默认情况下不会 发送任何值。

rtmp_playpath

要播放或发布的流标识符。此选项会覆盖 URI 中指定的参数。

rtmp_subscribe

要订阅的直播流名称。默认情况下不会发送任何值。 仅当指定了该选项或 rtmp_live 被设置为 live 时才会发送。

rtmp_swfhash

解压后的 SWF 文件的 SHA256 哈希（32 字节）。

rtmp_swfsize

解压后的 SWF 文件大小，SWFVerification 需要此项。

rtmp_swfurl

该媒体所用 SWF 播放器的 URL。默认情况下不会发送任何值。

rtmp_swfverify

播放器 swf 文件的 URL，将自动计算哈希/大小。

rtmp_tcurl

目标流的 URL。默认为 proto://host[:port]/app。

tcp_nodelay=1|0

设置 TCP_NODELAY 以禁用 Nagle 算法。默认值为 0。

备注：当前套接字写入未做最小化系统调用方面的优化，这降低了 TCP_NODELAY 的效率 / 效果。

启用 TCP keepalive 机制以检测失效的对端，并有助于维持长时间的空闲连接。默认值为 0。

只有基本的 keepalive 选项（SO_KEEPALIVE）可以启用或禁用。诸如 TCP_KEEPIDLE、TCP_KEEPINTVL 或 TCP_KEEPCNT 之类的平台特定调优参数不可配置，将使用操作系统的默认值。

例如，要使用 ffplay 从 RTMP 服务器 "myserver" 的 应用程序 "vod" 中读取名为 "sample" 的多媒体资源：

3.29 libcurl# TOC

user_agent

覆盖 User-Agent 头。默认为 Lavf/<version>。

referer

设置 Referer 头。

headers

设置自定义 HTTP 头，覆盖内部默认值。多个头之间 以换行符分隔。

http_proxy

设置要经由其建立隧道的 HTTP 代理。

cookies

在后续请求中发送的 Cookie，以换行符分隔的 Set-Cookie 风格的值给出。

控制连接的可寻址性。若设为 0，则该流被视为 不可寻址；1 强制可寻址；-1（默认值）则由 服务器响应自动检测。

用于双向 TLS 的客户端证书和私钥文件。

是否在 UDP 套接字上执行 connect()（若设为 1 则执行，若 设为 0 则不执行）。

sources=ip[,ip]

列出允许的源 IP 地址。

block=ip[,ip]

列出不允许（被阻止）的源 IP 地址。

write_to_source=0|1

将数据包发送到最近收到的数据包的源地址（若 设为 1），或发送到默认的远程地址（若设为 0）。

localaddr=addr

用于发送数据包或加入组播组的网络接口的本地 IP 地址。

timeout=n

将套接字 I/O 操作的超时时间（单位为微秒）设为 n。

重要说明：

  1. 若未设置 rtcpport，则 RTCP 端口将被设为 RTP 端口值加 1。
  2. 若未设置 localrtpport（本地 RTP 端口），则本地 RTP 和 RTCP 端口将使用任意可用端口。
  3. 若未设置 localrtcpport（本地 RTCP 端口），则它将被 设为本地 RTP 端口值加 1。

3.34 rtsp# TOC

实时流传输协议。

从技术上讲，RTSP 在 libavformat 中并不是协议处理器，而是一个解复用器 和复用器。解复用器同时支持普通 RTSP（数据通过 RTP 传输； 例如 Apple 和 Microsoft 使用这种方式）和 Real-RTSP（数据通过 RDT 传输）。

复用器可用于通过 RTSP ANNOUNCE 将流发送到支持它的服务器 （目前为 Darwin Streaming Server 和 Mischa Spiegelmock 的 RTSP 服务器）。

RTSP url 所需的语法为： 

rtsp://hostname[:port]/path

选项可以在 ffmpeg/ffplay 命令行 中设置，也可以在代码中通过 AVOption 或在 avformat_open_input 中设置。

3.34.1 复用器# TOC

支持以下选项。

rtsp_transport

设置 RTSP 传输协议。

它接受以下取值：

‘udp’

使用 UDP 作为底层传输协议。

‘tcp’

使用 TCP（在 RTSP 控制通道内交织）作为底层 传输协议。

默认值为 ‘0’。

rtsp_flags

设置 RTSP 标志。

接受以下取值：

‘latm’

对 AAC 使用 MP4A-LATM 打包方式，而不是 MPEG4-GENERIC。

‘rfc2190’

对 H.263 使用 RFC 2190 打包方式，而不是 RFC 4629。

‘skip_rtcp’

不发送 RTCP 发送方报告。

‘h264_mode0’

在 RTP 中对 H.264 使用模式 0。

‘send_bye’

结束时发送 RTCP BYE 数据包。

默认值为 ‘0’。

min_port

设置本地 UDP 最小端口。默认值为 5000。

max_port

设置本地 UDP 最大端口。默认值为 65000。

buffer_size

设置套接字缓冲区的最大大小（以字节为单位）。

pkt_size

设置发送数据包的最大大小（以字节为单位）。默认值为 1472。

3.34.2 解复用器# TOC

支持以下选项。

initial_pause

如果设为 1，则不立即开始播放流。默认值为 0。

rtsp_transport

设置 RTSP 传输协议。

它接受以下取值：

‘udp’

使用 UDP 作为下层传输协议。

‘tcp’

使用 TCP（在 RTSP 控制信道内交织）作为下层 传输协议。

‘udp_multicast’

使用 UDP 组播作为下层传输协议。

‘http’

使用 HTTP 隧道作为下层传输协议，这对于 穿过代理很有用。

‘https’

使用 HTTPs 隧道作为下层传输协议，这对于 穿过代理很有用，并且出于安全考虑被广泛使用。

可以指定多个下层传输协议，此时它们会 被逐个尝试（如果其中一个建立失败，就尝试下一个）。 对于复用器，仅支持 ‘tcp’ 和 ‘udp’ 选项。

rtsp_flags

设置 RTSP 标志。

接受以下取值：

‘filter_src’

只接受来自协商好的对端地址和端口的数据包。

‘listen’

作为服务器运行，监听传入连接。

‘prefer_tcp’

如果 TCP 可作为 RTSP RTP 传输，则优先为 RTP 传输尝试 TCP。

‘satip_raw’

导出原始 MPEG-TS 流而不是进行解复用。该标志只是把 原始流写出，同时保持原有的 PAT/PMT/PID 不变。

默认值为 ‘none’。

allowed_media_types

设置要从服务器接受的媒体类型。

接受以下标志：

‘video’
‘audio’
‘data’
‘subtitle’

默认情况下它接受所有媒体类型。

min_port

设置本地 UDP 最小端口。默认值为 5000。

max_port

设置本地 UDP 最大端口。默认值为 65000。

listen_timeout

设置建立初始连接的最大超时时间（以秒为单位）。将 listen_timeout 设为 > 0 会把 rtsp_flags 设为 ‘listen’。默认值为 -1， 表示在设置了 ‘listen’ 模式时超时时间为无限。

reorder_queue_size

设置用于处理乱序数据包而缓冲的数据包数量。

timeout

设置套接字 TCP I/O 超时时间（以微秒为单位）。

user_agent

覆盖 User-Agent 头。如果未指定，则默认为 libavformat 标识字符串。

buffer_size

设置套接字缓冲区的最大大小（以字节为单位）。

通过 UDP 接收数据时，解复用器会尝试对收到的数据包重新排序 （因为它们可能乱序到达，或者数据包可能完全丢失）。可以通过把最大解复用延迟设为零 （经由 AVFormatContext 的 max_delay 字段）来禁用这一行为。

使用 ffplay 观看多码率的 Real-RTSP 流时，可用 -vst n 和 -ast n 分别选择要显示的视频流和音频流，并且可以 通过按 v 和 a 即时切换。

3.34.3 示例# TOC

以下示例都使用了 ffplay 和 ffmpeg 工具。

  • 通过 UDP 观看流，最大重排序延迟为 0.5 秒： 
    ffplay -max_delay 500000 -rtsp_transport udp rtsp://server/video.mp4
  • 观看通过 HTTP 隧道传输的流： 
    ffplay -rtsp_transport http rtsp://server/video.mp4
  • 把流实时发送到 RTSP 服务器，供其他人观看： 
    ffmpeg -re -i input -f rtsp -muxdelay 0.1 rtsp://server/live.sdp
  • 实时接收流： 
    ffmpeg -rtsp_flags listen -i rtsp://ownaddress/live.sdp output

3.35 sap# TOC

会话通告协议（Session Announcement Protocol，RFC 2974）。严格来说它并不是 libavformat 中的协议处理器，而是复用器和解复用器。 它用于 RTP 流的信令，做法是在单独的端口上定期通告这些流的 SDP。

3.35.1 复用器# TOC

传给复用器的 SAP url 语法为： 

sap://destination[:port][?options]

RTP 数据包会被发送到 destination 的 port 端口， 如果未指定端口，则发送到端口 5004。 options 是一个以 & 分隔的列表。支持以下 选项：

announce_addr=address

指定发送通告的目标 IP 地址。 如果省略，通告会被发送到常用的 SAP 通告组播地址 224.2.127.254（sap.mcast.net），或者当 destination 是 IPv6 地址时 发送到 ff0e::2:7ffe。

announce_port=port

指定发送通告所用的端口，如果未指定 则默认为 9875。

ttl=ttl

指定通告和 RTP 数据包的生存时间（TTL）值， 默认为 255。

same_port=0|1

如果设为 1，则把所有 RTP 流发送到同一对端口上。如果设为零 （默认值），所有流会被发送到各自独立的端口上，每个流所在的 端口号比前一个高 2。 VLC/Live555 要求把该项设为 1 才能接收该流。 libavformat 中用于接收的 RTP 栈要求把所有流都发送 到各自独立的端口上。

以下是示例命令行。

要在本地子网上广播流以便用 VLC 观看： 

ffmpeg -re -i input -f sap sap://224.0.0.255?same_port=1

类似地，要用 ffplay 观看： 

ffmpeg -re -i input -f sap sap://224.0.0.255

以及通过 IPv6 用 ffplay 观看： 

ffmpeg -re -i input -f sap sap://[ff0e::1:2:3:4]

3.35.2 解复用器# TOC

传给解复用器的 SAP url 语法为： 

sap://[address][:port]

address 是用于监听通告的组播地址， 如果省略，则使用默认的 224.2.127.254（sap.mcast.net）。port 是所监听的端口，如果省略则为 9875。

解复用器在给定的地址和端口上监听通告。 一旦收到通告，它就会尝试接收那个特定的流。

以下是示例命令行。

要播放通过常规 SAP 组播地址通告的第一个流： 

ffplay sap://

要播放通过默认 IPv6 SAP 组播地址通告的第一个流： 

ffplay sap://[ff0e::2:7ffe]

3.36 sctp# TOC

流控制传输协议（Stream Control Transmission Protocol）。

接受的 URL 语法为： 

sctp://host:port[?options]

options 包含一组以 & 分隔的选项，形式为 key=val。可以使用标准的百分号编码（以及用加号表示 空格）来转义键和值。

选项也可以通过命令行选项指定（或在代码中通过 AVOption 指定）。

支持的选项列表如下。

listen

如果设为任意值，则监听传入连接。默认行为是向外发起连接。

max_streams

设置流的最大数量。默认不设限制。

3.37 shared# TOC

用于输入流的线程安全、持久化、跨进程缓存包装器。它把 输入流缓存到指定目录下的文件中。这类似于 cache，但带有磁盘上的持久化缓存，可以在 多个进程或解复用器之间共享，甚至可以并发共享。

缓存的文件名通过对输入 URL 做哈希得到，因此如果同一个 URL 被用于不同的内容（例如由于使用额外的 POST 数据来选择流 ID）， 就存在一定的冲突风险。为避免这种情况，请确保只对能唯一 标识内容的 URL 使用本协议； 否则你可能会得到 混杂错乱的多个来源。

接受的选项有：

cache_dir

存储缓存文件的目录路径。此选项为必需项。

block_shift

用于内部读写的块大小的移位因子（log2）。默认 为 15，即 32KB 块。如果该值与创建一个现有缓存文件时 所指定的值不一致，则会 改用先前指定的值。

read_only

如果为真，则使用共享缓存进行读取，但不向其写入任何新块。 默认值为假。注意，即使启用了此选项，如果缓存文件 尚不存在，它也会被初始化。

cache_verify

如果为真，则把从缓存读取的任何数据与底层输入流 进行校验，并在出现任何不匹配时报错退出。注意这会使缓存 层实际上毫无用处。这纯粹是一个调试选项。

cache_timeout

如果设为非零值，则指定等待数据可用的最长时间（以微秒为单位）， 前提是另一个进程当前正在同时尝试获取并缓存 同一个块。如果该超时时间耗尽，则 认为另一个进程可能在此期间卡住或已经死掉。

如果设为零，则不进行任何等待，所有进程都会立即争抢 并尝试自行获取相同的缺失块。默认值为 10000（10 毫秒）。

retry_errors

若为真（默认值），来自底层输入流的瞬时读取错误 会被忽略并重试。若为假，此前读取失败的 任何块都将被视为永久不可访问。

retry_corrupt

若为真（默认值），内容未能通过 CRC 完整性检查的块 会从底层输入流重新获取，并覆盖已损坏的 缓存数据。若为假，缓存损坏会被视为致命的读取错误。

URL 语法为 

shared:URL

3.38 srt# TOC

通过 libsrt 实现的 Haivision Secure Reliable Transport 协议。

SRT URL 支持的语法为： 

srt://hostname:port[?options]

options 包含以 & 分隔的选项列表，形式为 key=val。可以使用标准的百分号编码（以及用加号表示 空格）来转义键与值。

这些选项也可以通过命令行选项指定（或在代码中通过 AVOption 指定）。

支持的选项列表如下。

connect_timeout=milliseconds

连接超时；当 RTT > 1500 毫秒（2 次握手交换）时， 使用默认的 3 秒连接超时，SRT 无法建立连接。 此选项适用于 caller 和 rendezvous 连接模式。连接超时为 rendezvous 模式所设值的 10 倍（在早期版本中，这可以作为 解决该连接问题的一种变通方法）。

ffs=bytes

飞行标志大小（窗口大小），以字节为单位。FFS 实际上是 一个内部参数，其取值不应小于 recv_buffer_size 和 mss。默认值 相对较大，因此除非你设置了非常大的接收缓冲区， 否则无需更改此选项。默认值为 25600。

inputbw=bytes/seconds

发送方的标称输入速率，以字节/秒为单位。当 maxbw 设为相对值 (0) 时，它与 oheadbw 一起 用于计算在随主媒体流一起发送恢复包时的 最大发送速率： inputbw * (100 + oheadbw) / 100 若未设置 inputbw 而 maxbw 被设为 相对值 (0)，则实际输入速率会在库内部 进行估算。默认值为 0。

iptos=tos

IP 服务类型。仅适用于发送方。默认值为 0xB8。

ipttl=ttl

IP 生存时间。仅适用于发送方。默认值为 64。

latency=microseconds

基于时间戳的数据包投递延迟。 用于吸收突发性的丢包重传。 此标志会把 rcvlatency 和 peerlatency 设为相同的值。注意，在 1.3.0 版本之前， 这是唯一用于设置延迟的标志，不过 当本端为发送方时它实际上等同于设置 peerlatency， 而当本端为接收方时等同于设置 rcvlatency， 并且不支持双向流 发送。

listen_timeout=microseconds

设置套接字监听超时。

maxbw=bytes/seconds

最大发送带宽，以字节/秒为单位。 -1 表示无限（CSRTCC 限制为 30mbps） 0 表示相对于输入速率（参见 inputbw） >0 表示绝对限制值 默认值为 0（相对）

mode=caller|listener|rendezvous

连接模式。 caller 打开客户端连接。 listener 启动服务器以监听传入的连接。 rendezvous 使用 Rendez-Vous 连接模式。 默认值为 caller。

mss=bytes

最大段大小，以字节为单位。在假定数据包完全填满的 情况下，用于借助数据包计数器进行缓冲区分配 和速率计算。使用对等端之间最小的 MSS。在整个互联网中该值默认为 1500。 这是 UDP 数据包的最大大小，只能减小， 除非你有某些不寻常的专用 网络设置。默认值为 1500。

nakreport=1|0

若设为 1，接收方会周期性地发送 ‘UMSG_LOSSREPORT‘ 消息， 直到丢失的数据包被重传或 被有意丢弃。默认值为 1。

oheadbw=percents

高于输入速率的恢复带宽开销，以百分比为单位。 参见 inputbw。默认值为 25%。

passphrase=string

HaiCrypt 加密/解密口令字符串，长度 为 10 到 79 个字符。该口令是发送方与 接收方之间的共享密钥。它用于 通过 PBKDF2（基于口令的密钥派生 函数）生成密钥加密密钥。仅当 pbkeylen 非零时才会使用它。在接收方， 仅当接收到的数据已加密时才会使用它。 所配置的口令无法恢复（只写）。

enforced_encryption=1|0

若为真，连接双方必须设置相同的口令 （包括空口令，即不加密）。若口令 不匹配或只有一方未加密， 则连接被拒绝。默认为真。

kmrefreshrate=packets

传输多少个数据包之后加密密钥会切换为 新密钥。默认为 -1。 -1 表示自动（在 srt 库中为 0x1000000）。此选项的 取值范围是 0 - INT_MAX 之间的整数。

kmpreannounce=packets

从发送新加密密钥到发生切换之间的 时间间隔。此值也适用于从发生切换 到旧加密密钥被停用之间的 后续间隔。默认为 -1。 -1 表示自动（在 srt 库中为 0x1000）。此选项的 取值范围是 0 - INT_MAX 之间的整数。

snddropdelay=microseconds

发送方在丢弃数据包之前的额外延迟。此延迟 会加到默认的丢弃延迟时间间隔值上。

特殊值 -1：完全不丢弃发送方上的数据包。

payload_size=bytes

设置 Live 模式下单次调用发送函数期间 所传输数据包的声明最大大小。 若不使用此值则设为 0（在 file 模式下 这是默认值）。 默认为 -1（自动），这通常意味着 MPEG-TS； 如果你打算使用 SRT 发送任何不同类型的负载，例如 把直播流封装到非常小的帧中，那么你可以 使用更大的最大帧大小，但不得大于 1456 字节。

pkt_size=bytes

‘payload_size’ 的别名。

peerlatency=microseconds

由发送方设置的延迟值（如 rcvlatency 中所述）， 用作接收方的最小值。

pbkeylen=bytes

发送方加密密钥长度，以字节为单位。 只能设为 0、16、24 和 32。 若不为 0 则启用发送方加密。 在接收方不需要设置（设为 0）， 密钥大小在 HaiCrypt 握手中从发送方获取。 默认值为 0。

rcvlatency=microseconds

从数据包被发送的那一刻到 它在接收函数中被投递给接收方 应用程序的那一刻之间应当经过的时间。 该时间应是一个足够大的缓冲时间， 以涵盖发送所耗费的时间、意外延长的 RTT 时间，以及重传丢失的 UDP 数据包所需的时间。有效延迟值将是 此选项的值与对端所设置的 peerlatency 值两者中的最大值。在 1.3.0 版本之前，此选项仅以 latency 的形式提供。

recv_buffer_size=bytes

设置 UDP 接收缓冲区大小，以字节为单位。

send_buffer_size=bytes

设置 UDP 发送缓冲区大小，以字节为单位。

timeout=microseconds

设置读、写和连接操作的报错超时。注意， SRT 库有可单独控制的内部超时， 这里设置的值只是它们的上限。

tlpktdrop=1|0

过晚数据包丢弃（Too-late Packet Drop）。在接收方启用时，它会跳过 未能及时投递的缺失数据包，并在 其播放时间到来时把随后的数据包 投递给应用程序。它还会向发送方 发送一个伪 ACK。在发送方启用且 接收对端也启用时，发送方会丢弃 没有机会及时投递的较旧数据包。如果接收方 支持，则该功能会在发送方 自动启用。

sndbuf=bytes

设置发送缓冲区大小，以字节为单位。

rcvbuf=bytes

设置接收缓冲区大小，以字节为单位。

接收缓冲区不得大于 ffs。

lossmaxttl=packets

重排容忍度可以增长到的上限值。当 重排容忍度 > 0 时，丢包报告会延迟， 直到收到该数量的数据包为止。每当 一个 "迟到" 的数据包到达，且它并非 由重传导致时（即 UDP 数据包出现 乱序的情况），重排容忍度会增加，增加量为 最新序号与该数据包序号之差，且不超过 此选项的值。默认情况下为 0，这意味着该 机制被关闭，丢包报告总是在 遇到序号 "间隙" 时立即发送。

minversion

要求对端提供的 SRT 最低版本。与不满足 最低版本要求的对端之间的连接 将被拒绝。

十六进制版本格式为 0xXXYYZZ，对应人类可读 形式的 x.y.z。

streamid=string

一个限制为 512 个字符的字符串，可在连接之前 在套接字上设置。监听方将能够从 srt_accept 返回的、且由设置了该流 ID 的套接字 所连接的套接字中取回该流 ID。SRT 并不强制 对该字符串的内容作任何特殊解释。 此选项在 Rendezvous 连接中没有意义；结果 可能只是一方覆盖另一方的值， 至于哪一方会胜出则全凭运气

srt_streamid=string

‘streamid’ 的别名，以避免与 ffmpeg 命令行选项冲突。

smoother=live|file

该套接字传输所使用的 Smoother 类型，它 负责传输与拥塞控制。Smoother 类型在连接双方上必须完全相同， 否则连接会被拒绝。

messageapi=1|0

设置后，该套接字使用 Message API，否则使用 Buffer API。注意，在 live 模式下（参见 transtype）只有 message API 可用。在 File 模式下你可以选择使用两种模式之一：

Stream API（默认，当此选项为假时）。在此模式下，你可以 通过一条发送指令发送任意多的数据，甚至可以使用 直接从文件读取的专用函数。内部机制 会处理任何速度与拥塞控制。接收时，你也可以 接收任意多的数据，未取出的数据会 等待下一次调用。在 Stream 模式下 数据部分之间没有边界。

Message API。在此模式下，你的单条发送指令恰好传递 一块有边界的数据（一条消息）。与 Live 模式相反， 该消息可以跨越多个 UDP 数据包，唯一的 大小限制是它必须整体放入发送缓冲区。接收方 应使用所需大小的缓冲区来接收该消息， 否则该消息不会被放弃。当消息不完整 （并非所有数据包都已收到，或出现了丢包）时， 它不会被放弃。

transtype=live|file

设置套接字的传输类型，特别是，设置此 选项会按照特定传输类型的需要把多个其它 参数设为其默认值。

live：按 live 传输来设置选项。在此模式下，你 应当通过一条发送指令只发送能放入一个 UDP 数据包的数据， 并且限制为 payload_size 中首先定义的值（此模式下 默认为 1316）。此模式下没有速度控制，只有 带宽控制（如果已配置），以免开销传输 （重传包和控制包）超出带宽。

file：按非 live 传输来设置选项。进一步的说明 请参见 messageapi

linger=seconds

关闭时套接字等待未发送数据的秒数。 默认为 -1。-1 表示自动（live 模式下关闭，为 0 秒； file 模式下开启，为 180 秒）。此选项的取值范围是 0 - INT_MAX 之间的整数。

tsbpd=1|0

为真时，使用基于时间戳的数据包投递模式。默认行为 取决于传输类型：在 live 模式下启用，在 file 模式下 禁用。

ipv6only=1|0

在使用 IPv6 通配地址时是否接受 IPv4。监听 IPv6 通配地址时 应当设置此项。

更多信息请参见：https://github.com/Haivision/srt。

3.42 tcp# TOC

传输控制协议。

TCP URL 的语法要求如下： 

tcp://hostname:port[?options]

options 包含一组以 & 分隔的选项，形式为 key=val。可以使用标准的百分号编码（以加号表示 空格）来转义键和值。

选项也可以通过命令行选项指定（或在代码中通过 AVOption 指定）。

支持的选项列表如下。

listen=2|1|0

监听传入连接。0 禁用监听，1 以单客户端模式 启用监听，2 以多客户端模式启用监听。默认值为 0。

local_addr=addr

用于 tcp 套接字连接的网络接口的本地 IP 地址。

local_port=port

用于 tcp 套接字连接的本地端口。

timeout=microseconds

设置触发错误的超时时间，单位为微秒。

该选项仅在读取模式下有意义：如果在超过此时间间隔后 仍没有数据到达，则触发错误。

listen_timeout=milliseconds

设置监听超时时间，单位为毫秒。

recv_buffer_size=bytes

设置接收缓冲区大小，单位为字节。

send_buffer_size=bytes

设置发送缓冲区大小，单位为字节。

tcp_nodelay=1|0

设置 TCP_NODELAY 以禁用 Nagle’s 算法。默认值为 0。

注意：目前对套接字的写入并未针对减少系统调用进行优化，会降低 TCP_NODELAY 的效率 / 效果。

tcp_mss=bytes

设置输出 TCP 数据包的最大分段大小，单位为字节。

下面的示例展示了如何用 ffmpeg 建立一个监听 TCP 连接， 随后使用 ffplay 访问该连接： 

ffmpeg -i input -f format tcp://hostname:port?listen
ffplay tcp://hostname:port

3.43 tls# TOC

传输层安全（TLS）/ 安全套接字层（SSL）

TLS/SSL URL 的语法要求如下： 

tls://hostname:port[?options]

options 包含一组以 & 分隔的选项，形式为 key=val。可以使用标准的百分号编码（以加号表示 空格）来转义键和值。

选项也可以通过命令行选项指定（或在代码中通过 AVOption 指定）。

支持的选项列表如下。

ca_file, cafile=filename

包含要视为可信的证书颁发机构（CA）根证书的文件。 如果所链接的 TLS 库包含默认值，则为了验证能够正常工作 可能无需指定此项，但并非所有库和 配置都内置了默认值。 该文件必须为 OpenSSL PEM 格式。

tls_verify, verify=1|0

如果启用，则尝试验证与之通信的对端。 注意，如果使用 OpenSSL，目前这只能确保 对端证书由 CA 数据库中的某个根证书签名， 但不会验证该证书是否确实 与我们尝试连接的主机名匹配。（对于其它后端， 主机名也会被验证。）

此项默认启用。验证对端需要 CA 数据库， 在某些情况下必须由调用者提供。

cert_file, cert=filename

包含用于与对端握手的证书的文件。 （当以服务器身份在监听模式下运行时，这更多是对端 要求的，而客户端证书仅在 某些配置中是必需的。）

key_file, key=filename

包含该证书私钥的文件。

listen=1|0

如果启用，则在指定端口上监听连接，并在握手中 扮演服务器角色而不是客户端角色。

http_proxy

要隧道经过的 HTTP 代理，例如 http://example.com:1234。 该代理必须支持 CONNECT 方法。

示例命令行：

创建一个提供输入流的 TLS/SSL 服务器。 

ffmpeg -i input -f format tls://hostname:port?listen&cert=server.crt&key=server.key

使用 ffplay 从 TLS/SSL 服务器回放流： 

ffplay tls://hostname:port

3.45 udp# TOC

用户数据报协议。

UDP URL 所需的语法为： 

udp://hostname:port[?options]

options 包含一组以 & 分隔的选项，形式为 key=val。可以使用标准的百分号编码（以及用加号表示 空格）来转义键和值。

选项也可以通过命令行选项指定（或在代码中通过 AVOption 指定）。

如果系统启用了线程，则会使用环形缓冲区 来存储传入的数据，这可以减少因 UDP 套接字缓冲区溢出而导致的数据丢失。fifo_size 和 overrun_nonfatal 选项与此缓冲区相关。

支持的选项列表如下。

buffer_size=size

设置 UDP 最大套接字缓冲区大小，单位为字节。根据套接字的用途， 该值用于设置接收缓冲区或发送缓冲区的大小。 输出的默认值为 32 KB，输入的默认值为 384 KB。另请参见 fifo_size。

bitrate=bitrate

如果设置为非零值，则当输入有足够的数据包来维持时， 输出将具有指定的恒定码率。

burst_bits=bits

使用 bitrate 时，此项指定数据包突发中的 最大比特数。

localport=port

覆盖要绑定的本地 UDP 端口。

localaddr=addr

用于发送数据包或加入多播组的网络接口的 本地 IP 地址。

pkt_size=size

设置 UDP 数据包的大小，单位为字节。

reuse=1|0

显式允许或禁止重用 UDP 套接字。

ttl=ttl

设置生存时间值（仅用于多播）。

dscp=dscp

设置传出数据包的 6 位 DSCP 字段。

connect=1|0

使用 connect() 初始化 UDP 套接字。在这种情况下， 之后无法用 ff_udp_set_remote_url 更改目标地址。 如果开始时目标地址未知，也可以在 ff_udp_set_remote_url 中 指定此选项。 这样可以借助 getsockname 找出数据包的源地址， 并且在收到 "destination unreachable" 时使写入返回 AVERROR(ECONNREFUSED)。 对于接收来说，这样做的好处是只接收来自 指定对等地址/端口的数据包。

sources=address[,address]

只接收从指定地址发送的数据包。在多播的情况下， 还只订阅来自这些地址的多播流量。

block=address[,address]

忽略从指定地址发送的数据包。在多播的情况下， 还会在多播订阅中排除这些源地址。

fifo_size=units

设置 UDP 接收环形缓冲区的大小，以大小为 188 字节的 数据包数量表示。如果未指定，默认为 7*4096。

overrun_nonfatal=1|0

在 UDP 接收环形缓冲区溢出时仍继续运行。默认 值为 0。

timeout=microseconds

设置触发错误的超时时间，单位为微秒。

此选项仅在读取模式下有意义：如果在该时间间隔内 没有数据到达，则触发错误。

broadcast=1|0

显式允许或禁止 UDP 广播。

请注意，在具有广播风暴保护的网络上， 广播可能无法正常工作。

3.45.1 示例# TOC

  • 使用 ffmpeg 通过 UDP 向远程端点传输流： 
    ffmpeg -i input -f format udp://hostname:port
  • 使用 ffmpeg 以 mpegts 格式通过 UDP 传输流，使用 188 字节大小的 UDP 数据包，并使用较大的输入缓冲区： 
    ffmpeg -i input -f mpegts udp://hostname:port?pkt_size=188&buffer_size=65535
  • 使用 ffmpeg 通过 UDP 从远程端点接收流： 
    ffmpeg -i udp://[multicast-address]:port ...

3.47 zmq# TOC

使用 libzmq 库进行 ZeroMQ 异步消息传递。

该库支持向多个客户端进行单播流传输，而无需依赖 外部服务器。

进行流传输或连接到流所需的语法为： 

zmq:tcp://ip-address:port

示例： 在端口 5555 上创建 localhost 流： 

ffmpeg -re -i input -f mpegts zmq:tcp://127.0.0.1:5555

多个客户端可以使用以下命令连接到该流： 

ffplay zmq:tcp://127.0.0.1:5555

向多个客户端进行流传输是通过 ZeroMQ 发布-订阅模式实现的。 服务器端绑定到一个端口并发布数据。客户端连接到 服务器（通过 IP 地址/端口）并订阅该流。服务器和客户端 的启动顺序通常无关紧要。

ffmpeg 必须使用 –enable-libzmq 选项编译才能支持 此协议。

选项可以在 ffmpeg/ffplay 命令行 上设置。支持以下选项：

pkt_size

强制设置发送/接收数据的最大数据包大小。默认值 为 131,072 字节。在服务器端，这设置通过 ZeroMQ 发送的数据包 的最大大小。在客户端，这设置用于接收数据包的内部 缓冲区大小。请注意，客户端上的 pkt_size 应等于或大于 服务器上的 pkt_size。否则收到的消息可能被截断，从而导致 解码错误。
