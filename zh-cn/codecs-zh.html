1 描述# TOC

本文档介绍编解码器（解码器和编码器），它们由 libavcodec 库提供。

2 编解码器选项# TOC

libavcodec 提供了一些通用的全局选项，可以对 所有编码器和解码器进行设置。此外，每个编解码器还可能支持 所谓的私有选项，这些选项专用于某个特定的编解码器。

有时，某个全局选项可能只影响某类特定的编解码器， 而对另一种编解码器则没有意义或被忽略，因此你需要了解 所指定选项的含义。此外，有些选项 仅用于解码或编码。

选项可以在 FFmpeg 工具中通过指定 -option value 来设置， 也可以在 AVCodecContext 选项中显式设定该值，或使用 libavutil/opt.h API 以供编程使用。

受支持的选项列表如下：

b integer (encoding,audio,video)

设置码率，单位为比特/秒。默认值为 200K。

ab integer (encoding,audio)

设置音频码率（单位为比特/秒）。默认值为 128K。

bt integer (encoding,video)

设置视频码率容差（单位为比特/秒）。在 1-pass 模式下，码率 容差指定了码率控制愿意偏离目标 平均码率值的程度。这与最小/最大 码率无关。将容差设得过低会对质量产生不良影响。

flags flags (decoding/encoding,audio,video,subtitles)

设置通用标志。

可能的取值：

‘mv4’

对每个宏块使用四个运动矢量（mpeg4）。

‘qpel’

使用 1/4 像素精度的运动补偿。

‘loop’

使用环路滤波器。

‘qscale’

使用固定 qscale。

‘pass1’

在第一遍模式下使用内部 2pass 码率控制。

‘pass2’

在第二遍模式下使用内部 2pass 码率控制。

‘gray’

仅解码/编码灰度。

‘psnr’

在编码期间设置 error[?] 变量。

‘truncated’

输入比特流可能被随机截断。

‘drop_changed’

不要输出参数与流中首个已解码帧不同的帧。 当帧被丢弃时会返回错误 AVERROR_INPUT_CHANGED。

‘ildct’

使用隔行 DCT。

‘low_delay’

强制低延迟。

‘global_header’

将全局头置于 extradata 中，而不是放在每个关键帧中。

‘bitexact’

仅写入与平台、构建和时间无关的数据。（(I)DCT 除外）。 这可确保文件和数据校验和可复现，并在各平台之间保持一致。 其主要用途是回归测试。

‘aic’

应用 H263 高级帧内编码 / mpeg4 ac 预测。

‘ilme’

应用隔行运动估计。

‘cgop’

使用闭合 gop。

‘output_corrupt’

即使帧可能已损坏也输出。

time_base rational number

设置编解码器时基。

它是以秒为单位的基本时间单位， 帧时间戳即以此为基准表示。对于固定 fps 的内容，时基 应为 1 / frame_rate，且时间戳 的增量应恒为 1。

g integer (encoding,video)

设置图像组（GOP）大小。默认值为 12。

ar integer (decoding/encoding,audio)

设置音频采样率（单位为 Hz）。

ac integer (decoding/encoding,audio)

设置音频声道数。

cutoff integer (encoding,audio)

设置截止带宽。（仅部分编码器支持，请参见 各自的文档章节。）

frame_size integer (encoding,audio)

设置音频帧大小。

除最后一帧外，每个提交的帧在每个声道上必须恰好包含 frame_size 个采样。当编解码器设置了 CODEC_CAP_VARIABLE_FRAME_SIZE 时，该值可以为 0，此时帧大小 不受限制。某些解码器会设置该值以表示固定帧 大小。

frame_number integer

设置帧编号。

delay integer
qcomp float (encoding,video)

设置视频量化器尺度压缩（VBR）。它用作码率控制 方程中的常数。默认 rc_eq 的推荐范围为： 0.0-1.0。

qblur float (encoding,video)

设置视频量化器尺度模糊（VBR）。

qmin integer (encoding,video)

设置最小视频量化器尺度（VBR）。必须介于 -1 和 69 之间，默认值为 2。

qmax integer (encoding,video)

设置最大视频量化器尺度（VBR）。必须介于 -1 和 1024 之间，默认值为 31。

qdiff integer (encoding,video)

设置量化器尺度之间的最大差值（VBR）。

bf integer (encoding,video)

设置非 B 帧之间 B 帧的最大数量。

必须是 -1 和 16 之间的整数。0 表示 B 帧 被禁用。若使用 -1，则会自动选择一个 取决于编码器的值。

默认值为 0。

b_qfactor float (encoding,video)

设置 P 帧与 B 帧之间的 qp 系数。

codec_tag integer
bug flags (decoding,video)

规避未能自动检测到的编码器缺陷。

可能的取值：

‘autodetect’
‘xvid_ilace’

Xvid 隔行缺陷（若 fourcc==XVIX 则自动检测）

‘ump4’

（若 fourcc==UMP4 则自动检测）

‘no_padding’

填充缺陷（自动检测）

‘amv’
‘qpel_chroma’
‘std_qpel’

旧标准的 qpel（按 fourcc/版本自动检测）

‘qpel_chroma2’
‘direct_blocksize’

direct-qpel-blocksize 缺陷（按 fourcc/版本自动检测）

‘edge’

边缘填充缺陷（按 fourcc/版本自动检测）

‘hpel_chroma’
‘dc_clip’
‘ms’

规避 microsoft 有问题的解码器中的各种缺陷。

‘trunc’

被截断的帧

‘h264_dp_nnz’

对分片条带进行 H.264 nC 推导，如同 JM 所做而非按 9.2.1 所述（自动检测）

strict integer (decoding/encoding,audio,video)

指定遵循标准的严格程度。

可能的取值：

‘very’

严格遵循规范的较早且更严格的版本或参考软件

‘strict’

无论后果如何，严格遵循规范中的所有内容

‘normal’
‘unofficial’

允许非官方扩展

‘experimental’

允许非标准化的实验性内容，以及实验性 （未完成/开发中/未经充分测试）的解码器和编码器。 注意：实验性解码器可能带来安全风险，请勿将其用于 解码不受信任的输入。

b_qoffset float (encoding,video)

设置 P 帧与 B 帧之间的 QP 偏移。

err_detect flags (decoding,audio,video)

设置错误检测标志。

可能的取值：

‘crccheck’

校验内嵌的 CRC

‘bitstream’

检测比特流规范偏差

‘buffer’

检测不当的比特流长度

‘explode’

检测到轻微错误时中止解码

‘ignore_err’

忽略解码错误，并继续解码。 如果你想分析视频内容，从而希望 无论出现什么情况都解码所有内容，此选项很有用。出现错误时，此选项不会产生 观感良好的视频。

‘careful’

将违反规范且在实践中未曾出现的情况视为错误

‘compliant’

将所有不符合规范的情况视为错误

‘aggressive’

将正常编码器不应做的事情视为错误

has_b_frames integer
block_align integer
rc_override_count integer
maxrate integer (encoding,audio,video)

设置最大码率容差（单位为比特/秒）。需要先设置 bufsize。

minrate integer (encoding,audio,video)

设置最小码率容差（单位为比特/秒）。在设置 CBR 编码时最为有用。其他情况下用处不大。

bufsize integer (encoding,audio,video)

设置码率控制缓冲区大小（单位为比特）。

i_qfactor float (encoding,video)

设置 P 帧与 I 帧之间的 QP 系数。

i_qoffset float (encoding,video)

设置 P 帧与 I 帧之间的 QP 偏移。

dct integer (encoding,video)

设置 DCT 算法。

可能的取值：

‘auto’

自动选择一个合适的（默认）

‘fastint’

快速整数

‘int’

精确整数

‘mmx’
‘altivec’
‘faan’

浮点 AAN DCT

lumi_mask float (编码，视频)

对亮区施加比中间调更强的压缩。

tcplx_mask float (编码，视频)

设置时间复杂度掩蔽。

scplx_mask float (编码，视频)

设置空间复杂度掩蔽。

p_mask float (编码，视频)

设置帧间掩蔽。

dark_mask float (编码，视频)

对暗区施加比中间调更强的压缩。

‘auto’

3 解码器# TOC

解码器是 FFmpeg 中的可配置组件，用于解码多媒体流。

在配置 FFmpeg 构建时，所有受支持的原生解码器默认都是启用的。需要外部库的 解码器必须通过相应的 --enable-lib 选项手动启用。可以使用 配置选项 --list-decoders 列出所有可用的解码器。

可以使用配置选项 --disable-decoders 禁用所有解码器， 并通过选项 --enable-decoder=DECODER / --disable-decoder=DECODER 选择性地启用/禁用单个解码器。

ff* 工具的 -decoders 选项会显示已启用的解码器列表。

5.1.1 AC-3 解码器选项# TOC

-drc_scale value

动态范围缩放系数。用于 AC-3 流中动态范围值的系数。 该系数以指数方式应用。默认值为 1。 有 3 个值得注意的缩放系数区间：

drc_scale == 0

禁用 DRC。产生全范围音频。

0 < drc_scale <= 1

drc_scale > 1

启用 DRC。以非对称方式应用 drc_scale。 响亮的声音被完全压缩。轻柔的声音被增强。

8.1 aac# TOC

8.1.1 选项# TOC

9.29.2 速度方面的考虑# TOC

在默认的工作模式下，编码器必须遵守帧约束 （即不生成尺寸大于所要求的帧），同时仍尽可能 使输出画面质量最佳。 包含大量细小细节的帧更难压缩，编码器 会花费更多时间为每个 slice 搜索合适的量化器。

设置更高的 bits_per_mb 限值将提升速度。

要获得最快的编码速度，请设置 qscale 参数（4 是 推荐值），并且不要设置尺寸约束。

9.30 QSV 编码器# TOC

9.30.1 码率控制方法# TOC

码率控制方法的选择方式如下：

  • 当指定了 global_quality 时，使用基于质量的模式。 具体来说，这表示以下之一
    • CQP - 恒定量化器步长，当同时设置了 qscale 编解码器标志 （即 -qscale ffmpeg 选项）时。
    • LA_ICQ - 带前瞻的智能恒定质量，当同时设置了 look_ahead 选项时。
    • ICQ – 其它情况下的智能恒定质量。对于 ICQ 模式，全局 质量范围为 1 到 51，其中 1 表示最佳质量。
  • 否则，当使用 b 选项指定了期望的平均码率时， 使用基于码率的模式。
    • LA - 带前瞻的 VBR，当指定了 look_ahead 选项时。
    • VCM - 视频会议模式，当设置了 vcm 选项时。
    • CBR - 恒定码率，当指定了 maxrate 且其值等于 平均码率时。
    • VBR - 可变码率，当指定了 maxrate 但其值高于 平均码率时。
    • AVBR - 平均 VBR 模式，当未指定 maxrate、且 avbr_accuracy 与 avbr_convergence 都设为非零值。该 模式在 Windows 上可用于 H264 和 HEVC。
  • 否则，使用默认的码率控制方法 CQP。

请注意，取决于你的系统，编码器可能选择与你指定的模式不同的模式。 将详细程度级别设为 verbose 或 更高，以查看 QSV 运行时实际使用的设置。
