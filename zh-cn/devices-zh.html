1 描述# TOC

本文档介绍 libavdevice 库所提供的输入设备与 输出设备。

2 设备选项# TOC

libavdevice 库提供与 libavformat 相同的接口。也就是说，输入设备被视为解复用器，而 输出设备被视为复用器；其接口和通用设备 选项与 libavformat 提供的一致（参见 ffmpeg-formats 手册）。

此外，每个输入或输出设备还可以支持所谓的私有 选项，这些选项是该组件特有的。

选项可以通过在 FFmpeg 工具中指定 -option value 来 设置，也可以在设备的 AVFormatContext 选项中显式设置该值，或使用 libavutil/opt.h API 进行编程调用。

3 输入设备# TOC

输入设备是 FFmpeg 中经过配置的组件，用于访问 来自连接到系统的多媒体设备的数据。

配置 FFmpeg 构建时，所有支持的输入设备 默认都会启用。你可以使用配置 选项 "–list-indevs" 列出所有可用的输入设备。

你可以使用配置选项 "–disable-indevs" 禁用所有输入设备，并使用选项 "–enable-indev=INDEV" 有选择地启用某个输入设备，或使用选项 "–disable-indev=INDEV" 禁用某个特定的输入设备。

ff* 工具的 "-devices" 选项会显示 支持的输入设备列表。

下面介绍当前可用的输入设备。

3.1 alsa# TOC

ALSA（Advanced Linux Sound Architecture）输入设备。

要在配置期间启用此输入设备，你需要在系统上 安装 libasound。

此设备允许从 ALSA 设备进行采集。要采集的 设备名称必须是 ALSA 声卡标识符。

ALSA 标识符的语法为： 

hw:CARD[,DEV[,SUBDEV]]

其中 DEV 和 SUBDEV 部分是可选的。

这三个参数（按顺序为：CARD,DEV,SUBDEV） 分别指定声卡编号或标识符、设备编号和子设备编号 （-1 表示任意）。

要查看系统当前识别到的声卡列表，请检查 文件 /proc/asound/cards 和 /proc/asound/devices。

例如，要使用 ffmpeg 从声卡 id 为 0 的 ALSA 设备 进行采集，可以运行以下命令： 

ffmpeg -f alsa -i hw:0 alsaout.wav

更多信息请参见： http://www.alsa-project.org/alsa-doc/alsa-lib/pcm.html

3.1.1 选项# TOC

sample_rate

设置采样率，单位为 Hz。默认为 48000。

ch_layout

设置声道布局。未设置时，布局默认为立体声，或默认为设备 支持的最小声道数，并尽最大努力从 ALSA 声道映射中填充。

3.2 android_camera# TOC

Android 摄像头输入设备。

此输入设备使用 Android Camera2 NDK API，该 API 在 API 级别 24 及以上的设备上可用。android_camera 的可用性会在配置期间自动检测。

此设备允许从 Android 设备上的所有摄像头采集， 这些摄像头已集成到 Camera2 NDK API 中。

可用的摄像头会在内部枚举，可通过 camera_index 参数进行选择。输入文件字符串 会被丢弃。

通常后置摄像头的索引为 0，而前置 摄像头的索引为 1。

3.2.1 选项# TOC

video_size

设置视频尺寸，以字符串形式给出，例如 640x480 或 hd720。 如果请求的视频尺寸不可用，则回退到 Android 报告的 第一个可用配置，或使用默认值。

framerate

设置视频帧率。 如果请求的帧率不可用，则回退到 Android 报告的 第一个可用配置，或使用默认值（-1）。

camera_index

设置要使用的摄像头索引。默认为 0。

input_queue_size

设置要缓冲的最大帧数。默认为 5。

3.3 avfoundation# TOC

AVFoundation 输入设备。

AVFoundation 是 Apple 目前推荐的框架，用于在 OSX >= 10.7 以及 iOS 上进行流采集。

输入文件名必须按以下语法给出： 

-i "[[VIDEO]:[AUDIO]]"

第一项选择视频输入，后一项则选择音频输入。 流必须通过设备列表中显示的设备名称或设备索引来指定。 另外，也可以使用以下选项按索引选择视频和/或音频输入设备 -video_device_index <INDEX> 和/或 -audio_device_index <INDEX> ，其会覆盖 输入文件名中给出的任何设备名称或索引。

可以使用 -list_devices true 枚举所有可用设备，它会列出 所有设备名称及对应的索引。

有两个设备名称别名：

default

选择相应类型的 AVFoundation 默认设备。

none

不录制相应的媒体类型。 这等同于指定空的设备名称或索引。

3.3.1 选项# TOC

AVFoundation 支持以下选项：

-list_devices <TRUE|FALSE>

若设为 true，则会给出所有可用输入设备的列表，显示其 索引、名称、唯一 ID 和 USB 序列号（如果可用）。

-video_device_index <INDEX>

通过索引指定视频设备。会覆盖输入文件名中给出的任何内容。

-audio_device_index <INDEX>

通过索引指定音频设备。会覆盖输入文件名中给出的任何内容。

-video_device_id <ID>

通过带前缀的标识符指定视频设备，如 -list_devices 所示：uid:<UID> 按 AVFoundation 唯一 ID 选择， serial:<SERIAL> 按 USB 序列号选择。UVC 设备的唯一 ID 在重新启动后可能不稳定。只有 UVC 设备会提供序列号。 会覆盖输入文件名中给出的任何内容。

-audio_device_id <ID>

通过带前缀的标识符指定音频设备。参见 -video_device_id；对于音频，序列号仅在 符合类规范的 USB 设备上可用。

-pixel_format <FORMAT>

请求视频设备使用特定的像素格式。 如果指定的格式不受支持，则会给出可用格式列表， 并改用该列表中的第一个。可用的像素格式有： monob, rgb555be, rgb555le, rgb565be, rgb565le, rgb24, bgr24, 0rgb, bgr0, 0bgr, rgb0, bgr48be, uyvy422, yuva444p, yuva444p16le, yuv444p, yuv422p16, yuv422p10, yuv444p10, yuv420p, nv12, yuyv422, gray

-framerate

设置采集帧率。默认为 ntsc，对应 帧率 30000/1001。

-video_size

设置视频帧尺寸。

-capture_cursor

采集鼠标指针。默认为 0。

-capture_mouse_clicks

采集屏幕上的鼠标点击。默认为 0。

-capture_raw_data

采集原始设备数据。默认为 0。 使用此选项可能会导致接收到传递给 AVFoundation 框架的底层数据。例如，对于向该框架发送原始 DV 数据的复用设备（如基于磁带的摄录一体机），将此选项设为 false 只会得到按指定像素格式采集的已提取视频帧。将此选项设为 true 则会原样接收原始 DV 流。

3.3.2 示例# TOC

  • 打印 AVFoundation 支持的设备列表并退出： 
    $ ffmpeg -f avfoundation -list_devices true -i ""
  • 从视频设备 0 录制视频、从音频设备 0 录制音频，写入 out.avi： 
    $ ffmpeg -f avfoundation -i "0:0" out.avi
  • 从视频设备 2 录制视频、从音频设备 1 录制音频，写入 out.avi： 
    $ ffmpeg -f avfoundation -video_device_index 2 -i ":1" out.avi
  • 使用像素格式 bgr0 从系统默认视频设备录制视频，且不录制任何音频，写入 out.avi： 
    $ ffmpeg -f avfoundation -pixel_format bgr0 -i "default:none" out.avi
  • 从合适的输入设备录制原始 DV 数据，并将输出写入 out.dv： 
    $ ffmpeg -f avfoundation -capture_raw_data true -i "zr100:none" out.dv

3.4 decklink# TOC

decklink 输入设备为 Blackmagic DeckLink 设备提供采集能力。

要启用此输入设备，你需要 Blackmagic DeckLink SDK，并 需要使用适当的 --extra-cflags 和 --extra-ldflags 进行配置。 在 Windows 上，你需要通过 widl 运行 IDL 文件。

DeckLink 对它所支持的格式非常挑剔。输入的 像素格式可通过 raw_format 设置。 帧率和视频尺寸必须针对你的设备用 -list_formats 1 来确定。音频采样率始终为 48 kHz， 声道数可以是 2、8 或 16。请注意，所有音频声道都被打包在单条 音轨中。

3.4.1 选项# TOC

list_devices

若设为 true，则打印设备列表并退出。 默认为 false。此选项已弃用，请使用 ffmpeg 的 -sources 选项来列出可用的输入设备。

list_formats

若设为 true，则打印受支持的格式列表并退出。 默认为 false。

format_code <FourCC>

这将把输入视频格式设置为 FourCC 所指定的格式。要查看 你的设备所支持的值，请使用 list_formats。 请注意，有一个 FourCC 'pal ' 也可以 写作 pal（3 个字母）。 默认行为是自动检测输入视频格式， 前提是硬件支持此功能。

raw_format

设置所采集视频的像素格式。 可用值有：

‘auto’

这是默认值，表示如果使用格式 自动检测则为 8 位 YUV 422 或 8 位 ARGB，否则为 8 位 YUV 422。

‘uyvy422’

8 位 YUV 422。

‘yuv422p10’

10 位 YUV 422。

‘argb’

8 位 RGB。

‘bgra’

8 位 RGB。

‘rgb10’

10 位 RGB。

teletext_lines

若设为非零值，则会从 垂直辅助数据中额外采集一路图文电视流。SD PAL（576i）和 HD（1080i 或 1080p） 信号源均受支持。对于 HD 信号源，会解码 OP47 数据包。

此选项是所采集 SD PAL VBI 行的位掩码，具体为第 6 到 22 行，以及第 318 到 335 行。第 6 行是掩码中的最低有效位。所选 但不含图文电视信息的行将被忽略。你可以使用 特殊的 all 常量来选择所有可能的行，或使用 standard 跳过第 6、318 和 319 行，这些行并非与 所有接收机兼容。

对于 SD 信号源，ffmpeg 需要使用 --enable-libzvbi 编译。对于 HD 信号源，在较旧（4K 之前）的 DeckLink 卡型号上必须以 10 位模式采集。

channels

定义要采集的音频声道数。必须为 ‘2’、‘8’ 或 ‘16’。 默认为 ‘2’。

duplex_mode

设置 decklink 设备的双工/配置文件模式。必须为 ‘unset’、‘half’、‘full’、 ‘one_sub_device_full’、‘one_sub_device_half’、‘two_sub_device_full’、 ‘four_sub_device_half’ 默认为 ‘unset’。

注意：DeckLink SDK 11.0 已将 duplex 属性替换为 profile 属性。 对于 DeckLink Duo 2 和 DeckLink Quad 2，任意 2 个使用相同连接器的子设备共享一个配置文件。对于 DeckLink 8K Pro，一个配置文件 由全部 4 个子设备共享。因此 DeckLink 8K Pro 支持四个配置文件。

DeckLink 8K Pro（使用 DeckLink SDK >= 11.0）的有效配置文件模式： ‘one_sub_device_full’、‘one_sub_device_half’、‘two_sub_device_full’、 ‘four_sub_device_half’

DeckLink Quad 2 和 DeckLink Duo 2 的有效配置文件模式： ‘half’、‘full’

timecode_format

要包含在帧和视频流元数据中的时间码类型。必须为 ‘none’、‘rp188vitc’、‘rp188vitc2’、‘rp188ltc’、 ‘rp188hfr’、‘rp188any’、‘vitc’、‘vitc2’ 或 ‘serial’。 默认为 ‘none’（不包含）。

为了正确支持 50/60 fps 时间码，所查询的 ‘rp188any’ 时间码类型的顺序对于 >30 fps 的内容为 HFR、VITC1、VITC2 和 LTC。请注意，这与 DeckLink API 使用的顺序略有不同，后者为 HFR、VITC1、LTC、VITC2。

video_input

设置视频输入源。必须为 ‘unset’、‘sdi’、‘hdmi’、 ‘optical_sdi’、‘component’、‘composite’ 或 ‘s_video’。 默认为 ‘unset’。

audio_input

设置音频输入源。必须为 ‘unset’、‘embedded’、 ‘aes_ebu’、‘analog’、‘analog_xlr’、‘analog_rca’ 或 ‘microphone’。默认为 ‘unset’。

video_pts

设置视频数据包时间戳来源。必须为 ‘video’、‘audio’、 ‘reference’、‘wallclock’ 或 ‘abs_wallclock’。 默认为 ‘video’。

audio_pts

设置音频数据包时间戳来源。必须为 ‘video’、‘audio’、 ‘reference’、‘wallclock’ 或 ‘abs_wallclock’。 默认为 ‘audio’。

draw_bars

若设为 ‘true’，则在信号丢失时绘制彩条。 默认为 ‘true’。 此选项已弃用，请使用 signal_loss_action 选项。

signal_loss_action

设置信号丢失时要采取的操作。接受 以下值之一：

1, none

信号丢失时不执行任何操作。这通常会导致黑帧。

2, bars

信号丢失时绘制彩条。仅支持 8 位输入信号。

3, repeat

信号丢失时重复最后一帧视频帧。

默认为 ‘bars’。

queue_size

设置输入缓冲区的最大字节数。如果缓冲达到此值， 后续到达的帧将被丢弃。 默认为 ‘1073741824’。

audio_depth

设置音频采样位深。必须为 ‘16’ 或 ‘32’。 默认为 ‘16’。

decklink_copyts

若设为 true，则时间戳按原样转发，不扣除 初始偏移量。 默认为 false。

timestamp_align

采集开始时间对齐，单位为秒。若设为非零值，输入帧将被 丢弃，直到系统时间戳与配置的值对齐。 最多可容忍一帧时长的对齐差异。 这对于在 N 个不同 硬件设备（部署用于 ’N-way’ 冗余）之间保持输入同步很有用。不同硬件设备的系统时间 应通过 NTP 或 PTP 等协议同步， 然后再使用此选项。 请注意，此方法并非万无一失。在某些边界情况下，输入 同步可能因操作系统中的线程调度抖动而不会发生。 同步偏差可能为 1 帧，或在更少见的情况下为 timestamp_align 秒。 默认为 ‘0’。

wait_for_tc (bool)

丢弃帧，直到收到带时间码的帧。有时串行时间码 不会随首个输入帧一起收到。如果发生这种情况，所存储的流 时间码将不准确。如果此选项设为 true，则会丢弃输入帧， 直到收到带时间码的帧为止。 必须指定 timecode_format 选项。 默认为 false。

enable_klv(bool)

若设为 true，则从 VANC 中提取 KLV 数据并输出 KLV 数据包。 KLV VANC 数据包根据 MID 和 PSC 字段进行合并，并聚合 成一个 KLV 数据包。 默认为 false。

3.4.2 示例# TOC

  • 列出输入设备： 
    ffmpeg -sources decklink
  • 列出支持的格式： 
    ffmpeg -f decklink -list_formats 1 -i 'Intensity Pro'
  • 以 1080i50 采集视频片段： 
    ffmpeg -format_code Hi50 -f decklink -i 'Intensity Pro' -c:a copy -c:v copy output.avi
  • 以 1080i50 10 位采集视频片段： 
    ffmpeg -raw_format yuv422p10 -format_code Hi50 -f decklink -i 'UltraStudio Mini Recorder' -c:a copy -c:v copy output.avi
  • 以 1080i50 采集带 16 个音频声道的视频片段： 
    ffmpeg -channels 16 -format_code Hi50 -f decklink -i 'UltraStudio Mini Recorder' -c:a copy -c:v copy output.avi

3.5 dshow# TOC

Windows DirectShow 输入设备。

当 FFmpeg 使用 mingw-w64 项目构建时，DirectShow 支持会被启用。 目前仅支持音频和视频设备。

多个设备可以作为独立的输入打开，但它们也可以 在同一个输入上打开，这应当能改善它们之间的同步性。

输入名称应采用以下格式： 

TYPE=NAME[:TYPE=NAME]

其中 TYPE 可以是 audio 或 video， 而 NAME 是设备的名称或替代名称。

3.5.1 选项# TOC

如果未指定任何选项，则使用设备的默认值。 如果设备不支持所请求的选项，它将 打开失败。

video_size

设置采集视频的视频尺寸。

framerate

设置采集视频的帧率。

sample_rate

设置所采集音频的采样率（单位为 Hz）。

sample_size

设置所采集音频的样本大小（单位为位）。

channels

设置所采集音频的声道数。

list_devices

若设为 true，则打印设备列表并退出。

list_options

若设为 true，则打印所选设备的选项列表 并退出。

video_device_number

为同名设备设置视频设备编号（从 0 开始， 默认为 0）。

audio_device_number

为同名设备设置音频设备编号（从 0 开始， 默认为 0）。

pixel_format

选择供 DirectShow 使用的像素格式。仅当 未设置视频编解码器或将其设为 rawvideo 时才能设置此项。

audio_buffer_size

以毫秒为单位设置音频设备缓冲区大小（取决于设备，它会直接影响 延迟）。 默认使用音频设备的 默认缓冲区大小（通常是 500ms 的某个倍数）。 将此值设得过低会降低性能。 另请参见 http://msdn.microsoft.com/en-us/library/windows/desktop/dd377582(v=vs.85).aspx

video_pin_name

按名称或替代名称选择要使用的视频采集引脚。

audio_pin_name

按名称或替代名称选择要使用的音频采集引脚。

crossbar_video_input_pin_number

为 crossbar 设备选择视频输入引脚编号。它将 路由到 crossbar 设备的 Video Decoder 输出引脚。 注意，更改此值会影响后续调用 （设置新的默认值），直到系统重启为止。

crossbar_audio_input_pin_number

为 crossbar 设备选择音频输入引脚编号。它将 路由到 crossbar 设备的 Audio Decoder 输出引脚。 注意，更改此值会影响后续调用 （设置新的默认值），直到系统重启为止。

show_video_device_dialog

3.7 gdigrab# TOC

基于 Win32 GDI 的屏幕采集设备。

该设备允许你在 Windows 上采集显示器的一个区域。

title=window_title

ffmpeg -f gdigrab -framerate 6 -offset_x 10 -offset_y 20 -video_size vga -i desktop out.mpg

ffmpeg -f gdigrab -framerate 6 -i title=Calculator out.mpg

3.8 iec61883# TOC

iec61883 采集设备支持从通过 IEEE1394（FireWire）连接的视频设备采集， 它使用 libiec61883 和新的 Linux FireWire 协议栈（juju）。这是 Linux 内核 2.6.37 及更高版本中默认的 DV/HDV 输入方法， 因为旧的 FireWire 协议栈已被移除。

3.9 jack# TOC

JACK 输入设备。

要在配置时启用该输入设备，系统上需要安装 libjack。

一个 JACK 输入设备会创建一个或多个 JACK 可写客户端，每个 音频声道一个，名称为 client_name:input_N，其中 client_name 是应用程序提供的名称，N 是标识声道的编号。 每个可写客户端都会把获取到的数据发送给 FFmpeg 输入 设备。

创建了一个或多个 JACK 可读客户端后，需要 把它们连接到一个或多个 JACK 可写客户端。

要连接或断开 JACK 客户端，可以使用 jack_connect 和 jack_disconnect 程序，也可以通过图形界面来完成， 例如使用 qjackctl。

要列出 JACK 客户端及其属性，可以调用命令 jack_lsp。

下面是一个示例，展示如何用 ffmpeg 采集一个 JACK 可读客户端。 

# Create a JACK writable client with name "ffmpeg".
$ ffmpeg -f jack -i ffmpeg -y out.wav

# Start the sample jack_metro readable client.
$ jack_metro -b 120 -d 0.2 -f 4000

# List the current JACK clients.
$ jack_lsp -c
system:capture_1
system:capture_2
system:playback_1
system:playback_2
ffmpeg:input_1
metro:120_bpm

# Connect metro to the ffmpeg writable client.
$ jack_connect metro:120_bpm ffmpeg:input_1

更多信息请参阅： http://jackaudio.org/

channels

设置声道数。默认值为 2。

3.11 lavfi# TOC

Libavfilter 输入虚拟设备。

该输入设备从 libavfilter 滤镜图的 打开输出端口读取数据。

对于滤镜图的每一个打开的输出，该输入设备都会创建一个 对应的流，并映射到所生成的输出。 滤镜图通过选项 graph 指定。

3.11.1 选项# TOC

graph

指定要用作输入的滤镜图。每个视频打开的输出都必须 用形如 "outN" 的唯一字符串标记，其中 N 是 一个从 0 开始的编号，对应该设备生成的 映射输入流。 第一个未标记的输出会自动被赋予 "out0" 标签，但其它所有输出都需要显式指定。

可以在输出标签后附加后缀 "+subcc"，以创建一个额外的 流，其中携带附加到该输出的闭路字幕数据包 （实验性；目前仅适用于 EIA-608 / CEA-708）。 subcc 流在所有普通流之后创建，顺序与 对应的流一致。 例如，如果有 "out19+subcc"、"out7+subcc" 以及直到 "out42" 的各流，则 流 #43 是流 #7 的 subcc，流 #44 是流 #19 的 subcc。

如果未指定，则默认为为输入 设备指定的文件名。

graph_file

设置要读取并发送到其它滤镜的滤镜图文件名。 滤镜图的语法与 选项 graph 所指定的语法相同。

dumpgraph

把滤镜图转储到 stderr。

3.11.2 示例# TOC

  • 创建一个彩色视频流，并用 ffplay 播放： 
    ffplay -f lavfi -graph "color=c=pink [out0]" dummy
  • 与上一个示例相同，但使用文件名来指定滤镜图 描述，并省略 "out0" 标签： 
    ffplay -f lavfi color=c=pink
  • 创建三个不同的视频测试滤镜源并播放它们： 
    ffplay -f lavfi -graph "testsrc [out0]; testsrc,hflip [out1]; testsrc,negate [out2]" test3
  • 使用 amovie 源从文件中读取音频流，并用 ffplay 播放： 
    ffplay -f lavfi "amovie=test.wav"
  • 读取一个音频流和一个视频流，并用 ffplay 播放： 
    ffplay -f lavfi "movie=test.avi[out0];amovie=test.wav[out1]"
  • 把解码后的帧转储为图像，并把闭路字幕转储为 RCWT 备份： 
    ffmpeg -f lavfi -i "movie=test.ts[out0+subcc]" -map v frame%08d.png -map s -c copy -f rcwt subcc.bin

3.20 x11grab# TOC

X11 视频输入设备。

要在配置期间启用此输入设备，系统中需要安装 libxcb。它会在配置期间被自动检测到。

该设备可用于采集 X11 显示器的某个区域。

作为输入传入的文件名具有以下语法： 

[hostname]:display_number.screen_number[+x_offset,y_offset]

hostname:display_number.screen_number 指定要采集的屏幕的 X11 显示名称。hostname 可以省略，默认为 "localhost"。环境变量 DISPLAY 包含默认显示名称。

x_offset 和 y_offset 指定所采集区域相对于 X11 屏幕左上边界的偏移量。它们默认为 0。

请查阅 X11 文档（例如 man X）以获取更详细的信息。

使用 xdpyinfo 程序可以获取有关 X11 显示器属性的基本信息（例如用 grep 查找 "name" 或 "dimensions"）。

例如，从 :0.0 采集，使用 ffmpeg： 

ffmpeg -f x11grab -framerate 25 -video_size cif -i :0.0 out.mpg

在位置 10,20 采集： 

ffmpeg -f x11grab -framerate 25 -video_size cif -i :0.0+10,20 out.mpg

select_region

指定是否使用指针以图形方式选择采集区域。值为 1 时会提示用户通过点击并拖动来以图形方式选择采集区域。仅单击而不拖动将选择整个屏幕。宽度或高度为零的区域也将选择整个屏幕。该选项会覆盖 video_size、grab_x 和 grab_y 选项。默认值为 0。

该选项会禁用 follow_mouse 和 select_region 选项。

grab_y

hostname 指定显示器实际连接到的 主机名。number 指定该主机上 显示服务器的编号。screen_number 指定 该服务器上要使用的屏幕。

如果未指定，则默认为 DISPLAY 环境变量的 值。

例如，dual-headed:0.1 将指定名为 “dual-headed” 的机器上 显示器 0 的屏幕 1。

关于显示名格式的更详细信息，请查阅 X11 规范。

window_id

当设置为非零值时，设备不会创建新窗口， 而是使用所提供的 window_id 对应的已有窗口。默认情况下 该选项被设置为零，设备会创建自己的窗口。

window_size

设置所创建窗口的大小，可以是 widthxheight 形式的字符串，也可以是视频尺寸缩写。如果 未指定，则默认为输入视频的尺寸。 当设置了 window_id 时忽略此项。

window_x
window_y

设置所创建窗口的 X 和 Y 偏移。它们默认 都被设置为 0。这些值可能会被窗口管理器忽略。 当设置了 window_id 时忽略此项。

window_title

设置窗口标题，若未指定则默认为输出设备所指定的 文件名。当设置了 window_id 时被忽略。

有关 XVideo 的更多信息，请参见 http://www.x.org/。
