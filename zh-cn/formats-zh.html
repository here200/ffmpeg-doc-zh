本文档介绍所支持的格式（复用器与解复用器） 由 libavformat 库提供。

2 格式选项# TOC

libavformat 库提供了一些通用的全局选项，这些选项 可以在所有复用器和解复用器上设置。此外，每个复用器或 解复用器可能支持所谓的私有选项，这些选项特定于 该组件。

可以通过在 FFmpeg 工具中指定 -option value 来设置选项， 或者在 AVFormatContext 选项中显式设置该值，或使用 libavutil/opt.h API 进行编程调用。

支持的选项列表如下：

avioflags flags (输入/输出)

可能的值：

‘direct’

减少缓冲。

probesize integer (输入)

以字节为单位设置探测大小，即为了获取 流信息而需要分析的数据大小。较高的值可以在信息分散于流中时 检测到更多信息，但会增加延迟。 必须是不小于 32 的整数。默认值为 5000000。

max_probe_packets integer (输入)

设置探测编解码器时缓冲的数据包最大数量。 默认值为 2500 个数据包。

packetsize integer (输出)

设置数据包大小。

fflags flags

设置格式标志。其中一些仅针对有限数量的格式实现。

输入文件可能的值：

‘discardcorrupt’

丢弃损坏的数据包。

‘fastseek’

为某些格式启用快速但不精确的定位。

‘genpts’

如果存在 DTS，则生成缺失的 PTS。

‘igndts’

如果同时也设置了 PTS，则忽略 DTS。在设置了 PTS 的情况下，DTS 值 会被设为 NOPTS。当设置了 nofillin 标志时，此选项被忽略。

‘ignidx’

忽略索引。

‘nobuffer’

减少在初始输入流分析期间由缓冲引入的延迟。

‘nofillin’

不要填充数据包字段中可以精确计算的缺失值。

‘noparse’

禁用 AVParsers，这还需要 +nofillin。

‘sortdts’

尝试按 DTS 交织输出数据包。目前仅对带索引的 AVI 可用。

输出文件可能的值：

‘autobsf’

按输出格式的要求自动应用比特流滤波器。默认启用。

‘bitexact’

只写入与平台、构建和时间无关的数据。 这可确保文件和数据的校验和可重现，并在不同 平台之间保持一致。其主要用途是回归测试。

‘flush_packets’

立即写出数据包。

‘shortest’

在最短的流结束时停止复用。 为避免在 EOF 之前冲刷较长的流，可能需要增大 max_interleave_delta。

seek2any integer (输入)

若设为 1，则在支持时允许在解复用器层定位到非关键帧。 默认值为 0。

analyzeduration integer (输入)

指定为探测输入而分析的微秒数。较高的 值可以检测到更准确的信息，但会 增加延迟。默认值为 5,000,000 微秒 = 5 秒。

cryptokey hexadecimal string (输入)

设置解密密钥。

indexmem integer (输入)

设置用于时间戳索引的最大内存（每个流）。

rtbufsize integer (输入)

设置用于缓冲实时帧的最大内存。

fdebug flags (输入/输出)

打印特定的调试信息。

可能的值：

‘ts’

打印时间戳信息。

‘id3v2’

在解复用包含 ID3v2 标签的文件时打印 ID3v2 帧数据。

max_delay integer (输入/输出)

以微秒为单位设置最大复用或解复用延迟。

fpsprobesize integer (输入)

设置用于探测 fps 的帧数。

audio_preload integer (输出)

设置音频数据包应提前交织的微秒数。

chunk_duration integer (输出)

设置每个数据块的微秒数。

chunk_size integer (输出)

设置每个数据块的字节大小。

err_detect, f_err_detect flags (输入)

设置错误检测标志。f_err_detect 已弃用， 只能通过 ffmpeg 工具使用。

可能的值：

‘crccheck’

校验内嵌的 CRC。

‘bitstream’

检测比特流规范偏差。

‘buffer’

检测不正确的比特流长度。

‘explode’

检测到轻微错误时中止解码。

‘careful’

把违反规范且在实际中未曾出现的情况 视为错误。

‘compliant’

把所有不符合规范的情况视为错误。

‘aggressive’

把正常的编码器不应做的事情视为错误。

max_interleave_delta integer (输出)

设置用于交织的最大缓冲时长。该时长 以微秒表示，默认为 10000000（10 秒）。

为确保所有流都被正确交织，libavformat 会 等到每个流都至少有一个数据包后，才真正 将任何数据包写入输出文件。当某些流是 "稀疏的"（即相邻数据包之间存在较大间隔）时，这 可能导致过度缓冲。

该字段指定复用队列中第一个和最后一个数据包 时间戳之间的最大差值，超过该值时 libavformat 将输出一个数据包，而不管它是否已为所有流 排队了数据包。

若设为 0，libavformat 将继续缓冲数据包，直到它 为每个流都有一个数据包为止，而不考虑已缓冲 数据包之间的最大时间戳差值。

use_wallclock_as_timestamps integer (输入)

若设为 1，则使用墙上时钟作为时间戳。默认值为 0。

avoid_negative_ts integer (输出)

可能的值：

‘make_non_negative’

平移时间戳使其非负。 另请注意，这仅影响开头的负时间戳，而 不影响非单调的负时间戳。

‘make_zero’

平移时间戳，使第一个时间戳为 0。

‘auto (default)’

在目标格式要求时启用平移。

‘disabled’

禁用时间戳平移。

启用平移时，所有输出时间戳都平移相同的 量。与不平移时相比，音频、视频和字幕的 失同步以及相对时间戳差值都 保持不变。

skip_initial_bytes integer (输入)

若设为 1，则设置读取头部和帧之前要跳过的字节数。 默认值为 0。

correct_ts_overflow integer (输入)

若设为 1，则修正单个时间戳溢出。默认值为 1。

flush_packets integer (输出)

在每个数据包之后冲刷底层 I/O 流。默认值为 -1（auto）， 表示由底层协议决定；1 启用该功能，其 效果是减少延迟；0 禁用该功能，在某些情况下 可能提高 IO 吞吐量。

output_ts_offset offset (输出)

设置输出时间偏移。

offset 必须是一个时长规格， 参见 ffmpeg-utils(1) 手册中的 Time duration 一节。

该偏移由复用器加到输出时间戳上。

指定正偏移意味着相应的流会被延迟 offset 所指定的时长。默认 值为 0（表示不应用任何偏移）。

format_whitelist list (输入)

以","分隔的允许的解复用器列表。默认全部允许。

dump_separator string (输入)

用于分隔命令行上打印的关于 流参数的字段的分隔符。 例如，用换行和缩进来分隔字段： 

ffprobe -dump_separator "
                          "  -i ~/videos/matrixbench_mpeg2.mpg
max_streams integer (输入)

指定流的最大数量。这可用于拒绝那些 因流数量过多而需要过多资源的文件。

skip_estimate_duration_from_pts bool (输入)

如果估计输入时长需要在文件末尾对 PTS 进行额外探测，则跳过该估计。 目前适用于 MPEG-PS 和 MPEG-TS。

duration_probesize integer (输入)

设置在确实需要在文件末尾对 PTS 进行额外探测（目前为 MPEG-PS 和 MPEG-TS）时， 用于估计输入时长的探测大小（以字节为单位）。 它面向那些本身就对更好的时长探测感兴趣的用户，或者例如 因为使用 concat 解复用器而间接受益的用户。 典型的用例是高码率、高视频缓冲且 结尾清理时视频和音频 PTS 相近的 MPEG-TS CBR：在这种情况下，最后一个 视频数据包与最后一个音频数据包之间较大的 物理间隔使得必须读取大量字节才能获得视频流时长。 另一个用例是默认探测行为由于帧重排序而只到达单个视频帧， 而该帧并非流的最后一帧，因此时长不准确。 设置此选项即使对较小的文件也会有性能影响，因为探测 大小是固定的。 默认行为是一种通用目的的折中方案，具有很大的自适应性，但探测大小 不会不惜一切代价地扩展来获取流时长。 必须是不小于 1 的整数，或为 0 表示使用默认行为。

strict, f_strict integer (输入/输出)

指定遵循标准的严格程度。f_strict 已弃用， 只能通过 ffmpeg 工具使用。

可能的值：

‘very’

严格遵循规范或参考软件的更旧、更严格的版本

‘strict’

无论后果如何，都严格遵循规范中的所有内容

‘normal’
‘unofficial’

允许非官方扩展

‘experimental’

允许非标准化的实验性内容，以及实验性 （未完成/开发中/未经充分测试）的解码器和编码器。 注意：实验性解码器可能带来安全风险，不要用它 解码不受信任的输入。

2.1 格式流标识符# TOC

格式流标识符允许选择一个或多个 匹配特定属性的流。

流标识符的确切语义由 avformat_match_stream_specifier() 函数定义，该函数声明于 libavformat/avformat.h 头文件中，并在 ffmpeg(1) 手册中的 Stream specifiers 一节中说明。

3 解复用器# TOC

解复用器是 FFmpeg 中经过配置的组件，可以读取 来自某种特定类型的文件的多媒体流。

配置 FFmpeg 构建时，所有受支持的解复用器 默认都会启用。你可以使用配置选项 --list-demuxers 列出所有可用的解复用器。

你可以使用配置选项 --disable-demuxers 禁用所有解复用器，并用 选项 --enable-demuxer=DEMUXER 选择性地启用单个解复用器，或用 选项 --disable-demuxer=DEMUXER 将其禁用。

ff* 工具的选项 -demuxers 会显示 已启用的解复用器列表。使用 -formats 可以查看 已启用的解复用器与复用器的合并列表。

下面介绍当前可用的一些解复用器。

3.1 aa# TOC

Audible Format 2、3 和 4 解复用器。

该解复用器用于解复用 Audible Format 2、3 和 4（.aa）文件。

3.2 aac# TOC

原始音频数据传输流 AAC 解复用器。

该解复用器用于解复用包含单个 AAC 流的 ADTS 输入， 以及其中任何 ID3v1/2 或 APE 标签。

3.3 apng# TOC

动画便携式网络图形解复用器。

该解复用器用于解复用 APNG 文件。 除 PNG 签名之外的所有头部，直到（但不包括）第一个 fcTL 块为止，都作为 extradata 传输。 帧随后按两个 fcTL 块之间的所有块来划分，或按 最后一个 fcTL 与 IEND 块之间的所有块来划分。

-ignore_loop bool

如果设置，则忽略文件中的循环变量。默认启用。

-max_fps int

最大帧率，以帧每秒为单位。默认值为 0 表示不施加限制。

-default_fps int

当文件中未指定时使用的默认帧率，以帧每秒为单位 （0 表示尽可能快）。默认值为 15。

3.4 asf# TOC

高级系统格式解复用器。

该解复用器用于解复用 ASF 文件和 MMS 网络流。

-no_resync_search bool

不要通过查找某个可选的起始码来尝试重新同步。

3.5 concat# TOC

虚拟拼接脚本解复用器。

该解复用器从文本文件中读取文件列表和其他指令， 并将它们依次解复用，就好像它们的所有数据包都被 复用在一起一样。

文件中的时间戳会被调整，使第一个文件从 0 开始， 每个后续文件都从前一个文件结束的位置开始。注意这是 全局进行的，如果所有流没有完全相同的长度， 就可能产生间隙。

所有文件必须具有相同的流（相同的编解码器、相同的时基等）。

每个文件的时长用于调整下一个文件的时间戳： 如果该时长不正确（例如因为它是用码率计算出来的， 或因为文件被截断），就可能导致瑕疵。 duration 指令可用于覆盖存储在每个 文件中的时长。

3.5.1 语法# TOC

该脚本是一个扩展 ASCII 编码的文本文件，每行一条指令。 空行、行首空格以及以 ’#’ 开头的行都会被忽略。 可以识别以下指令：

file path

要读取的文件的路径；特殊字符和空格必须用 反斜杠或单引号转义。

所有后续与文件相关的指令都作用于该文件。

ffconcat version 1.0

标识脚本类型和版本。

为了让 FFmpeg 自动识别该格式，这条指令必须 原样（不要有多余空格或字节顺序标记）出现在 脚本的第一行。

duration dur

文件的时长。这一信息可以从文件中指定； 在此处指定可能更高效，或者在文件中的信息 不可用或不准确时有所帮助。

如果为所有文件都设置了时长，就可以在整个 拼接后的视频中进行定位。

inpoint timestamp

文件的入点。当解复用器打开文件时，它会立即定位到 指定的时间戳。定位的方式要使所有流都能 在入点处成功呈现。

该指令对帧内编码编解码器效果最好，因为对于非帧内 编码的编解码器，你通常会在实际入点之前得到额外的数据包， 而解码后的内容也很可能包含入点之前的帧。

对于每个文件，文件入点之前的数据包的时间戳会小于 该文件计算出的起始时间戳（对于第一个文件则为负值）， 并且文件的时长（如果未由 duration 指令指定）会根据其指定的入点而减少。

由于指定入点之前可能存在数据包，数据包时间戳 在两个拼接文件之间可能会重叠。

outpoint timestamp

文件的出点。当解复用器在任意流中到达指定的解码 时间戳时，它会将其视为文件结束条件，并 跳过当前数据包以及所有流中剩余的全部数据包。

出点是独占的，这意味着解复用器不会输出 解码时间戳大于或等于出点的数据包。

该指令对帧内编码编解码器以及所有流紧密交织的 格式效果最好。对于非帧内编码的编解码器，你通常会得到 呈现时间戳在出点之后的额外数据包，因此 解码后的内容也很可能包含出点之后的帧。如果你的 流没有紧密交织，你可能无法在出点之前获得所有流的 全部数据包，并且可能只能解码最早的那个 流直到出点为止。

文件的时长（如果未由 duration 指令指定）会根据其指定的出点而减少。

file_packet_metadata key=value

3.7 dvdvideo# TOC

DVD-Video 解复用器，由 libdvdnav 和 libdvdread 提供支持。

可以直接将 DVD 标题（具体来说是顺序 PGC）导入 转换流水线。菜单素材（例如背景视频或音频） 也可以在给定菜单坐标的情况下解复用（尽力而为）。

接受块设备（DVD 驱动器）、ISO 文件和目录结构。 在这些输入之一前面加上 -f dvdvideo 即可启用。

该解复用器不包含任何形式的解密代码。处理加密 DVD 时 你需要自行负责，并且不应期望在这方面获得支持。

底层播放由 libdvdnav 处理，结构解析由 libdvdread 处理。 FFmpeg 必须启用 GPL 库支持，并带有 配置开关 --enable-libdvdnav 和 --enable-libdvdread。

你需要提供所需的 "title number" 或精确的 PGC/PG 坐标。 许多开源 DVD 播放器和工具可以帮助提供这一信息。 如果未指定，解复用器将默认使用标题 1，这对许多光盘都适用。 不过，由于该格式非常灵活，建议手动检查。 有许多光盘的制作方式很怪异，或者带有无效的头部。

如果输入是真实的 DVD 驱动器，请注意有些驱动器可能会 在读取光盘上的坏扇区时静默失败，返回随机比特， 这实际上是损坏的数据。这在老化或损坏的光盘上尤其常见。 需要第二遍读取和完整性检查才能检测出这种损坏。 这不是 FFmpeg 的问题。

3.7.1 背景# TOC

DVD-Video 并不是传统意义上可直接访问的线性容器格式。 相反，它允许对经过精心复用、存储在无文件头 VOB 文件中的 MPEG-PS 流 进行复杂且可编程的播放。 对最终用户而言，这些流被简单地称为 "titles"（标题），但实际的 逻辑播放顺序由标题内的一个或多个 "PGCs"（即 Program Group Chain，程序组链）定义。 PGC 又由多个 "PGs"（即 Program，程序）构成， 它们才是实际的视频片段（对于典型的视频长片而言，是按顺序排列的）。 PGC 结构以及流布局和元数据都存储在需要解析的 IFO 文件中。 更简单地说，PGC 可以看作是播放列表。

真正的 DVD 播放器依赖用户通过菜单进行 GUI 交互，并依靠内部 VM 来决定解复用的方向。通常，用户要么（通过菜单）自行导航， 要么自动被重定向到他们所选的 PGC。在此过程 以及随后的播放中，DVD 播放器的内部 VM 还会维护状态并 执行指令，这些指令可能在播放过程中跳转到不同的扇区。 这正是需要 libdvdnav 的原因，因为在许多情况下，仅对光盘上的 MPEG-PS 数据块（VOB）做线性读取并不足以产生正确的播放序列。

还有许多其他 DVD 结构（这是一个庞大的话题），此处不再讨论。 特别是 NAV 数据包，本解复用器会处理它们以构建精确的时间信息， 但不会将其作为流输出。若要从高层面上很好地理解，请参考： https://code.videolan.org/videolan/libdvdnav/-/blob/master/doc/dvd_structures

3.7.2 选项# TOC

本解复用器接受以下选项：

title int

要播放的标题编号。如果未设置 pgc 和 pg，则必须设置此项。 不适用于菜单。 默认值为 0（自动），目前它只选择第一个可用的标题（title 1）， 并就会产生的影响通知用户。

chapter_start int

起始的章节（即 PTT，part-of-title）编号。不适用于菜单。 默认值为 1。

chapter_end int

结束的章节（即 PTT，part-of-title）编号。不适用于菜单。 默认值为 0，这是一个特殊值，表示在最后一个可能的章节处结束。

angle int

视频角度编号，它实际上指的是一条额外的 视频流，该流由 VOB 中交织的交替帧组成。 不适用于菜单。 默认值为 1。

region int

用于播放的区域代码。某些光盘可能会用它来在不同区域默认以 特定角度播放。如果用作输入，此选项不会影响真实 DVD 驱动器的区域代码。 不适用于菜单。 默认值为 0，即 "world"。

menu bool

解复用菜单素材，而不是导航标题。需要菜单的精确坐标 （menu_lu、menu_vts、pgc、pg）。 默认值为 false。

menu_lu int

要解复用的菜单语言。在 DVD 中，菜单按语言分组。 默认值为 1，即第一个语言单元。

menu_vts int

菜单所在的 VTS；如果是 VMG 菜单（根级），则为 0。 默认值为 1，即第一个 VTS 的菜单。

pgc int

与 pg 配合使用时，用于开始播放的入口 PGC。 可替代设置 title。 目前不支持章节标记。 对于菜单必须显式设置。 默认值为 0，即根据 title 的值自动解析。

pg int

与 pgc 配合使用时，用于开始播放的入口 PG。 可替代设置 title。 目前不支持章节标记。 默认值为 1，即 PGC 的第一个 PG。

preindex bool

启用此项可获得准确的章节（PTT）标记和时长测量， 这需要一次较慢的二次读取，以便从 NAV 数据包中索引章节标记 时间戳。对于真实光驱而言，这是不理想的额外工作。 建议将此选项与存储在硬盘上的 DVD 结构副本一起使用，这样更快。 与 pgc 和 pg 不兼容。 默认值为 0，即 false。

trim bool

跳过开头的填充单元（即短于 1 秒的单元）。 许多光盘在 PGC 的开头都有填充片段， 其中的垃圾数据通常用于控制真实 DVD 播放器的 缓冲速度，此外没有其他实质性的数据价值。 不适用于菜单。 默认值为 1，即 true。

sequence

选择序列模式类型，用于指定由连续编号 索引的文件序列。

序列模式可以包含字符串 "%d" 或 "%0Nd"，它 指定了模式所匹配的每个文件名中代表顺序编号的字符所 处的位置。如果使用 "%d0Nd" 这种形式，则每个文件名中代表数字的字符串 会补零，而 N 是代表该数字的补零 位数总数。字面字符 ’%’ 可以用 字符串 "%%" 在模式中指定。

注意，模式不一定必须包含 "%d" 或 "%0Nd"，例如要转换单个图像文件 img.jpeg，可以使用以下命令： 

ffmpeg -i img.jpeg img.png

3.17 mcc# TOC

用于 MacCaption MCC 文件的解复用器，它支持 MCC 1.0 和 2.0 版本。 MCC 文件存储 VANC 数据，其中可以包含隐藏字幕（EIA-608 和 CEA-708）、辅助时间码、全景扫描数据等。 默认情况下，为了向后兼容，MCC 解复用器只提取 EIA-608 和 CEA-708 隐藏字幕并返回一个 EIA_608 流，忽略所有其它 VANC 数据。 你可以让它把全部 VANC 数据以 SMPTE_436M_ANC 数据流的形式返回，方法是设置 -eia608_extract 0

3.17.1 示例# TOC

    ffmpeg -i CC.mcc -c:s copy CC.scc

3.23 sbg# TOC

SBaGen 脚本解复用器。

此解复用器读取 SBaGen http://uazu.net/sbagen/ 所使用的脚本语言，用于生成双耳节拍会话。一个 SBG 脚本看起来像这样： 

-SE
a: 300-2.5/3 440+4.5/0
b: 300-2.5/0 440+4.5/3
off: -
NOW      == a
+0:07:00 == b
+0:14:00 == a
+0:21:00 == b
+0:30:00    off

SBG 脚本可以混用绝对时间戳和相对时间戳。如果脚本只使用 绝对时间戳（包括脚本开始时间）或只使用 相对时间戳，那么它的布局是固定的，转换也很 直接。另一方面，如果脚本混用了这两种 时间戳，那么相对时间戳的 NOW 参考值将取 自读取脚本时的当前时刻，而 脚本布局将根据该参考值被冻结。这意味着如果 脚本被直接播放，实际时间将与绝对时间戳一致， 误差不超过声卡时钟精度；但如果用户 以某种方式暂停播放或定位，所有时间都会相应地偏移。

4.4.1 分片# TOC

‘mov’、‘mp4’ 和 ‘ismv’ 复用器支持 分片。通常，MOV/MP4 文件将所有 数据包的全部元数据存储在一个位置。

这些数据通常写在文件末尾，但可以 通过向 -movflags 添加 +faststart，或使用 qt-faststart 工具， 将其移到开头以获得更好的播放效果）。

分片文件由若干分片组成，其中数据包和有关这些数据包的 元数据存储在一起。写入分片 文件的优点是即使写入 被中断，文件仍可解码（而普通 MOV/MP4 如果未 正确结束则无法解码），并且在写入很长的 文件时所需内存更少（因为写入普通 MOV/MP4 文件会在内存中保存每个 数据包的信息，直到文件被关闭）。缺点是 它与其他应用程序的兼容性较差。

通过设置定义 如何将文件切分为分片的选项之一即可启用分片：

frag_duration
frag_size
min_frag_duration
movflags +frag_keyframe
movflags +frag_custom

如果指定了多个条件，则当指定的条件之一 得到满足时就会切分分片。例外情况是 选项 min_frag_duration，它必须被满足， 其他条件才会生效。

4.28 crc# TOC

复用器的输出由单行组成，形式如下： CRC=0xCRC，其中 CRC 是一个十六进制数，左侧补 0 至 8 位数字，包含所有已解码输入帧的 CRC。

4.28.1 示例# TOC

    ffmpeg -i INPUT -f crc out.crc
  • 使用 ffmpeg 通过以下命令将 CRC 打印到 stdout： 
    ffmpeg -i INPUT -f crc -
  • 可以使用 ffmpeg 选择每一帧的输出格式，方法是 指定音频和视频编解码器及格式。例如，要计算 转换为 PCM unsigned 8-bit 的输入音频以及转换为 MPEG-2 视频的输入视频的 CRC，请使用以下命令： 
    ffmpeg -i INPUT -c:a pcm_u8 -c:v mpeg2video -f crc -

4.29 dash# TOC

Dynamic Adaptive Streaming over HTTP（DASH）复用器。

此复用器根据 MPEG-DASH 标准 ISO/IEC 23009-1:2014 及其后续标准 更新创建分片和清单文件。

更多信息请参见：

  • ISO DASH 规范：http://standards.iso.org/ittf/PubliclyAvailableStandards/c065274_ISO_IEC_23009-1_2014.zip
  • WebM DASH 规范：https://sites.google.com/a/webmproject.org/wiki/adaptive-streaming/webm-dash-specification

此复用器为每个流创建 MPD（Media Presentation Description） 清单文件和分片文件。分片文件放置在 MPD 清单文件所在的同一目录中。

分片文件名可能包含清单 SegmentTemplate 部分中使用的预定义标识符，这些标识符如该标准的 5.3.9.4.4 节所定义。

可用的标识符有 $RepresentationID$、$Number$、 $Bandwidth$ 和 $Time$。除标准标识符之外， 还支持 ffmpeg 专有的 $ext$ 标识符。 指定后，ffmpeg 会将文件名中的 $ext$ 替换为复用格式的扩展名，例如 mp4、 webm 等。

4.33 fifo# TOC

FIFO（先进先出）复用器。

‘fifo’ 伪复用器通过使用先进先出队列，并在单独的线程中 运行实际的复用器，从而将编码与复用 分离。

它与 tee 复用器结合使用时尤其有用，可用来将数据发送到多个 可靠性/写入速度/延迟各不相同的目标。

目标复用器可从输出名称中选择，或者通过 fifo_format 选项指定。

‘fifo’ 复用器在队列填满或输出失败时 （例如某个数据包无法写入输出）的行为 是可选的：

  • 输出可以被透明地重启，重试之间的延迟可配置， 其依据是真实时间或所处理流的时间。
  • 在临时故障期间可以阻塞编码，也可以继续处理，在 FIFO 队列填满时 透明地丢弃数据包。

API 用户应当注意，回调函数 （interrupt_callback、io_open 和 io_close）在用于 其 AVFormatContext 中时必须是线程安全的。

4.33.1 选项# TOC

如果发生故障，则尝试恢复输出。这在用于网络输出时 尤其有用，因为它可以透明地 重启流传输。默认情况下，此选项设为 false。

drop_pkts_on_overflow bool

如果设为 true，那么在 fifo 队列填满时，数据包将被 丢弃，而不会阻塞编码器。这使得可以在不延迟输入的情况下 继续流传输，代价是会 省略流的一部分。默认情况下此选项设为 false，因此在这类 情况下编码器将被阻塞，直到复用器处理了其中一些 数据包，且不会丢失任何一个。

指定格式名称。当无法从 输出名称后缀推断出格式名时很有用。

format_opts options

为底层复用器指定格式选项。复用器选项可以 用由 ’:’ 分隔的 key=value 对列表来指定。

max_recovery_attempts count

设置连续恢复失败的最大次数，超过该次数后 输出将永久失败。默认情况下此选项设为 0（无限制）。

queue_size size

以数据包数量为单位指定队列大小。默认值为 60。

recover_any_error bool

如果设为 true，则无论导致故障的错误类型如何， 都会尝试恢复。默认情况下此选项设为 false，并且在出现某些（通常是永久性）错误时， 即使把 attempt_recovery 选项设为 true，也不会尝试恢复。

recovery_wait_streamtime bool

如果设为 false，则在等待恢复尝试时使用真实时间 （即，将等待由 recovery_wait_time 选项所指定的时间之后才尝试恢复）。

如果设为 true，则改为考虑所处理流的时间 （即，在丢弃与 recovery_wait_time 选项相对应的数据包之后将尝试恢复）。

默认情况下此选项设为 false。

recovery_wait_time duration

指定在上一次恢复尝试失败后，进行下一次恢复尝试之前的 等待时间（秒）。默认值为 5。

restart_with_keyframe bool

指定在从队列溢出或故障中恢复后是否等待关键帧。 此选项默认设为 false。

timeshift duration

缓冲指定数量的数据包并延迟写入 输出。请注意，queue_size 选项的值必须 足够大，以存储用于时移的数据包。在输入结束时， fifo 缓冲会以实时速度冲刷。

4.33.2 示例# TOC

使用 ffmpeg 向 RTMP 服务器进行流传输，即使发生临时故障 （网络中断）也按实时速率继续处理该流， 并每秒尝试恢复流传输， 无限重试：

  -drop_pkts_on_overflow 1 -attempt_recovery 1 -recovery_wait_time 1 \
  -map 0:v -map 0:a rtmp://example.com/live/stream_name

4.39 framecrc# TOC

CRC 是一个用 0 填充至 8 位的十六进制数，其中包含该数据包的 CRC。

ffmpeg -i INPUT -f framecrc out.crc

ffmpeg -i INPUT -f framecrc -

参见 crc 复用器。

4.40 framehash# TOC

ffmpeg -i INPUT -f framehash out.sha256

4.46 hls# TOC

Apple HTTP Live Streaming 复用器，它根据 HTTP Live Streaming (HLS) 规范对 MPEG-TS 进行分片。

它会创建一个播放列表文件，以及一个或多个分片文件。输出文件名 指定播放列表文件名。

默认情况下，复用器会为产生的每个分片创建一个文件。这些文件 与播放列表同名，后跟一个顺序编号和一个 .ts 扩展名。

请确保在编码时要求使用闭合 GOP，并将 GOP 大小设置为符合你的分片时间约束。

例如，要使用 ffmpeg 转换一个输入文件： 

ffmpeg -i in.mkv -c:v h264 -flags +cgop -g 30 -hls_time 1 out.m3u8

此示例将生成播放列表 out.m3u8，以及分片文件： out0.ts、out1.ts、out2.ts 等。

另请参见 segment 复用器，它提供了更通用、 更灵活的分片器实现，可用于执行 HLS 分片。

4.46.1 选项# TOC

hls_init_time duration

设置初始目标分片长度。默认值为 0。

duration 必须是一个时间时长规格， 参见 ffmpeg-utils(1) 手册中的时间时长部分。

在首个 m3u8 列表中该时间过去之后，分片将在下一个关键帧处 切分。初始播放列表填满后，ffmpeg 将 按照等于 hls_time 的时长切分分片。

hls_time duration

设置目标分片长度。默认值为 2。

duration 必须是一个时间时长规格， 参见 ffmpeg-utils(1) 手册中的时间时长部分。 该时间过去之后，分片将在下一个关键帧处切分。

hls_list_size size

设置播放列表条目的最大数量。如果设置为 0，列表文件 将包含所有分片。默认值为 5。

hls_delete_threshold size

设置在被 hls_flags delete_segments 删除之前，保留在磁盘上的未引用分片数量。 增大该值可让客户端继续下载 最近在播放列表中引用过的分片。默认值为 1，意味着早于 hls_list_size+1 的分片将被删除。

hls_start_number_source source

根据指定的源设置播放列表序列号（#EXT-X-MEDIA-SEQUENCE）。 除非设置了 hls_flags single_file，否则它还指定分片和字幕文件名的 起始序列号的来源。无论如何，如果设置了 hls_flags append_list 且读取到的播放列表序列号大于指定的起始序列号， 则将使用该值作为起始值。

它接受以下取值：

generic (default)

根据 start_number 选项的值设置起始编号。

epoch

将起始编号设置为自 epoch（1970-01-01 00:00:00）以来的秒数。

epoch_us

将起始编号设置为自 epoch（1970-01-01 00:00:00）以来的微秒数。

datetime

根据当前日期/时间将起始编号设置为 YYYYmmddHHMMSS 格式。例如 20161231235759。

start_number number

从指定的 number 开始设置播放列表序列号（#EXT-X-MEDIA-SEQUENCE），此时 hls_start_number_source 的值为 generic。（这是默认情况。） 除非设置了 hls_flags single_file，否则它还指定分片和字幕文件名的起始序列号。 默认值为 0。

hls_allow_cache bool

显式设置客户端可以（1）还是不得（0）缓存媒体分片。

hls_base_url baseurl

将 baseurl 追加到播放列表的每个条目。 用于生成带绝对路径的播放列表。

请注意，播放列表序列号对每个分片必须是唯一的， 不要将其与分片文件名的序列号相混淆， 后者可以是循环的，例如在指定了 wrap 选项的 情况下。

hls_segment_filename filename

设置分片文件名。除非将 hls_flags 选项设置为 ‘single_file’，否则 filename 会被用作字符串格式，并在其后附加 分片编号。

例如： 

ffmpeg -i in.nut -hls_segment_filename 'file%03d.ts' out.m3u8

将生成播放列表 out.m3u8，以及分片文件： file000.ts、file001.ts、file002.ts 等。

filename 可以包含完整路径或相对路径规格， 但只有不含任何路径的文件名部分会包含在 m3u8 分片列表中。 如果指定了相对路径，则所创建分片 文件的路径将相对于当前工作目录。 当设置了 strftime_mkdir 时，filename 的整个展开值都将被写入 m3u8 分片列表。

当 var_stream_map 被设置为两个或更多变体流时， filename 模式中必须包含字符串 "%v"，该字符串将被 展开为所生成分片文件名中变体流索引的 位置。

例如： 

ffmpeg -i in.ts -b:v:0 1000k -b:v:1 256k -b:a:0 64k -b:a:1 32k \
  -map 0:v -map 0:a -map 0:v -map 0:a -f hls -var_stream_map "v:0,a:0 v:1,a:1" \
  -hls_segment_filename 'file_%v_%03d.ts' out_%v.m3u8

将生成播放列表分片文件集： file_0_000.ts、file_0_001.ts、file_0_002.ts 等，以及 file_1_000.ts、file_1_001.ts、file_1_002.ts 等。

字符串 "%v" 可以出现在文件名中，也可以出现在包含该文件的 最后一个目录名中，但只能出现在其中之一。（此外，%v 可以在最后一个 子目录或文件名中出现多次。）如果字符串 %v 出现在目录名中，则 会在展开目录名模式之后创建子目录。这 使得可以在子目录中创建与不同变体流 对应的分片。

例如： 

ffmpeg -i in.ts -b:v:0 1000k -b:v:1 256k -b:a:0 64k -b:a:1 32k \
  -map 0:v -map 0:a -map 0:v -map 0:a -f hls -var_stream_map "v:0,a:0 v:1,a:1" \
  -hls_segment_filename 'vs%v/file_%03d.ts' vs%v/out.m3u8

将生成播放列表分片文件集： vs0/file_000.ts、vs0/file_001.ts、vs0/file_002.ts 等，以及 vs1/file_000.ts、vs1/file_001.ts、vs1/file_002.ts 等。

strftime bool

对 filename 使用 strftime()，以本地时间展开分片文件名。 在该模式下分片编号也可用，但要使用它， 你需要在 hls_flag 中设置 ‘second_level_segment_index’， 并且 %%d 将是说明符。

例如： 

ffmpeg -i in.nut -strftime 1 -hls_segment_filename 'file-%Y%m%d-%s.ts' out.m3u8

将生成播放列表 out.m3u8，以及分片文件： file-20160215-1455569023.ts、file-20160215-1455569024.ts 等。 注意：在某些系统/环境中，%s 说明符不可用。 参见 strftime() 文档。

例如： 

ffmpeg -i in.nut -strftime 1 -hls_flags second_level_segment_index -hls_segment_filename 'file-%Y%m%d-%%04d.ts' out.m3u8

将生成播放列表 out.m3u8，以及分片文件： file-20160215-0001.ts、file-20160215-0002.ts 等。

strftime_mkdir bool

与 strftime 一起使用时，它将创建 hls_segment_filename 选项展开值中出现的所有子目录。

例如： 

ffmpeg -i in.nut -strftime 1 -strftime_mkdir 1 -hls_segment_filename '%Y%m%d/file-%Y%m%d-%s.ts' out.m3u8

将创建一个目录 201560215（如果它不存在），然后 生成播放列表 out.m3u8，以及分片文件： 20160215/file-20160215-1455569023.ts、 20160215/file-20160215-1455569024.ts 等。

例如： 

ffmpeg -i in.nut -strftime 1 -strftime_mkdir 1 -hls_segment_filename '%Y/%m/%d/file-%Y%m%d-%s.ts' out.m3u8

将创建目录层级 2016/02/15（如果其中任何一个不 存在），然后生成播放列表 out.m3u8，以及分片文件： 2016/02/15/file-20160215-1455569023.ts、 2016/02/15/file-20160215-1455569024.ts 等。

hls_segment_options options_list

使用 key_info_file 中的信息进行分片加密。key_info_file 的第一 行指定写入播放列表的密钥 URI。密钥 URL 用于在播放期间访问加密密钥。第二行 指定加密过程中用于获取密钥的密钥文件路径。密钥文件以二进制格式作为 16 个八位字节的单个紧凑数组读取。可选的第三行以十六进制字符串 指定初始化向量（IV），用于替代分片序列号（默认值） 进行加密。对 key_info_file 的更改将导致使用新密钥/IV 进行 分片加密，并在启用 hls_flags periodic_rekey 时，在播放列表中为新密钥 URI/IV 添加一个条目。

密钥信息文件示例： 

http://server/file.key
/path/to/file.key
0123456789ABCDEF0123456789ABCDEF

#!/bin/sh
BASE_URL=${1:-'.'}
openssl rand 16 > file.key
echo $BASE_URL/file.key > file.keyinfo
echo file.key >> file.keyinfo
echo $(openssl rand -hex 16) >> file.keyinfo
ffmpeg -f lavfi -re -i testsrc -c:v h264 -hls_flags delete_segments \
  -hls_key_info_file file.keyinfo out.m3u8
hls_enc bool

启用（1）或禁用（0）AES128 加密。 启用后，生成的每个分片都会被加密，且加密密钥 保存为 playlist name.key。

hls_enc_key key

指定一个 16 个八位字节的密钥用于加密分片，默认情况下该密钥 随机生成。

hls_enc_key_url keyurl

如果设置，则在播放列表中，keyurl 会被前置到密钥文件名之前， 而不是 baseurl。

hls_enc_iv iv

为每个分片指定 16 个八位字节的初始化向量，而不使用 自动生成的值。

hls_segment_type flags

可能的取值：

‘mpegts’

以 MPEG-2 传输流格式输出分片文件。这与 所有 HLS 版本兼容。

‘fmp4’

以分片 MP4 格式输出分片文件，类似于 MPEG-DASH。 fmp4 文件可用于 HLS 版本 7 及更高版本。

hls_fmp4_init_filename filename

设置分片文件头文件的文件名，默认文件名为 init.mp4。

启用 strftime 时，filename 会按本地时间扩展为分片文件名。

例如： 

ffmpeg -i in.nut -hls_segment_type fmp4 -strftime 1 -hls_fmp4_init_filename "%s_init.mp4" out.m3u8

将生成类似这样的 init 文件 1602678741_init.mp4。

hls_fmp4_init_resend bool

每次 m3u8 文件刷新后都重新发送 init 文件，默认为 0。

当设置了 var_stream_map 且包含两个或更多变体流时， filename 模式必须包含字符串 "%v"，该字符串 指定变体流索引在生成的 init 文件名中的 位置。字符串 "%v" 可以出现在文件名中，也可以出现在 包含该文件的最后一个目录名中。如果该字符串出现在目录名中，那么 在展开目录名模式后会创建子目录。这 使得可以在子目录中创建与不同变体流相对应的 init 文件。

hls_flags flags

可能的取值：

‘single_file’

如果设置此标志，复用器会将所有分片存储在单个 MPEG-TS 文件中，并在播放列表中使用字节范围。以这种方式生成的 HLS 播放列表的版本号为 4。

例如： 

ffmpeg -i in.nut -hls_flags single_file out.m3u8

将生成播放列表 out.m3u8，以及单个分片文件 out.ts。

‘delete_segments’

从播放列表中移除的分片文件会在一段时间后被删除， 该时间等于分片的时长加上播放列表的时长。

‘append_list’

将新分片追加到旧分片列表的末尾， 并从旧分片列表中移除 #EXT-X-ENDLIST。

‘round_durations’

将播放列表文件分片信息中的时长信息四舍五入为整数 值，而不使用浮点数。 如果没有其他需要更高 HLS 版本的功能被使用， 那么这将允许 ffmpeg 输出 HLS 版本 2 的 m3u8。

‘discont_start’

在第一个分片的信息之前，向播放列表中添加 #EXT-X-DISCONTINUITY 标签。

‘omit_endlist’

不要在播放列表末尾追加 EXT-X-ENDLIST 标签。

‘periodic_rekey’

由 hls_key_info_file 指定的文件会被定期检查，以 检测加密信息的更新。请确保以原子方式替换此文件， 包括包含 AES 加密密钥的文件。

‘independent_segments’

向含有视频分片、且其所有分片都保证以关键帧开始的 播放列表添加 #EXT-X-INDEPENDENT-SEGMENTS 标签。

‘iframes_only’

向含有视频分片、且能在 #EXT-X-BYTERANGE 模式下 仅播放 I 帧的播放列表添加 #EXT-X-I-FRAMES-ONLY 标签。

‘split_by_time’

允许分片从非关键帧的帧开始。当关键帧之间的 时间间隔不一致时，这会改善某些播放器上的行为， 但可能使其他播放器上的情况更糟，并可能在 跳转播放时导致一些异常。此标志应与 hls_time 选项一起使用。

‘program_date_time’

生成 EXT-X-PROGRAM-DATE-TIME 标签。

‘second_level_segment_index’

当 strftime 选项开启时，除了日期/时间值之外，还可以在 hls_segment_filename 选项表达式中使用分片索引作为 %%d。要获得带前导零的 固定宽度数字，可以使用 %%0xd 格式，其中 x 是所需的宽度。

‘second_level_segment_size’

当 strftime 选项开启时，除了日期/时间值之外，还可以在 hls_segment_filename 选项表达式中使用分片大小（以字节计）作为 %%s。要获得带前导零的 固定宽度数字，可以使用 %%0xs 格式，其中 x 是所需的宽度。

‘second_level_segment_duration’

当 strftime 选项开启时，除了日期/时间值之外，还可以在 hls_segment_filename 选项表达式中使用分片时长（以微秒计算）作为 %%t。要获得带前导零的 固定宽度数字，可以使用 %%0xt 格式，其中 x 是所需的宽度。

例如： 

ffmpeg -i sample.mpeg \
   -f hls -hls_time 3 -hls_list_size 5 \
   -hls_flags second_level_segment_index+second_level_segment_size+second_level_segment_duration \
   -strftime 1 -strftime_mkdir 1 -hls_segment_filename "segment_%Y%m%d%H%M%S_%%04d_%%08s_%%013t.ts" stream.m3u8

将生成类似这样的分片： segment_20170102194334_0003_00122200_0000003000000.ts、segment_20170102194334_0004_00120072_0000003000000.ts 等。

‘temp_file’

将分片数据写入 filename.tmp，并仅在分片完成后 将其重命名为 filename。

提供分片服务的 Web 服务器可以配置为拒绝针对 *.tmp 的请求，以 防止在分片被添加到 m3u8 播放列表之前访问正在写入的 分片。

此标志还会影响 m3u8 播放列表文件的创建方式。如果设置此标志， 所有播放列表文件都会被写入临时文件，并在完成后重命名， 处理方式与分片类似。但使用 file 协议、且 hls_playlist_type 类型不是 ‘vod’ 的播放列表， 无论是否设置此标志，都会始终写入临时文件。

通过 master_pl_name 指定的主播放列表文件（如果有）， 在使用 file 协议时，如果 master_pl_publish_rate 值不为零， 则无论是否设置此标志，都会始终写入临时文件。

hls_playlist_type type

如果 type 为 ‘event’，则在 m3u8 头部中发出 #EXT-X-PLAYLIST-TYPE:EVENT。这会强制将 hls_list_size 设为 0； 播放列表只能被追加。

如果 type 为 ‘vod’，则在 m3u8 头部中发出 #EXT-X-PLAYLIST-TYPE:VOD。这会强制将 hls_list_size 设为 0； 播放列表不得改变。

method method

使用给定的 HTTP 方法创建 hls 文件。

例如： 

ffmpeg -re -i in.ts -f hls -method PUT http://example.com/live/out.m3u8

将使用 HTTP PUT 方法将所有 mpegts 分片文件上传到 HTTP 服务器， 并使用相同的方法每 refresh 次更新 m3u8 文件。 请注意，HTTP 服务器必须支持用于上传文件的 给定方法。

http_user_agent agent

覆盖 HTTP 头部中的 User-Agent 字段。仅适用于 HTTP 输出。

var_stream_map stream_map

指定一个映射字符串，用于定义如何把音频、视频和字幕流 分组为不同的变体流。变体流组之间用 空格分隔。

预期的字符串格式如下 "a:0,v:0 a:1,v:1 ...."。其中 a:、v:、s: 是 分别用于指定音频、视频和字幕流的键。 允许的取值为 0 到 9（仅依据实际使用情况加以限制）。

当存在两个或更多变体流时，输出文件名模式中必须 包含字符串 "%v"：该字符串指定变体流 索引在输出媒体播放列表文件名中的位置。字符串 "%v" 可以出现在 文件名中，也可以出现在包含该文件的最后一级目录名中。如果该字符串 出现在目录名中，那么在展开 目录名模式之后会创建子目录。这样就可以在 子目录中创建变体流。

下面给出几个示例。

  • 创建两个 hls 变体流。第一个变体流将包含 码率为 1000k 的视频流和码率为 64k 的音频流，第二个变体 流将包含码率为 256k 的视频流和码率为 32k 的音频流。此处将创建两个媒体播放列表，文件名分别为 out_0.m3u8 和 out_1.m3u8。 
    ffmpeg -re -i in.ts -b:v:0 1000k -b:v:1 256k -b:a:0 64k -b:a:1 32k \
  -map 0:v -map 0:a -map 0:v -map 0:a -f hls -var_stream_map "v:0,a:0 v:1,a:1" \
  http://example.com/live/out_%v.m3u8
  • 如果你希望在结果名称中使用有意义的文本而不是索引， 可以为每个或部分变体指定名称。下面的示例将 像前一个示例那样创建两个 hls 变体流。但这里，将会创建两个 媒体播放列表，其文件名分别为 out_my_hd.m3u8 和 out_my_sd.m3u8。 
    ffmpeg -re -i in.ts -b:v:0 1000k -b:v:1 256k -b:a:0 64k -b:a:1 32k \
  -map 0:v -map 0:a -map 0:v -map 0:a -f hls -var_stream_map "v:0,a:0,name:my_hd v:1,a:1,name:my_sd" \
  http://example.com/live/out_%v.m3u8
  • 创建三个 hls 变体流。第一个变体流将是仅含视频的 流，视频码率为 1000k；第二个变体流将是仅含音频的 流，码率为 64k；第三个变体流将是仅含视频的流， 码率为 256k。此处将创建三个媒体播放列表，文件名分别为 out_0.m3u8、 out_1.m3u8 和 out_2.m3u8。 
    ffmpeg -re -i in.ts -b:v:0 1000k -b:v:1 256k -b:a:0 64k \
  -map 0:v -map 0:a -map 0:v -f hls -var_stream_map "v:0 a:0 v:1" \
  http://example.com/live/out_%v.m3u8
  • 在子目录中创建变体流。此处第一个媒体播放列表 创建于 http://example.com/live/vs_0/out.m3u8，第二个创建于 http://example.com/live/vs_1/out.m3u8。 
    ffmpeg -re -i in.ts -b:v:0 1000k -b:v:1 256k -b:a:0 64k -b:a:1 32k \
  -map 0:v -map 0:a -map 0:v -map 0:a -f hls -var_stream_map "v:0,a:0 v:1,a:1" \
  http://example.com/live/vs_%v/out.m3u8
  • 创建两个仅含音频和两个仅含视频的变体流。除了为 主播放列表中每个变体流添加 #EXT-X-STREAM-INF 标签之外，还会为 这两个仅含音频的变体流添加 #EXT-X-MEDIA 标签， 并将它们映射到两个仅含视频的变体流，音频组名称为 ’aud_low’ 和 ’aud_high’。 默认情况下，会创建一个包含所有已编码流的 hls 变体。 
    ffmpeg -re -i in.ts -b:a:0 32k -b:a:1 64k -b:v:0 1000k -b:v:1 3000k  \
  -map 0:a -map 0:a -map 0:v -map 0:v -f hls \
  -var_stream_map "a:0,agroup:aud_low a:1,agroup:aud_high v:0,agroup:aud_low v:1,agroup:aud_high" \
  -master_pl_name master.m3u8 \
  http://example.com/live/out_%v.m3u8
  • 创建两个仅含音频和一个仅含视频的变体流。除了为 主播放列表中每个变体流添加 #EXT-X-STREAM-INF 标签之外，还会为 这两个仅含音频的变体流添加 #EXT-X-MEDIA 标签， 并将它们映射到一个仅含视频的变体流，音频组名称为 ’aud_low’，且该音频组的默认状态为 NO 或 YES。 默认情况下，会创建一个包含所有已编码流的 hls 变体。 
    ffmpeg -re -i in.ts -b:a:0 32k -b:a:1 64k -b:v:0 1000k \
  -map 0:a -map 0:a -map 0:v -f hls \
  -var_stream_map "a:0,agroup:aud_low,default:yes a:1,agroup:aud_low v:0,agroup:aud_low" \
  -master_pl_name master.m3u8 \
  http://example.com/live/out_%v.m3u8
  • 创建两个仅含音频和一个仅含视频的变体流。除了为 主播放列表中每个变体流添加 #EXT-X-STREAM-INF 标签之外，还会为 这两个仅含音频的变体流添加 #EXT-X-MEDIA 标签， 并将它们映射到一个仅含视频的变体流，音频组名称为 ’aud_low’，且该音频组的默认状态为 NO 或 YES，并且其中一个音频 流的语言名为 ENG，另一个音频流的语言名为 CHN。默认 情况下，会创建一个包含所有已编码流的 hls 变体。 
    ffmpeg -re -i in.ts -b:a:0 32k -b:a:1 64k -b:v:0 1000k \
  -map 0:a -map 0:a -map 0:v -f hls \
  -var_stream_map "a:0,agroup:aud_low,default:yes,language:ENG a:1,agroup:aud_low,language:CHN v:0,agroup:aud_low" \
  -master_pl_name master.m3u8 \
  http://example.com/live/out_%v.m3u8
  • 创建单个变体流。在主播放列表中为 webvtt 字幕组名 ’subtitle’ 添加带有 TYPE=SUBTITLES 的 #EXT-X-MEDIA 标签， 并可选择性指定字幕名称，例如 ’English’。请确保输入 文件至少有一个文本字幕流。 
    ffmpeg -y -i input_with_subtitle.mkv \
 -b:v:0 5250k -c:v h264 -pix_fmt yuv420p -profile:v main -level 4.1 \
 -b:a:0 256k \
 -c:s webvtt -c:a mp2 -ar 48000 -ac 2 -map 0:v -map 0:a:0 -map 0:s:0 \
 -f hls -var_stream_map "v:0,a:0,s:0,sgroup:subtitle,sname:English" \
 -master_pl_name master.m3u8 -t 300 -hls_time 10 -hls_init_time 4 -hls_list_size \
 10 -master_pl_publish_rate 10 -hls_flags \
 delete_segments+discont_start+split_by_time ./tmp/video.m3u8
cc_stream_map cc_stream_map

用于指定不同隐藏式字幕组及其属性的映射 字符串。隐藏式字幕流组之间用空格分隔。

预期的字符串格式如下 "ccgroup:<group name>,instreamid:<INSTREAM-ID>,language:<language code> ...."。 ’ccgroup’ 和 ’instreamid’ 是必需属性。’language’ 是可选 属性。

使用该选项配置的隐藏式字幕组，通过在 var_stream_map 字符串中提供相同的 ’ccgroup’ 名称， 即可映射到不同的变体流。

例如： 

ffmpeg -re -i in.ts -b:v:0 1000k -b:v:1 256k -b:a:0 64k -b:a:1 32k \
  -a53cc:0 1 -a53cc:1 1 \
  -map 0:v -map 0:a -map 0:v -map 0:a -f hls \
  -cc_stream_map "ccgroup:cc,instreamid:CC1,language:en ccgroup:cc,instreamid:CC2,language:sp" \
  -var_stream_map "v:0,a:0,ccgroup:cc v:1,a:1,ccgroup:cc" \
  -master_pl_name master.m3u8 \
  http://example.com/live/out_%v.m3u8

将在主播放列表中为 INSTREAM-ID ’CC1’ 和 ’CC2’ 添加两个 带有 TYPE=CLOSED-CAPTIONS 的 #EXT-X-MEDIA 标签。此外，它还会为 两个输出变体流添加组名为 ’cc’ 的 CLOSED-CAPTIONS 属性。

如果未设置 var_stream_map，那么 cc_stream_map 中第一个可用的 ccgroup 会被映射到输出变体流。

例如： 

ffmpeg -re -i in.ts -b:v 1000k -b:a 64k -a53cc 1 -f hls \
  -cc_stream_map "ccgroup:cc,instreamid:CC1,language:en" \
  -master_pl_name master.m3u8 \
  http://example.com/live/out.m3u8

这将在主播放列表中添加带有 TYPE=CLOSED-CAPTIONS 的 #EXT-X-MEDIA 标签， 其组名为 ’cc’、语言为 ’en’（english），INSTREAM-ID 为 ’CC1’。此外，它还会为输出变体流添加组名为 ’cc’ 的 CLOSED-CAPTIONS 属性。

master_pl_name name

创建具有给定名称的 HLS 主播放列表。

例如： 

ffmpeg -re -i in.ts -f hls -master_pl_name master.m3u8 http://example.com/live/out.m3u8

创建名为 master.m3u8 的 HLS 主播放列表，它发布 在 http://example.com/live/。

master_pl_publish_rate count

每经过指定数量的分段间隔后重复发布一次主播放列表。

例如： 

ffmpeg -re -i in.ts -f hls -master_pl_name master.m3u8 \
-hls_time 2 -master_pl_publish_rate 30 http://example.com/live/out.m3u8

创建名为 master.m3u8 的 HLS 主播放列表，并 每经过 30 个分段（即每经过 60s）就重复发布一次。

使用持久 HTTP 连接。仅适用于 HTTP 输出。

timeout timeout

设置套接字 I/O 操作的超时时间。仅适用于 HTTP 输出。

ignore_io_errors bool

忽略打开、写入和删除期间的 IO 错误。对于使用网络输出的长时间运行很有用。

4.50 image2, image2pipe# TOC

图像文件复用器。

‘image2’ 复用器把视频帧写入图像文件。

输出文件名由模式指定，该模式可用于 生成按顺序编号的文件序列。 该模式可以包含字符串 "%d" 或 "%0Nd"，该字符串 指定文件名中表示编号的字符的 位置。如果使用 "%0Nd" 形式，则每个文件名中 表示编号的字符串会补零至 N 位。字面字符 ’%’ 可以用字符串 "%%" 在模式中指定。

如果模式中包含 "%d" 或 "%0Nd"，则所指定文件列表的 第一个文件名会包含编号 1，其后的所有 编号都是连续的。

该模式可以包含一个后缀，用于自动 确定要写入的图像文件的格式。

例如，模式 "img-%03d.bmp" 将指定一系列 文件名，其形式为 img-001.bmp、img-002.bmp、...、 img-010.bmp 等。 模式 "img%%-%d.jpg" 将指定一系列文件名，其 形式为 img%-1.jpg、img%-2.jpg、...、img%-10.jpg 等。

该图像复用器支持 .Y.U.V 图像文件格式。该格式的 特殊之处在于，每个图像帧由三个文件组成，分别对应 YUV420P 的各个分量。要读写这种图像文件格式， 请指定 ’.Y’ 文件的名称。复用器会按需自动打开 ’.U’ 和 ’.V’ 文件。

‘image2pipe’ 复用器接受与 ‘image2’ 复用器相同的选项， 但会忽略模式的校验与展开，因为它应当写入 命令输出，而不是写入实际存储的文件。

如果设为 1，文件名将始终被解释为单纯的 文件名，而不是模式，且相应文件会被新图像不断 覆盖。默认值为 0。

4.50.2 示例# TOC

  • 使用 ffmpeg 创建文件序列 img-001.jpeg、 img-002.jpeg、...，每秒从输入视频中取一张图像： 
    ffmpeg -i in.avi -fps_mode cfr -r 1 -f image2 'img-%03d.jpeg'

    注意，使用 ffmpeg 时，如果未通过 -f 选项指定格式，而输出文件名指定了图像文件 格式，则会自动选择 image2 复用器，因此上一条 命令可以写成： 

    ffmpeg -i in.avi -fps_mode cfr -r 1 'img-%03d.jpeg'

    另请注意，该模式不必包含 "%d" 或 "%0Nd"，例如要从输入视频的开头创建单个图像文件 img.jpeg，可以使用以下命令： 

    ffmpeg -i in.avi -f image2 -frames:v 1 img.jpeg
  • strftime 选项允许你使用 日期和时间信息扩展文件名。语法请查看 strftime() 函数的文档。

    要根据 strftime() 的 "%Y-%m-%d_%H-%M-%S" 模式生成图像文件， 可以使用以下 ffmpeg 命令： 

    ffmpeg -f v4l2 -r 1 -i /dev/video0 -f image2 -strftime 1 "%Y-%m-%d_%H-%M-%S.jpg"
  • 使用当前帧的 PTS 设置文件名： 
    ffmpeg -f v4l2 -r 1 -i /dev/video0 -copyts -f image2 -frame_pts true %d.jpg
  • 每秒将桌面内容直接发布到 WebDAV 服务器： 
    ffmpeg -f x11grab -framerate 1 -i :0.0 -q:v 6 -update 1 -protocol_opts method=PUT http://example.com/desktop.jpg

4.58.2 选项# TOC

reserve_index_space size

默认情况下，该复用器把用于定位的索引（在 Matroska 术语中称为 cues）写在文件末尾，因为它无法预先知道要在 文件开头为索引留出多少空间。然而在某些使用场景中 – 例如可以定位但速度较慢的流式传输 – 将索引 放在文件开头是有用的。

如果将该选项设为非零值，复用器会在文件头中预留 size 字节 的空间，然后在复用结束时尝试把 cues 写入那里。如果预留的 空间不足，则不会写入任何 Cues，文件会被终结，写入 trailer 时将返回错误。对大多数使用场景而言，安全的大小约为 每小时视频 50kB。

注意，只有当输出可定位时才会写入 cues，若输出不可定位， 该选项不会产生任何效果。

cues_to_front bool

如果设置该选项，复用器会把索引写在文件开头， 必要时移动主数据。它可以与 reserve_index_space 结合使用，此时只有当 最初预留的空间不足时才会移动数据。

如果输出不可定位，该选项会被忽略。

cluster_size_limit size

在一个簇中最多存储所给定的字节数。

如果未指定，该限制会自动设置为一个合理的 硬编码固定值。

cluster_time_limit duration

在一个簇中最多存储所给定的毫秒数。

如果未指定，该限制会自动设置为一个合理的 硬编码固定值。

dash bool

创建符合 WebM DASH 规范的 WebM 文件。默认 设置为 false。

dash_track_number index

DASH 流的轨道编号。默认设置为 1。

live bool

按直播流的方式写入文件。默认设置为 false。

allow_raw_vfw bool

允许原始 VFW 模式。默认设置为 false。

flipped_raw_rgb bool

如果设为 true，则为原始 RGB 位图存储正的高度值，表示 位图按自下而上方式存储。注意，该选项不会翻转位图， 翻转必须事先手动完成，例如使用 ‘vflip’ 滤镜。 默认值为 false，表示位图按自上而下方式存储。

write_crc32 bool

在每个 Level 1 元素内写入一个 CRC32 元素。默认设置为 true。对 WebM 忽略此选项。

default_mode mode

控制输出轨道的 FlagDefault 如何设置。 它影响播放器默认应播放哪些轨道。默认模式 为 ‘passthrough’。

‘infer’

每个处置（disposition）为 default 的轨道都会设置 FlagDefault。 此外，对于每种轨道类型（音频、视频或字幕），如果不存在 该类型中处置为 default 的轨道，则该类型的第一条轨道 将被标记为默认（如果存在）。这样即使输入来自 缺少默认轨道概念的容器，也能以合理的方式 设置默认标志。

此模式与 infer 相同，区别在于如果不存在处置为 default 的字幕轨道，则不会将任何字幕轨道标记为默认。

4.63 mp3# TOC

MP3 复用器写入原始 MP3 流，并具有以下可选特性：

  • 开头的 ID3v2 元数据头（默认启用）。支持 2.3 和 2.4 版本，id3v2_version 私有选项控制使用哪一个 （3 或 4）。将 id3v2_version 设为 0 会完全禁用 ID3v2 头。

    该复用器支持将附加图片（APIC 帧）写入 ID3v2 头。 图片以包含单个 数据包的视频流形式提供给复用器。这样的流可以有任意数量，每一个都对应 单个 APIC 帧。流元数据标签 title 和 comment 分别 映射到 APIC 的 description 和 picture type。有关允许的图片类型，请参见 http://id3.org/id3v2.4.0-frames。

    请注意，APIC 帧必须写在开头，因此复用器会 缓冲音频帧，直到获取所有图片。所以建议 尽快提供图片，以避免过度的缓冲。

  • 紧跟在 ID3v2 头之后（如果存在）的 Xing/LAME 帧。它默认 启用，但只有在输出可定位时才会写入。可以使用 write_xing 私有选项将其禁用。该帧包含 对解码器可能有用的各种信息，例如音频时长 或编码器延迟。
  • 文件末尾的旧式 ID3v1 标签（默认禁用）。可以用 write_id3v1 私有选项启用它，但由于其能力 非常有限，不建议使用。

示例：

写入带有 ID3v2.3 头和 ID3v1 尾的 mp3： 

ffmpeg -i INPUT -id3v2_version 3 -write_id3v1 1 out.mp3

要将图片附加到 mp3 文件，请用 map 同时选择音频流和图片流： 

ffmpeg -i input.mp3 -i cover.png -c copy -map 0 -map 1
-metadata:s:v title="Album cover" -metadata:s:v comment="Cover (Front)" out.mp3

写入不带任何额外特性的 "干净" MP3： 

ffmpeg -i input.wav -write_xing 0 -id3v2_version 0 out.mp3

4.71 segment, stream_segment, ssegment# TOC

基本流分段器。

该复用器将流输出为若干个时长近乎 固定的独立文件。输出文件名模式可以按照 与 image2 类似的方式设置，或者使用 strftime 模板（如果启用了 strftime 选项）。

stream_segment 是该复用器的一个变体，用于写入 流式输出格式，即不需要全局头的格式， 推荐用于输出到例如 MPEG 传输流分段。 ssegment 是 stream_segment 的较短别名。

每个分段都以所选参考流的一个关键帧开始， 该参考流通过 reference_stream 选项设置。

请注意，如果希望对视频文件进行精确分割，需要 使输入关键帧与分段器所期望的精确 分割时间相对应，否则 segment 复用器将以 指定开始时间之后找到的下一个关键帧开始新的 分段。

segment 复用器在单个恒定帧率的视频上效果最佳。

它还可以选择生成已创建分段的列表，方法是设置 segment_list 选项。列表类型由 segment_list_type 选项指定。分段 列表中的条目文件名默认设置为对应分段文件的 基本名。

另请参见 hls 复用器，它为 HLS 分段提供了更专门的 实现。

4.71.1 选项# TOC

segment 复用器支持以下选项：

increment_tc 1|0

如果设置为 1，则在每个分段之间递增时间码。 如果选择此项，输入的第一个视频流中需要带有 时间码。默认值为 0。

reference_stream specifier

设置参考流，由字符串 specifier 指定。 如果 specifier 设置为 auto，则会自动选择 参考流。否则它必须是用于指定参考流的流标识符 （参见 ffmpeg 手册中的“流标识符”一章）。 默认值为 auto。

segment_format format

覆盖内部容器格式，默认情况下由文件名 扩展名推测。

segment_format_options options_list

使用以 : 分隔的 key=value 参数列表设置输出 格式选项。包含 : 特殊字符的值必须 进行转义。

segment_list name

同时生成名为 name 的列表文件。如果未指定， 则不生成列表文件。

segment_list_flags flags

设置影响分段列表生成的标志。

目前支持以下标志：

‘cache’

允许缓存（仅影响 M3U8 列表文件）。

‘live’

允许生成适合直播的文件。

segment_list_size size

更新列表文件，使其最多包含 size 个分段。如果为 0，列表文件将包含所有分段。默认 值为 0。

segment_list_entry_prefix prefix

为每个条目添加 prefix 前缀。可用于生成绝对路径。 默认情况下不添加前缀。

segment_list_type type

选择列表格式。

可识别以下取值：

‘flat’

为已创建的分段生成扁平列表，每行一个分段。

‘csv, ext’

为已创建的分段生成列表，每行一个分段， 每行符合以下格式（逗号分隔的值）： 

segment_filename,segment_start_time,segment_end_time

segment_filename 是复用器根据所提供的 模式生成的输出文件名。如有需要，会应用 CSV 转义（依据 RFC4180）。

segment_start_time 和 segment_end_time 指定 以秒为单位的分段开始和结束时间。

后缀为 ".csv" 或 ".ext" 的列表文件将 自动选择此格式。

‘ext’ 已废弃，请改用 ‘csv’。

‘ffconcat’

为已创建的分段生成 ffconcat 文件。生成的文件 可以使用 FFmpeg 的 concat 解复用器读取。

后缀为 ".ffcat" 或 ".ffconcat" 的列表文件将 自动选择此格式。

‘m3u8’

生成扩展的 M3U8 文件，版本 3，符合 http://tools.ietf.org/id/draft-pantos-http-live-streaming。

后缀为 ".m3u8" 的列表文件将自动选择此格式。

如果未指定，则根据列表文件名后缀推测类型。

segment_time time

将分段时长设置为 time，该值必须是时长 规格。默认值为 "2"。另请参见 segment_times 选项。

请注意，分割可能并不精确，除非强制参考流 在给定时间出现关键帧。参见前面的说明 以及下面的示例。

min_seg_duration time

将最小分段时长设置为 time，该值必须是时长 规格。这可以防止复用器在低于该值的时长处结束分段。 仅在使用 segment_time 时有效。默认值为 "0"。

segment_atclocktime 1|0

如果设置为 "1"，则从 00:00 整点开始，按固定的时钟时间 间隔进行分割。time 值在 segment_time 中 指定，用于设置分割间隔的长度。

例如，将 segment_time 设置为 "900" 时，就可以 在 12:00、12:15、12:30 等时刻创建文件。

默认值为 "0"。

segment_clocktime_offset duration

在使用 segment_atclocktime 时，将分段分割时间延后 指定的时长。

例如，将 segment_time 设置为 "900" 并将 segment_clocktime_offset 设置为 "300" 时，就可以 在 12:05、12:20、12:35 等时刻创建文件。

默认值为 "0"。

segment_clocktime_wrap_duration duration

强制分段器仅在数据包于分段时钟时间之后的指定时长内 到达复用器时才开始新分段。这样 可以使分段器更好地应对本地时间向后跳变的情况，例如 闰秒或从夏令时切换到标准时间。

默认值为可能的最大时长，这意味着无论 距上次时钟时间过去了多久，都会开始新分段。

segment_time_delta delta

指定为分段选择起始时间时的精度时间，以 时长规格表示。默认值为 "0"。

当指定了 delta 时，如果关键帧的 PTS 满足以下关系，它将开启一个新分段： 

PTS >= start_time - time_delta

该选项在切分视频内容时很有用，因为视频内容总是在 GOP 边界处切分，以防出现关键帧恰好位于 指定切分时间之前的情况。

特别地，它可以与 ffmpeg 的选项 force_key_frames 组合使用。由 force_key_frames 指定的关键帧时间可能因为舍入 问题而设置不准确，其后果是某个关键帧时间可能被设置得恰好 位于指定时间之前。对于恒定帧率视频，取值为 1/(2*frame_rate) 应能应对 指定时间与 force_key_frames 所设置时间之间最坏情况的不匹配。

segment_times times

指定切分点列表。times 包含以逗号 分隔的时长规格列表，按递增顺序排列。另请参见 segment_time 选项。

segment_frames frames

指定切分视频帧编号列表。frames 包含 以逗号分隔的整数列表，按递增顺序排列。

该选项指定：每当遇到参考 流的关键帧，且该帧的序号（从 0 开始） 大于或等于列表中的下一个值时，就开启一个新分段。

segment_wrap limit

当分段索引达到 limit 时回绕。

segment_start_number number

设置第一个分段的序号。默认为 0。

segment_wrap_number number

设置生成分段列表中报告的索引时，假定分段索引已经 回绕的次数。它与 segment_wrap 和 segment_start_number 一起对报告的 索引进行偏移，该索引的计算方式为 segment_start_number + segment_wrap * segment_wrap_number。默认为 0。

strftime 1|0

使用 strftime 函数来定义要写入的新 分段的名称。如果选中此项，输出分段名称必须 包含 strftime 函数模板。默认值为 0。

break_non_keyframes 1|0

如果启用，允许分段从非关键帧的帧开始。当关键帧之间的 时间间隔不一致时，这能改善某些播放器上的 表现，但在另一些播放器上可能更糟，并且可能在 跳转时引发一些异常。默认为 0。

reset_timestamps 1|0

在每个分段的开头重置时间戳，使每个分段 都从接近零的时间戳开始。这样做是为了便于 播放生成的分段。在某些复用器/编解码器组合下 可能无效。默认设置为 0。

initial_offset offset

指定要应用到输出数据包时间戳的时间戳偏移。该 参数必须是时长规格，默认为 0。

write_empty_segments 1|0

如果启用，当分段通常会跨越的时间段内没有数据包时，写入一个 空分段。否则，该分段将用下一个写入的 数据包填充。默认为 0。

write_header_trailer bool

把头部写入第一个分段、把尾部写入最后一个分段，而不是 为每个独立分段都写入头部和尾部。禁用它 （false）还会强制把 individual_header_trailer 设为 false， 这样任何分段都不会有头部或尾部。默认值为 true。

individual_header_trailer bool

如果启用，为每个分段写入完整的头部和尾部，使每个 分段都成为可独立使用的文件。如果禁用（false），只有第一个 分段会写入头部，只有最后一个分段会写入尾部。当 write_header_trailer 为 false 或设置了 segment_header_filename 时，此项被强制为 false。默认值为 true。

segment_header_filename name

把流头部写入名为 name 的单独文件，而不是将其 存储在分段中。设置此项会强制把 write_header_trailer 设为 true，把 individual_header_trailer 设为 false，因此 头部只会写入一次，即写入 name。默认未设置。

请确保编码时要求闭合 GOP，并将 GOP 大小设置为符合你的分段时长约束。

4.73 streamhash# TOC

逐流哈希测试格式。

该复用器按逐流方式计算并打印所有输入帧的 加密哈希值。这可用于相等性检查，而无需 进行完整的二进制比较。

默认情况下，在计算哈希之前，音频帧会转换为有符号 16 位原始音频， 视频帧会转换为原始视频，不过也可以使用显式转换为其它编解码器后的 输出。时间戳会被忽略。它默认使用 SHA-256 加密哈希函数， 但还支持其它几种算法。

该复用器的输出为每个流一行，形式如下： streamindex,streamtype,algo=hash，其中 streamindex 是所映射流的索引，streamtype 是 表示流类型的单个字符，algo 是表示所用哈希函数的 短字符串，hash 是表示所计算哈希值的 十六进制数。

hash algorithm

使用由字符串 algorithm 指定的加密哈希函数。 支持的取值包括 MD5、murmur3、RIPEMD128、 RIPEMD160、RIPEMD256、RIPEMD320、SHA160、 SHA224、SHA256（默认）、SHA512/224、SHA512/256、 SHA384、SHA512、CRC32 和 adler32。

4.73.1 示例# TOC

ffmpeg -i INPUT -f streamhash out.sha256

要把 MD5 哈希值打印到标准输出，请使用以下命令： 

ffmpeg -i INPUT -f streamhash -hash md5 -

另请参见 hash 和 framehash 复用器。

4.74 tee# TOC

tee 复用器可用于把同一份数据写入多个输出，例如文件或流。 例如，它可用于通过网络流式传输视频，同时将其保存到磁盘。

它不同于为 ffmpeg 命令行工具指定多个输出。 使用 tee 复用器时，音频和视频数据只会被编码一次。 而在传统的多输出方式中，会并行发起多次编码操作， 这可能是一个开销非常大的过程。直接使用 libavformat API 时 tee 复用器没有用处， 因为那时可以直接把相同的数据包馈送给多个复用器。

由于 tee 复用器不代表任何特定的输出格式，ffmpeg 无法自动选择 输出流。因此所有要输出的流都必须用 -map 指定。参见 下面的示例。

某些编码器可能需要根据输出格式使用不同的选项； 这种自动检测在 tee 复用器下无法生效，因此必须显式指定它们。 主要的例子是 global_header 标志。

从属输出在传给复用器的文件名中指定， 彼此之间用 ’|’ 分隔。如果任何从属名称包含 ’|’ 分隔符、 前导或尾随空格，或者任何特殊字符，则必须对它们 进行转义（参见 ffmpeg-utils(1) 手册中的 "Quoting and escaping" 一节）。

如果设为 1，从属输出将使用 fifo 复用器在单独的线程中处理。这样可以补偿各输出在 速度/延迟/可靠性上的差异，并建立透明的恢复机制。默认情况下此功能是关闭的。

fifo_options

要传递给 fifo 伪复用器实例的选项。参见 fifo。

可以为每个从属输出指定复用器选项，方法是在方括号中前置一组 以 ’:’ 分隔的 key=value 对。如果 选项值包含特殊字符或 ’:’ 分隔符，则必须对它们 进行转义；注意这是第二层转义。

还识别以下特殊选项：

f

指定格式名。如果无法从输出 URL 推断出格式名， 则此项为必填。

bsfs[/spec]

指定要应用到指定输出的比特流滤波器 列表。

可以通过在选项后追加以 / 分隔的流标识符， 来指定给定的比特流滤波器应用到哪些流。 spec 必须是流标识符（参见 格式流标识符）。

如果未指定流标识符，比特流滤波器将 应用到输出中的所有流。如果输出中包含无法应用该比特流滤波器的 流，例如把 h264_mp4toannexb 应用到一个包含音频流的输出， 则会导致该输出操作失败。

比特流滤波器的选项必须以 opt=value 的形式指定。

可以指定多个比特流滤波器，彼此之间用 "," 分隔。

use_fifo bool

这允许为单个从属复用器覆盖 tee 复用器的 use_fifo 选项。

fifo_options

这允许为单个从属复用器覆盖 tee 复用器的 fifo_options。 参见 fifo。

select

选择应映射到从属输出的流， 由流标识符指定。如果未指定，则默认为 所有已映射的流。如果输出格式不接受所有已映射的流， 则会导致该输出操作失败。

你可以使用多个以逗号（,）分隔的流标识符，例如：a:0,v

onfail

指定输出失败时的行为。可以将其设为 abort（这是 默认值）或 ignore。abort 会在该从属输出失败时导致整个进程失败。 ignore 会忽略该输出上的失败，这样其它输出 将继续运行而不受影响。

  • 编码某些内容，既将其归档到 WebM 文件中， 又通过 UDP 以 MPEG-TS 形式进行流式传输： 
    ffmpeg -i ... -c:v libx264 -c:a mp2 -f tee -map 0:v -map 0:a
  "archive-20121107.mkv|[f=mpegts]udp://10.0.1.255:1234/"
  • 同上，但即使输出到本地文件失败 （例如本地磁盘已满）也继续流式传输： 
    ffmpeg -i ... -c:v libx264 -c:a mp2 -f tee -map 0:v -map 0:a
  "[onfail=ignore]archive-20121107.mkv|[f=mpegts]udp://10.0.1.255:1234/"
  • 使用 ffmpeg 对输入进行编码，并将输出 发送到三个不同的目标。按照 MPEG-TS 格式的要求，使用 dump_extra 比特流滤波器向所有输出视频 关键帧数据包添加 extradata 信息。select 选项应用于 out.aac，以使其只包含 音频数据包。 
    ffmpeg -i ... -map 0 -flags +global_header -c:v libx264 -c:a aac
       -f tee "[bsfs/v=dump_extra=freq=keyframe]out.ts|[movflags=+faststart]out.mp4|[select=a]out.aac"
  • 同上，但只为音频输出选择流 a:1。注意 必须进行第二级转义，因为 ":" 是用于 分隔选项的特殊字符。 
    ffmpeg -i ... -map 0 -flags +global_header -c:v libx264 -c:a aac
       -f tee "[bsfs/v=dump_extra=freq=keyframe]out.ts|[movflags=+faststart]out.mp4|[select=\'a:1\']out.aac"

4.75 wav# TOC

RIFF Wave 音频复用器。

4.75.1 选项# TOC

rf64 mode

选择是否使用 RF64 文件格式而非 RIFF。 RF64 允许文件大于 4 GB，但 RF64 的支持 不如 RIFF 那样普遍。

可识别以下模式：

‘auto’

开始写入标准 RIFF 文件，以保持与 不支持 RF64 的软件的兼容性，但如果输出文件增长到 超过 4 GB 则切换到 RF64。使用 JUNK 块在文件头中 预留少量额外空间，所有符合规范的 RIFF 读取器都应忽略该块， 但某些极其简单的 WAV 读取器可能会因此产生困惑。

‘always’

无论文件大小如何，始终使用 RF64 格式。输出文件 只能被兼容 RF64 的软件读取， 不再属于标准 RIFF WAVE 文件。

‘never’

始终使用普通 RIFF，绝不使用 RF64。此模式与旧版 软件兼容性最好，但如果输出文件增长到超过 4 GB， data 块中的 32 位大小字段将无法再正确表示大小， 大多数音频软件将无法读取部分或全部数据。 （可使用 wav 解复用器的 ignore_length 选项来恢复此类 文件。） 这是默认模式。

write_bext bool

若启用，则添加包含扩展音频 元数据的 Broadcast Wave Format BEXT 块。默认为 false。

write_peak mode

若启用，则添加 Peak Envelope 块（EBU Tech 3285 Supplement 3）。 默认为 off。

‘off’

不添加 Peak Envelope 块。

‘on’

添加 Peak Envelope 块，并根据 peak_block_size、peak_format 和 peak_ppv 选项计算峰值。

‘only’

与 on 类似，但跳过写入实际音频数据（不会向文件 写入 data 块；只写入 Peak Envelope 和其它元数据 块。）

peak_block_size int

用于生成每个峰值帧的音频采样数，最大为 65536。 默认为 256。

peak_format format

峰值包络数据的格式（1: uint8，2: uint16）。默认为 2 (uint16)。

peak_ppv int

每个峰值的峰值点数（1 或 2）。默认为 2。

4.78 whip# TOC

WebRTC（实时通信）复用器，按照 WHIP（WebRTC-HTTP 摄取协议）规范支持亚秒级延迟的流式传输。

这是一项实验性功能。

它使用 HTTP 作为信令协议来交换 SDP 能力和 ICE lite 候选。然后， 它使用 STUN 绑定请求和响应通过 UDP 建立会话。随后， 它将发起 DTLS 握手以交换 SRTP 加密密钥。最后，它将视频和 音频帧拆分为 RTP 数据包，并使用 SRTP 对它们加密。

请确保使用不含 B 帧的 H.264，音频编解码器使用 Opus。例如，使用 ffmpeg 将输入文件转换为 WebRTC： 

ffmpeg -re -i input.mp4 -acodec libopus -ar 48000 -ac 2 \
  -vcodec libx264 -profile:v baseline -tune zerolatency -threads 1 -bf 0 \
  -f whip "http://localhost:1985/rtc/v1/whip/?app=live&stream=livestream"

在此示例中，我们采用了低延迟选项，端到端延迟 约为 150 毫秒。

5 元数据# TOC

FFmpeg 能够将媒体文件中的元数据导出到一个简单的 UTF-8 编码的 类 INI 文本文件中，然后使用 metadata 复用器/解复用器将其重新加载。

文件格式如下：

  1. 一个文件由一个头部和若干被划分为多个节的元数据标签组成， 每个各占一行。
  2. 头部是一个 ‘;FFMETADATA’ 字符串，后面跟一个版本号（目前为 1）。
  3. 元数据标签的形式为 ‘key=value’
  4. 紧跟在头部之后的是全局元数据
  5. 在全局元数据之后，可能有一些包含按流/按章节 元数据的节。
  6. 节以大写形式的节名（即 STREAM 或 CHAPTER）开始，该名称位于 方括号（‘[’、‘]’）中，并以下一个节或文件结尾结束。
  7. 在章节节的开头，可以有一个可选的时基，用于 起始/结束值。它必须采用 ‘TIMEBASE=num/den’ 的形式，其中 num 和 den 是 整数。如果缺少时基，则起始/结束时间被认为 以纳秒为单位。

    接下来，章节节必须包含章节的起始和结束时间，形式为 ‘START=num’、‘END=num’，其中 num 是一个正 整数。

  8. 空行以及以 ‘;’ 或 ‘#’ 开头的行会被忽略。
  9. 包含特殊字符（‘=’、‘;’、 ‘#’、‘\’ 和换行符）的元数据键或值必须用反斜杠 ‘\’ 进行转义。
  10. 请注意，元数据中的空白（例如 ‘foo = bar’）被视为 标签的一部分（在上例中，键是 ‘foo ’，值是 ‘ bar’）。

一个 ffmetadata 文件可能如下所示： 

;FFMETADATA1
title=bike\\shed
;this is a comment
artist=FFmpeg troll team

[CHAPTER]
TIMEBASE=1/1000
START=0
#chapter ends at 0:01:00
END=60000
title=chapter \#1
[STREAM]
title=multi\
line

通过使用 ffmetadata 复用器和解复用器，可以将 元数据从输入文件提取到一个 ffmetadata 文件，然后使用编辑后的 ffmetadata 文件 将该文件转码为输出文件。

使用 ffmpeg 提取 ffmetadata 文件的方法如下： 

ffmpeg -i INPUT -f ffmetadata FFMETADATAFILE

可以使用如下方式将 FFMETADATAFILE 文件中编辑后的元数据信息 重新插入： 

ffmpeg -i INPUT -i FFMETADATAFILE -map_metadata 1 -codec copy OUTPUT
