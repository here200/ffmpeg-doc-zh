1.1 高级链接配置# TOC

如果你以静态方式编译了 FFmpeg 库，并想用它们来 构建你自己的共享库，你可能需要强制启用 PIC 支持（在 FFmpeg configure 期间使用 --enable-pic），并向你的项目 LDFLAGS 添加以下选项： 

-Wl,-Bsymbolic

如果你的目标平台要求二进制文件与位置无关，你应当 把正确的链接标志（例如 -pie）传给 --extra-ldexeflags。

4.1 使用 MinGW 或 MinGW-w64 的本机 Windows 编译# TOC

FFmpeg 可以构建为使用 MinGW-w64 工具链在 Windows 上 本机运行。请从 https://www.msys2.org/ 和/或 https://www.mingw-w64.org/ 安装最新版本的 MSYS2 和 MinGW-w64。 你可以在下载部分和 常见问题中找到详细的安装说明。

注意事项：

  • 不鼓励为 MSYS 环境构建，请改用 MSYS2 提供的 某个 MinGW-w64 环境。UCRT64 提供基于 GCC 的 工具链，CLANG64 提供基于 LLVM 的工具链，而 CLANGARM64 面向 ARM64 上的 Windows。
  • 通过禁用 Makefile 中的隐式规则可以加快使用 MSYS2 构建的速度， 办法是调用 make -r 而不是普通的 make。这种 加速对于普通的一次性构建几乎不存在，只有在第二次运行 make 时 才比较明显（例如执行 make install 时）。
  • 为了编译 FFplay，你必须安装 SDL 的 MinGW 开发库以及 pkg-config。
  • 在配置 FFmpeg 时使用 ./configure --enable-shared， 你就可以把 FFmpeg 库（例如 libavutil、libavcodec、 libavformat）构建为 DLL。

4.1.1 使用 MSYS2 的本机 Windows 编译# TOC

MSYS2 的 MinGW-w64 环境提供开箱即用的工具链和 依赖，这些依赖可通过 pacman 获取。

使用启动器启动你想要在其中构建的环境的 shell， 例如 ucrt64.exe，或 UCRT64 对应的开始菜单 快捷方式。然后安装工具链和 FFmpeg 依赖。pacboy 包装器来自 pactoys 包，它会填入当前环境的包名前缀，因此 同一条命令在每个环境中都可用。 

# normal msys2 packages
pacman -S make pkgconf diffutils pactoys

# mingw-w64 packages and toolchains for the current environment
pacboy -S cc nasm SDL2

4.2 用于 Windows 的 Microsoft Visual C++ 或 Intel C++ 编译器# TOC

FFmpeg 可以用 MSVC 2019 16.8 或更高版本构建，这是第一个能够 编译 C11 的版本。

你需要以下先决条件：

  • MSYS2
  • NASM （也可通过 MSYS2 的包管理器获取。）

要在 MSYS2 中建立合适的环境，你需要运行 msys2_shell.cmd -use-full-path，它要在 Visual Studio 或 Intel Compiler 的 命令提示符中执行。

把 nasm.exe 放到你的 PATH 中的某个位置。

接下来，确保你想使用的任何其它头文件和库（例如 zlib）都 位于编译器能够看到的位置。为此，请修改 LIB 和 INCLUDE 环境变量，使其包含指向这些目录的 Windows 风格 路径。或者，你也可以尝试使用 --extra-cflags/--extra-ldflags 配置选项。

最后，运行： 

For MSVC:
./configure --toolchain=msvc

For ICL:
./configure --toolchain=icl

make
make install

如果你希望编译共享库，请把 --enable-shared 加到你的 配置选项中。注意，由于 MSVC 和 ICL 处理 DLL 导入与 导出的方式，你无法同时编译静态库和共享库，而且 启用共享库会自动禁用静态库。

注意事项：

  • 如果你希望构建时启用 zlib 支持，就必须从某处获取一个兼容的 zlib 二进制文件（带 MSVC 导入库），或者，如果你希望静态 链接，可以按照下面的说明用 MSVC 构建一个兼容的 zlib.lib。无论使用哪种方法，你仍然必须 遵循第 3 步，否则编译会失败。
    1. 获取 zlib 源码。
    2. 编辑 win32/Makefile.msc，使其使用 -MT 而不是 -MD，因为 FFmpeg 也是这样构建的。
    3. 编辑 zconf.h 并删除它对 unistd.h 的包含。构建 FFmpeg 时 它会错误地被包含进来。
    4. 运行 nmake -f win32/Makefile.msc。
    5. 把 zlib.lib、zconf.h 和 zlib.h 移到 MSVC 能看到的地方。

4.2.1 使用 Microsoft Visual C++ 链接到 FFmpeg# TOC

如果你打算链接由 MSVC 构建的静态库，你需要 确保在你项目的设置中把 Runtime Library 设置为 Multi-threaded (/MT)。

如果你打算使用由 dlltool 创建的导入库，你必须 在链接器优化设置中把 References 设为 No (/OPT:NOREF)， 否则生成的二进制文件会在运行时失败。 在使用由 lib.exe 生成的导入库时不需要这样做。 此问题已在上游报告，参见 http://sourceware.org/bugzilla/show_bug.cgi?id=12633。

要创建能与 /OPT:REF 选项 （该选项在 Release 模式下默认启用）配合使用的导入库，请按以下步骤操作：

  1. 打开 Visual Studio 命令提示符。

    或者，在普通的命令行提示符中调用 vcvarsall.bat， 它会为 Visual C++ 工具设置好环境变量。

  2. 进入存放所创建的 LIB 和 DLL 文件的 bin 目录。
  3. 用 lib.exe 生成新的导入库： 
    lib /machine:i386 /def:..\lib\foo-version.def  /out:foo.lib

    把 foo-version 和 foo 替换为相应的库名。

4.3 在 Linux 上为 Windows 交叉编译# TOC

你必须使用 MinGW-w64 交叉编译工具，大多数 Linux 发行版都以软件包形式提供这些工具。

然后用以下选项配置 FFmpeg： 

./configure --arch=x86_64 --target-os=mingw32 --cross-prefix=x86_64-w64-mingw32-

（你可以根据为 MinGW-w64 工具选择的前缀来更改 cross-prefix）。

然后你可以用 Wine 轻松测试 FFmpeg。

4.4 在 Cygwin 下编译# TOC

安装 Cygwin 时要包含所有 "Base" 包，再加上 以下 "Devel" 包： 

binutils, gcc-core, make, git, texinfo

为了运行 FATE，你还需要以下 "Utils" 包： 

diffutils

如果你想用附加的库来构建 FFmpeg，请从任意 Cygwin 软件包仓库下载适用于 Ogg 和 Vorbis 的 Cygwin "Devel" 包： 

libogg-devel, libvorbis-devel

4.5 在 Cygwin 下为 Windows 交叉编译# TOC

使用 Cygwin 你可以创建不需要 cygwin1.dll 的 Windows 二进制文件。

只需像前面说明的那样安装 Cygwin，再加上 MinGW-w64 交叉 工具链的 "Devel" 包： 

mingw64-x86_64-gcc-core, mingw64-x86_64-binutils

然后用以下命令配置： 

./configure --arch=x86_64 --target-os=mingw32 --cross-prefix=x86_64-w64-mingw32-

4.6 ARM64EC# TOC

FFmpeg 不打算支持 Windows ARM64EC 构建配置； 为 ARM64EC 的用途而改动各个库的补丁 将不会被接受。

在这种构建配置下构建 FFmpeg 或许仍然可行； 这样的构建在某种程度上看似可以工作。不过这种构建可能存在 一些 ABI 不一致——对此我们不打算修复。

（要把 aarch64 汇编代码改为严格支持 ARM64EC，需要对 几乎所有此类汇编代码做 ifdef 处理或修改，这会带来 巨大的维护负担。此外，改动库的 ABI 接口以修复 ABI 不一致，可能需要大量且侵入性的 改动。）
