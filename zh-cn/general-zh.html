1 外部库# TOC

FFmpeg 可以接入若干外部库，以增加对更多格式的支持。 默认情况下不会使用其中任何一个，若要使用它们，必须 通过将相应的标志传给 ./configure 来显式请求。

1.1 Alliance for Open Media (AOM)# TOC

FFmpeg 可以使用 AOM 库进行 AV1 解码和编码。

请访问 http://aomedia.org/ 并按照说明 安装该库。然后将 --enable-libaom 传给 configure 以 启用它。

1.2 AMD AMF/VCE# TOC

FFmpeg 可以使用 AMD Advanced Media Framework 库 在带有 Video Coding Engine (VCE) 的硬件上加速 H.264 和 HEVC（仅限 windows）编码。

要启用支持，必须从 https://github.com/GPUOpen-LibrariesAndSDKs/AMF.git 获取 AMF 框架头文件（版本 1.4.9+）。

在系统 include 路径中创建 AMF/ 目录。 将 AMF/amf/public/include/ 的内容复制到该目录中。 然后使用 --enable-amf 配置 FFmpeg。

amf 编码器的初始化按以下顺序进行： 1) 尝试通过 dx11 初始化（仅限 windows） 2) 尝试通过 dx9 初始化（仅限 windows） 3) 尝试通过 vulkan 初始化

要在 linux 上使用 h.264(AMD VCE) 编码器，需要 amdgru-pro 版本 19.20+ 和 amf-amdgpu-pro 包（amdgru-pro 中包含该包，但不会自动安装）。

该驱动程序可以使用官方 amd 驱动归档中的 amdgpu-pro-install 脚本安装。

1.3 AviSynth# TOC

FFmpeg 可以将 AviSynth 脚本作为输入读取。要启用支持，请将 --enable-avisynth 传给 configure，在此之前需先安装 由 AviSynth+ 提供的头文件。 可以通过以下任一方式将 AviSynth+ 配置为仅安装头文件： 将 -DHEADERS_ONLY:bool=on 传给常规的基于 CMake 的构建 系统，或使用随附的 GNUmakefile。

在 Windows 上，受支持的 AviSynth 变体为 AviSynth 2.6 RC1 或更高版本（用于 32 位构建），以及 AviSynth+ r1718 或更高版本（用于 32 位和 64 位构建）。

在 Linux、macOS 和 BSD 上，唯一受支持的 AviSynth 变体是 AviSynth+，从版本 3.5 开始。

2016 年，AviSynth+ 增加了对使用 GCC 构建的支持。然而，由于 Windows’ 调用约定的古怪之处，AviSynth+ 的 32 位 GCC 构建 与典型的 32 位 FFmpeg 构建不兼容。

默认情况下，FFmpeg 假定与 AviSynth+ 的 32 位 MSVC 构建兼容， 因为那是最广泛使用、最为根深蒂固的构建 配置。 用户可以覆盖这一点，并启用对 AviSynth+ 的 32 位 GCC 构建的支持：在配置 FFmpeg 时，将 -DAVSC_WIN32_GCC32 传给 --extra-cflags。

64 位 FFmpeg 构建不受影响，可以使用 MSVC 或 GCC 构建的 AviSynth+，无需任何特殊标志。

AviSynth(+) 是动态加载的。 发行者可以用 --enable-avisynth 构建 FFmpeg，这些二进制文件能否工作与 最终用户是否安装了 AviSynth 无关。 如果最终用户 想要使用 AviSynth 脚本，那么他们可以安装 AviSynth(+)， FFmpeg 就能找到并使用它来打开脚本。

1.4 Chromaprint# TOC

FFmpeg 可以使用 Chromaprint 库生成音频指纹。 将 --enable-chromaprint 传给 configure 以 启用它。参见 https://acoustid.org/chromaprint。

1.5 codec2# TOC

FFmpeg 可以使用 codec2 库进行 codec2 解码和编码。 目前没有原生解码器，因此必须使用 libcodec2 进行解码。

请访问 http://freedv.org/，下载 "Codec 2 source archive"。 使用 CMake 构建并安装。Debian 用户可以改为安装 libcodec2-dev 包。 安装 libcodec2 后，可以将 --enable-libcodec2 传给 configure 以启用它。

使用 codec2 最简单的方式是使用 .c2 文件，因为它们包含解码所需的模式信息。 要编码此类文件，请使用 .c2 文件扩展名，并为 libcodec2 编码器指定 -mode 选项： ffmpeg -i input.wav -mode 700C output.c2。 播放非常简单，只需 ffplay output.c2。 要查看受支持模式的列表，请运行 ffmpeg -h encoder=libcodec2。 也支持原始 codec2 文件。 要解析它们，需要将所使用的模式指定为格式选项： ffmpeg -f codec2raw -mode 1300 -i input.raw output.wav。

1.10 Intel QuickSync Video# TOC

FFmpeg 可以使用 Intel QuickSync Video (QSV) 来加速 多种编解码器的解码和编码。要使用 QSV，FFmpeg 必须链接到 libmfx 调度器，由它加载实际的解码库。

该调度器是开源的，可从 https://github.com/lu-zero/mfx_dispatch.git 下载。FFmpeg 需要 使用 --enable-libmfx 选项进行配置，并且 pkg-config 需要能够 找到该调度器的 .pc 文件。

1.18 ONNX Runtime# TOC

FFmpeg 可以使用 ONNX Runtime 库作为基于 DNN 的滤镜的后端。

请访问 https://onnxruntime.ai/ 并按照说明 安装该库。各种平台都提供预构建的包。

配置 FFmpeg 以支持 ONNX Runtime： 

./configure \
    --enable-libonnxruntime \
    --extra-cflags="-I/path/to/onnxruntime/include" \
    --extra-ldflags="-L/path/to/onnxruntime/lib"

在基于 ELF 的系统（Linux、BSD）上，你可能还想嵌入 库搜索路径，以便已安装的 ffmpeg 二进制文件在运行时 无需设置 LD_LIBRARY_PATH 就能找到该共享库： 

./configure \
    --enable-libonnxruntime \
    --extra-cflags="-I/path/to/onnxruntime/include" \
    --extra-ldflags="-L/path/to/onnxruntime/lib -Wl,-rpath,/path/to/onnxruntime/lib"

-Wl,-rpath 标志是 ELF 专用的，在 其他平台（Windows、macOS）上应当省略。

对于 MinGW GCC 构建，请添加 -D_stdcall=__stdcall 标志，以与 ONNX Runtime 头文件兼容。

1.19 OpenCORE、VisualOn 和 Fraunhofer 库# TOC

OpenCore、VisualOn 和 Fraunhofer 库源自 Google Android 源码， 它们为多种音频编解码器提供编码器。

OpenCORE 和 VisualOn 库采用 Apache License 2.0 （详情参见 http://www.apache.org/licenses/LICENSE-2.0），它与 LGPL 2.1 版和 GPL 2 版不兼容。你必须 把 FFmpeg 的许可证升级为 LGPL 第 3 版（如果你启用了 GPL 组件，则为 GPL 第 3 版），方法是向 configure 传入 --enable-version3， 这样才能使用它。

Fraunhofer AAC 库的许可证与 GPL 不兼容。 因此，对于 GPL 构建，你必须向 configure 传入 --enable-nonfree 才能使用它。据我们所知，它 与 LGPL 兼容。

1.20 OpenH264# TOC

FFmpeg 可以利用 OpenH264 库进行 H.264 解码和编码。

请访问 http://www.openh264.org/ 并按照说明 安装该库。然后向 configure 传入 --enable-libopenh264 即可启用它。

在解码方面，该库比 libavcodec 中的内置解码器 受限得多；目前，该库不支持解码 B 帧 以及其它一些 main/high profile 特性。（它目前仅支持 constrained baseline profile 和 CABAC。）使用它主要适合 测试，以及利用 Cisco 的专利组合许可 （http://www.openh264.org/BINARY_LICENSE.txt）。
